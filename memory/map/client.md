## Purpose
Client WS net layer — the ONLY module importing `@colyseus/sdk` 0.17. Wraps raw Colyseus transport (join/leave/error/message) into typed callbacks; handles version handshake, zod-validates all inbound frames, recovers from unexpected drops with bounded retry + deterministic resync race avoidance. Returns a stable `WsClientHandle` that remains valid across reconnect (mutable `activeRoom` indirection).

## Entry points & files (net subdirectory)
- wsClient.ts (S2.3.2a): main net seam — exports `connect()` and `attachRoom()`. `connect()` has RESUME-FIRST branch: on cold load, reads `current-room` → roomId-keyed token, calls `capability.reconnect(token)` (self-contained, no roomId arg), then falls through to `attachRoom`. On reject or missing token, clears pointer+token and calls `joinOrCreate`. `attachRoom` wires room to typed callbacks, persists current-room pointer + token on every wire (join + reconnect), implements reconnect retry logic: on unexpected drop calls `capability.reconnect(token)` with bounded retry (8× [500,1000,2000,4000,8000,8000,8000]ms ≈31.5s, widened from 3×[250,750]ms), then SYNCHRONOUS `wire(newRoom)` to beat the resync race. Returned `WsClientHandle` stays the SAME object across reconnects via mutable `activeRoom` indirection. Clears pointer+token on consented leave.
- reconnectToken.ts (S2.3.2a, live): per-room and current-room token persistence. Per-room exports `persistReconnectionToken(roomId, token)`, `readReconnectionToken(roomId)`, `clearReconnectionToken(roomId)` keyed by `skervik:reconnect:{roomId}`. Current-room tracking exports `persistCurrentRoomId(roomId)`, `readCurrentRoomId()`, `clearCurrentRoomId()` keyed by `skervik:reconnect:current-room` (global, not per-room). Uses `sessionStorage` (per-tab, survives reload, auto-cleared on tab close). Guarded no-op when unavailable — net layer keeps in-memory fallback alongside. **Live:** both read and write are functional; `connect()` uses current-room pointer + token to resume a held seat on cold load.

- PublicGameStateSchema (protocol, consumed here — m2-gate-07): carries OPTIONAL `profileId` + `vpToWinOverride`. Both are load-bearing on the client: `board/matchTopology.ts` derives the topology from `gameState.profileId` and DEFAULTS TO CLASSIC when it is missing, so before this fix a reconnect into an `expanded` match re-rendered a radius-2 board.

- ReconnectCapability: {reconnect(token)→Promise<RoomLike>, maxAttempts?, backoffMs?} — supplied by `connect()` which owns the real Colyseus Client (keeps net layer free of SDK deps).
- WsClientHandle: {sessionId (get), sendIntent, disconnect} — mutable indirection returned from `attachRoom`, valid across reconnect.
- WsClientCallbacks: {onSnapshot, onBatch, onReject, onError, onConnectionChange} — typed message handlers.

## Gotchas
1. **Stable handle across reconnect (S2.3.2)** — `WsClientHandle` indirects through mutable `activeRoom` rather than being locked to the initial room. When reconnect succeeds, `activeRoom` is swapped to the new RoomLike, so a caller holding a stashed handle (the store) never needs to re-fetch it — all subsequent `sendIntent()` calls target the live room. The handle is returned SYNCHRONOUSLY after the initial `attachRoom(room)` call, before reconnect is even possible, so there's no race.
2. **Synchronous re-wire on reconnect (S2.3.2, Key decision 5)** — after `capability.reconnect(token)` succeeds (HTTP roundtrip to server, mints new Room), `wire(newRoom)` is called WITH NO await/delay in between. This ensures `onMessage('state.snapshot')` listener is registered BEFORE the server's `#sendSnapshot(liveClient)` unicast arrives on the reconnected socket. Missing this results in the snapshot being received before the handler exists and dropped as an unknown message.
3. **Bounded reconnect retry (S2.3.2a)** — default 8 attempts with [500,1000,2000,4000,8000,8000,8000]ms backoff (~31.5s total, well under server's 120s grace). Retry loop is tight (no randomness), predictable. After exhaustion, token is cleared + terminal 'disconnected' status fired; a fresh join via the lobby is the only recovery path.
4. **Resume-on-reload via current-room pointer (S2.3.2a)** — `connect()` now checks `readCurrentRoomId()` and `readReconnectionToken(roomId)` on every load. If both are present (i.e., a prior session held a seat in the grace window), it calls `reconnect(token)` BEFORE `joinOrCreate`, resuming the held seat. Token is self-contained (encodes room/seat/epoch). If token/pointer is missing or `reconnect()` rejects, flow falls through to normal `joinOrCreate`. The pointer persists on every `wire()` call (join + reconnect) and clears on consented leave or game-end room close.
5. **Zod validation at the boundary (S2.3.2)** — every inbound message (`state.snapshot`, `event.batch`, `intent.rejected`, `intent.error`) is parsed + validated against its schema; a frame that fails validation is logged with dev warning and dropped, never propagated to callbacks. Frames must be well-formed by the server; a mismatch is a protocol contract violation.
6. **sessionStorage guard (reconnectToken.ts)** — `hasSessionStorage()` check guards all three functions (persist/read/clear); they degrade to no-op in test environments or when storage is disabled. The in-memory token in `attemptReconnect` fallback covers the case where persistence failed.
7. **zod STRIPS what the schema does not name — `safeParse` success proves nothing (m2-gate-07)** — `PublicGameStateSchema` omitted `profileId`, so every snapshot silently lost it while every existing test stayed green (they asserted `.success`, not preservation). A snapshot test must assert the FIELD SURVIVED, not that parsing succeeded. Same trap for `vpToWinOverride`.
8. **The client's TESTS resolve `@skervik/*` through `dist`; its dev/build resolve through `src` (m2-gate-07)** — `vite.config.ts` aliases the workspace packages to `../<pkg>/src`, but `vitest.config.ts` exists alongside it and TAKES PRECEDENCE for test runs, carrying no alias. So a protocol/core fix is invisible to this suite until `pnpm --filter @skervik/protocol build` (the new wsClient test failed with `profileId: undefined` until then — the C3 regression reproduced by a stale dist). Rebuild before debugging any cross-package seam.
9. **Colyseus 0.17 SDK Client lifecycle** — `new Client(url)` created once per `connect()` call and kept in scope (in the `connect` function, not exported). The same client is reused by `capability.reconnect(token)` for HTTP reconnect calls. Multiple rooms/sessions would need multiple `Client` instances.
