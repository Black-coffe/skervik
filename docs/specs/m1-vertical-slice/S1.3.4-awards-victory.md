# S1.3.4 — Longest road, largest army, VP tally, victory

## Goal

Compute the two awards (longest road ≥5, largest army ≥3 knights), maintain the
victory-point tally (settlement 1, city 2, awards 2 each, VP dev cards hidden),
and detect victory at `profile.vpToWin` (Classic 10) on the acting player's turn.
On win, emit a `game.ended` event that freezes the match.

## Files

- `packages/core/src/types.ts` — additive: award-holder fields
  (`longestRoadHolder`, `largestArmyHolder`) on state; `game.ended` event; a
  derived-VP helper contract.
- `packages/core/src/validate.ts` — after any state-changing action that can move
  an award or VP (build road/settlement/city, knight play, dev-card buy of a VP
  card), recompute awards + total VP for the acting player and, if ≥ threshold on
  THEIR turn, emit `game.ended`.
- `packages/core/src/reduce.ts` — apply award transfers + `game.ended`
  (freeze: reject subsequent gameplay intents once ended).
- `packages/core/src/victory.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).

## Spec

- **Longest road:** for each player, longest SIMPLE path in their own road
  subgraph; an opponent's settlement/city on an intervening vertex BREAKS the
  path there. Award to the sole leader with length ≥5; ties → incumbent keeps it;
  losing the lead (e.g. road broken by a new opponent settlement) reassigns or
  vacates per Classic rules. Award = +2 VP to holder.
- **Build-legality enemy-cut (deferred here from S1.2.2):** the SAME
  "opponent's settlement/city on an intervening vertex breaks the road network"
  rule must ALSO gate road *building* in `validate` — a player may not extend a
  road THROUGH a vertex holding an opponent's building, even if an own road is
  incident there. S1.2.2 shipped a one-hop `touchesOwnNetwork` that ignores this;
  implement the shared graph helper here so BOTH the longest-road scoring cut and
  the build-legality cut use one implementation. Add/verify a `buildRoad` negative
  test for the enemy-cut case, and confirm S1.2.2's existing road tests still pass.
- **Largest army:** first to 3 played knights holds it; overtaken only by a
  strictly higher count; ties keep incumbent. Award = +2 VP.
- **VP tally:** settlement 1, city 2, each award 2, each VP dev card 1 (hidden
  from others until victory). `vpToWin` from `ClassicProfile` (10).
- **Victory:** evaluated only on the acting player's own turn (so hidden VP
  cards can complete a win). On reaching threshold → `game.ended` with the final
  standings; `reduce`/`validate` reject further gameplay intents afterward.
- Reject reasons (extend): game-already-ended.

## Implementation notes

- **Longest-road DFS (`validate.ts` `longestRoadLength`):** bounded backtracking
  DFS over the player's own road subgraph — from every own-road endpoint (sorted
  for determinism), `walk(vertex, usedEdges)` returns the longest simple path
  (no repeated EDGE) leaving that vertex. The break rule: `walk` returns 0
  immediately at any vertex holding an OPPONENT building, so an edge ENDING at
  such a vertex still counts (length +1) but the chain can't continue THROUGH
  it. Local `Set`s for visited edges (internal only — nothing mutable leaks into
  state/events). Board is ≤72 edges / ≤15 roads-per-player so the exponential
  worst case is trivially bounded.
- **Award tie/reassign (`computeLongestRoad`):** max length across players; `< 5`
  → vacate; else if the incumbent is among the co-leaders → keep (ties keep the
  holder); else a sole leader → take; else (tie, incumbent not leading) → vacate.
  **Largest army (`computeLargestArmy`):** max played-knight count; `< 3` → none;
  incumbent among leaders → keep (ties keep); sole leader → take; never vacates
  (counts only rise). Both iterate `state.players` in fixed array order.
- **ONE shared graph helper:** `vertexHasOpponentBuilding(vertex, player,
  buildings)` is used by BOTH the longest-road DFS (stop traversal) AND the
  road-build **enemy-cut** — `touchesOwnNetwork` now returns "no connection" at a
  vertex an opponent occupies, so a road can't extend THROUGH an opponent's
  settlement/city. That one change gates both `intent.buildRoad` and the
  road-building card. Negative + positive control tests in `victory.test.ts`;
  all S1.2.2 road tests still pass (they never had opponent buildings on the
  connecting vertex).
- **Awards + victory as EVENTS:** `appendAwardsAndVictory(state, primaryEvents,
  actingPlayer)` projects the action's events through the pure `reduce`,
  recomputes both awards on the post-action state, and emits `award.longestRoad`
  / `award.largestArmy` ONLY when a holder actually changes (indices continue
  contiguously). `validate` imports `reduce` (one-directional — `reduce` imports
  only `types`, no cycle). Wired into `buildRoad`, `buildSettlement`,
  `buildCity`, `buyDevCard`, the knight play, and the road-building card.
- **Victory-on-own-turn + freeze:** the win check runs ONLY for `actingPlayer`
  (always the current player for these intents), so a hidden VP card completes a
  win but an opponent pushed to the threshold on your turn does NOT win. At
  `vpToWin` → `game.ended` (winner + full standings); `reduce` sets phase
  `'finished'`; a new top-of-`validate` guard then rejects every gameplay intent
  with `GAME_ALREADY_ENDED`.
- **Hidden-VP tally (`computeVictoryPoints`):** derived straight from state —
  settlements×1 + cities×2 + each held award ×2 + `devCards[p].held.victoryPoint`
  ×1. Deriving from `buildings` (not the incremental `player.victoryPoints`,
  left untouched — out of scope) means setup-draft settlements count correctly,
  and the win check sees hidden VP cards.
- **New profile constants:** `CLASSIC_VICTORY_PROFILE` (exported: `vpToWin` 10,
  `longestRoadMin` 5, `largestArmyMin` 3, `longestRoadVP`/`largestArmyVP` 2) and
  `CLASSIC_ROBBER_PROFILE` (module-local: `handLimit` 7, `halfDivisor` 2) —
  folding in the S1.3.1 discard nit (`>7` / `floor(hand/2)` were inline magic
  numbers).
- **New types:** state fields `longestRoadHolder?`/`largestArmyHolder?`; events
  `award.longestRoad` (optional `playerId` — absent = vacated — + `length`),
  `award.largestArmy` (`playerId` + `knights`, never vacates), `game.ended`
  (`winnerId` + `finalStandings`); RejectReason `GAME_ALREADY_ENDED`. All
  additive to the unions.
- **Goldens NOT re-goldened:** verified — no award/victory/build events appear in
  `golden.events.ndjson`, and no existing event handling changed, so the golden
  replay is byte-identical (confirmed green). `replay.ts`'s wire-format
  `EventLogLine` union is separate from `GameEvent` and needs no new mapping.
- **Verification:** `pnpm --filter @skervik/core test` (206 passed, +11 new in
  `victory.test.ts`) · `pnpm -r typecheck` · `pnpm -r lint` · `pnpm -r build` —
  all green.
