# S1.3.4 — Longest road, largest army, VP tally, victory

## Goal

Compute the two awards (longest road ≥5, largest army ≥3 knights), maintain the
victory-point tally (settlement 1, city 2, awards 2 each, VP dev cards hidden),
and detect victory at `profile.vpToWin` (Classic 10) on the acting player's turn.
On win, emit a `game.ended` event that freezes the match.

## Files

- `packages/core/src/types.ts` — additive: award-holder fields
  (`longestRoadHolder`, `largestArmyHolder`) on state; `game.ended` event; a
  derived-VP helper contract.
- `packages/core/src/validate.ts` — after any state-changing action that can move
  an award or VP (build road/settlement/city, knight play, dev-card buy of a VP
  card), recompute awards + total VP for the acting player and, if ≥ threshold on
  THEIR turn, emit `game.ended`.
- `packages/core/src/reduce.ts` — apply award transfers + `game.ended`
  (freeze: reject subsequent gameplay intents once ended).
- `packages/core/src/victory.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).

  the codebase uses scattered `CLASSIC_*_PROFILE` objects (SETUP/PRODUCTION/BUILD/

  into a named constant (a robber/discard profile, same per-area convention) while

- **`game.ended` event + `finished` phase wiring:** the `finished` phase value
  exists in the `GamePhase` union but nothing enters it; this story wires
  `game.ended` → phase `finished`, and `validate`/`reduce` reject subsequent
  gameplay intents with `GAME_ALREADY_ENDED`.
- **Multi-hop longest-road DFS:** the existing `touchesOwnNetwork` is ONE-HOP only —
  insufficient for longest road. Add the graph DFS helper here; it is the SAME
  helper that implements the enemy-settlement-blocks-road build cut deferred from
  S1.2.2 (below) — build ONE traversal that both the award and the build-legality
  check share.
- **Hidden-VP tally:** core stores full VP (incl. VP dev cards) on shared state;
  victory is evaluated only on the acting player's OWN turn so a hidden VP card can
  complete a win. Per-viewer redaction (others see a count) is a server concern, not
  core — just make the win check see the full tally.

## Spec

- **Longest road:** for each player, longest SIMPLE path in their own road
  subgraph; an opponent's settlement/city on an intervening vertex BREAKS the
  path there. Award to the sole leader with length ≥5; ties → incumbent keeps it;
  losing the lead (e.g. road broken by a new opponent settlement) reassigns or
  vacates per Classic rules. Award = +2 VP to holder.
- **Build-legality enemy-cut (deferred here from S1.2.2):** the SAME
  "opponent's settlement/city on an intervening vertex breaks the road network"
  rule must ALSO gate road *building* in `validate` — a player may not extend a
  road THROUGH a vertex holding an opponent's building, even if an own road is
  incident there. S1.2.2 shipped a one-hop `touchesOwnNetwork` that ignores this;
  implement the shared graph helper here so BOTH the longest-road scoring cut and
  the build-legality cut use one implementation. Add/verify a `buildRoad` negative
  test for the enemy-cut case, and confirm S1.2.2's existing road tests still pass.
- **Largest army:** first to 3 played knights holds it; overtaken only by a
  strictly higher count; ties keep incumbent. Award = +2 VP.
- **VP tally:** settlement 1, city 2, each award 2, each VP dev card 1 (hidden
  from others until victory). `vpToWin` from `ClassicProfile` (10).
- **Victory:** evaluated only on the acting player's own turn (so hidden VP
  cards can complete a win). On reaching threshold → `game.ended` with the final
  standings; `reduce`/`validate` reject further gameplay intents afterward.
- Reject reasons (extend): game-already-ended.
