# S1.1.2 — Fair board generation from seed (constraint-aware, deterministic)

## Goal

Generate the Classic board layout **deterministically from the match seed**:
tile types, number tokens (no adjacent red 6/8), port assignment, robber start.
Same seed → identical board, forever. This is the first real consumer of
`rng.ts` beyond dice.

## Files

- `packages/core/src/boardgen.ts` (NEW)
- `packages/core/src/boardgen.test.ts` (NEW)
- `packages/core/src/types.ts` — additive: board-layout fields on `GameState`
  (tile types/tokens by tileId, port contents by slot, robber tileId) and a
  `board.generated`-style `GameEvent` if the design lands on event-sourced
  setup (preferred: setup emits events like everything else).
- `packages/core/src/reduce.ts` / `validate.ts` — only what's needed to apply
  the setup event(s); no gameplay rules here.
- `packages/core/src/index.ts` (re-export).
- Golden fixtures may need re-goldening if GameState shape grows — document it.

## Map slice

- `rng.ts`: `deriveValue(seed, streamIndex)`, `shuffle(items, seed, streamIndex)`
  (Fisher-Yates consuming indices `streamIndex..streamIndex+n-2`), golden seed
  `'skervik-golden-seed-1'` used in existing tests.
- S1.1.1 `board.ts` topology (tile/vertex/edge ids, port slots).
- Plan §3 "RNG stream discipline": board generation consumes a **reserved
  documented stream range**; write the chosen map into
  `docs/wiki/rng-stream-map.md` (NEW, this story creates it).

## Spec

- **Inputs:** `seed` (string), topology. **Outputs:** deterministic layout.
- Tile mix: 4 forest, 3 hills(clay), 4 pasture, 4 fields, 3 mountains, 1 desert
  — use the repo's mechanical resource ids (`timber/clay/fleece/barley/iron`,
  desert produces nothing). Shuffle onto the 19 tiles from the seed.
- Tokens `2,3,3,4,4,5,5,6,6,8,8,9,9,10,10,11,11,12` onto non-desert tiles.
  **Constraint: no two red tokens (6/8) on adjacent tiles.** Strategy:
  deterministic bounded retry — attempt k uses shuffle at
  `streamIndex = BASE + k * STRIDE`; first constraint-satisfying attempt wins.
  Bound attempts (e.g. 64) and prove in tests that the golden seed satisfies
  within bounds; on exhaustion return the last attempt with a documented flag
  (never throw nondeterministically).
- Ports: shuffle the 9 classic contents (4× generic 3:1, 5× resource 2:1 — one
  per resource) onto the fixed port slots from S1.1.1.
- Robber starts on the desert tile.
- Setup is **event-sourced**: generation produces event(s) carrying the full
  layout (so replay needs no generator re-run), applied via `reduce`.

## Acceptance criteria

- [ ] Same seed → byte-identical layout (test runs generator twice + through
      event replay).
- [ ] Red-token constraint holds for the golden seed AND a property test over
      ≥50 derived seeds (`seed-0`…`seed-49`).
- [ ] Every consumed stream index is documented in `docs/wiki/rng-stream-map.md`
      and stable (golden assertion on at least one full layout for the golden seed).
- [ ] Replay/golden determinism tests green (re-goldened consciously if state
      shape changed — noted in Implementation notes).
- [ ] `pnpm -r typecheck && lint && test && build` green; zero runtime deps.

## Implementation notes

- Branch `feat/s1.1.2-board-generation`. New: `packages/core/src/boardgen.ts`,
  `packages/core/src/boardgen.test.ts`, `docs/wiki/rng-stream-map.md`.
- New event `board.generated` (`BoardGeneratedEvent` in `types.ts`), added as
  the 2nd member of the `GameEvent` union (additive, never repurposed).
  Carries the full layout: `tileKinds`, `tileTokens`, `portContents`,
  `robberTileId`.
- New additive `GameState` field: `readonly board?: BoardState` — kept
  **optional** (not a placeholder value) specifically so the existing golden
  fixtures (`__fixtures__/golden.state.json` / `.ndjson`, whose recorded log
  never contains a `board.generated` line) stay byte-identical with **zero
  changes** — no re-goldening was needed or done. Chose optional over a
  default value because the golden fixture's `toEqual` deep-equality treats a
  missing key the same as `undefined`, and it keeps pre-S1.1.2 replay traces
  valid without a migration story.
- `TileKind` and `PortContent` types live in `types.ts` (alongside the other
  wire shapes) rather than in `boardgen.ts`, to keep the dependency graph
  acyclic: `boardgen.ts` imports them (plus `TileId`) unidirectionally;
  `types.ts` does not import anything from `boardgen.ts`.
- RNG stream-index map (full rationale + table in
  `docs/wiki/rng-stream-map.md`): board generation uses a **fixed reserved
  band** (`BOARD_GEN_STREAM` in `boardgen.ts`), deliberately NOT derived from
  `state.eventIndex` (which gameplay dice draws use) — this is the "reserved
  low range... before eventIndex counting starts" decision the plan left
  open. Chose a large fixed offset (`1_000_000+`) over "front-loading" the
  shared `eventIndex` counter, because a variable-length retry loop would
  make the first gameplay event's `eventIndex` depend on how many retry
  attempts board generation happened to need for a given seed — deterministic
  but fragile/surprising. The two streams are now provably disjoint by
  construction, no matter how eventIndex/retries evolve.
  - Tile-kind shuffle (19→18 draws): `1_000_000..1_000_017`.
  - Port-content shuffle (9→8 draws): `1_000_100..1_000_107`.
  - Token shuffle, attempt `k` (18→17 draws, bounded retry):
    `1_001_000 + k*100 .. +16`, `TOKEN_SHUFFLE_STRIDE = 100`,
    `TOKEN_RETRY_BOUND = 64`. On exhaustion (never observed): last attempt's
    tokens kept, `redConstraintSatisfied: false`, never throws.
- Golden seed `'skervik-golden-seed-1'` satisfies the red-token (no adjacent
  6/8) constraint on **attempt 4** (`attemptsUsed === 4`, well within the
  64-attempt bound). Property test in `boardgen.test.ts` additionally checks
  seeds `seed-0..seed-49` (all 50 satisfy within bound).
- `reduce.ts` gained a `case 'board.generated'` (mandatory: the exhaustive
  `never` check forces every `GameEvent` member to be handled). `validate.ts`
  needed **no change** — it switches on `PlayerIntent.type`, which is
  unmodified; board generation isn't triggered by a player intent, it's
  server-side match setup (same category as `match.started`, which also
  isn't produced via `validate`).
- Forced ripple fix (not scope creep, required for `tsc`/exhaustiveness):
  `types.test.ts`'s local `GameEvent` exhaustive switch needed a
  `case 'board.generated'` arm and a matching fixture entry, or the existing
  `const exhaustive: never = event` line fails to compile once `GameEvent`
  gains a 4th member.
- Verification, all green: `pnpm --filter @skervik/core test` (58/58, up from
  51 pre-story — 7 new in `boardgen.test.ts` + 1 case added to
  `types.test.ts`'s existing suite), `pnpm -r typecheck`, `pnpm -r lint`
  (needed `eslint --fix` + `prettier --write` once for import-sort/formatting
  on the new files), `pnpm -r build` — all pass across all 5 packages.
- No fixtures re-goldened; `docs/wiki/rng-stream-map.md` is the new doc this
  story creates per the plan's requirement.
