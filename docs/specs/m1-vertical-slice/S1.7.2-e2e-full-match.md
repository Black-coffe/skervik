# S1.7.2 — Cross-process E2E: a full Classic match online + replay-equality (CI gate)

## Goal

Prove the whole thing works **end to end, cross-process, for real**. Everything to date is
verified against mocks (pure core; boot-free room unit tests; S1.6.5 mock transport; S1.7.1's
single real-socket join proof). This story boots the real server (`startServer` from S1.7.1),
connects **3–4 real `@colyseus/sdk@0.17` clients** over a socket, drives them through a **complete
Classic match to `game.ended`** with legal moves, and asserts the two invariants that ARE the M1
promise:

1. **Server-side determinism** — the same seed + the same ordered intent sequence produce the same
   final `GameState`, run twice (byte-for-byte).
2. **Event-log replay equality (ADR-0009 event sourcing)** — parsing the server's persisted
   `matches/{id}/events.ndjson` (`parseGameEventLog`) and folding it through core `replay` yields a
   state **deep-equal** to the room's authoritative final `GameState`. The log is a faithful,
   replayable record — the foundation S1.7.3's `/verify` and every future replay/audit stands on.

This runs as a **named CI step** (A2 discipline: corrupting the flow or the log fails exactly this
gate). It is the vertical slice's headline proof: 3–4 people can play a fair, deterministic,
seed-verifiable Classic match online.

## Two phases (commit Phase A before Phase B; Queen can resume between)

### Phase A — server-side match-start orchestration (the missing trigger)
No match-start seam exists yet: the room holds a **lobby `GameState`** (S1.4.1) and nothing
transitions it into a playable game. E1.6/S1.6.5/S1.7.1 all deferred "match-start orchestration"
to E1.7 — **this is where it lands.** Add it to `GameRoom` (this is a sanctioned server change;
S1.7.1's "don't touch GameRoom" constraint was scoped to the boot story, NOT here):

- **Trigger (M1, minimal + deterministic):** when the room reaches its start condition — the
  configured player count is seated (default: `maxSeats`, i.e. 4; the E2E may configure N=3) —
  the room starts the match. No lobby-ready UI, no host button (later). Auto-start on seats-full
  is deterministic and scriptable. (If a manual "start" intent is cleaner given the join flow,
  that's an acceptable alternative — surface the choice.)
- **What start emits (via core, folded + persisted + broadcast exactly like any intent):**
  `match.started` (fixes the seated `playerOrder` — the snake/seat order) + `board.generated`
  (`generateBoard(seed, buildTopology())` — the SAME path S1.6.1's dev fixture uses; seed is the
  room's secret `#seed`, never serialized) → `reduce` folds them → `FsEventSink.append` persists →
  broadcast `event.batch` → the phase becomes the setup/snake-draft phase (S1.1.3). Clients fold
  the batch (Fork 1) and see the board appear.
- **Determinism:** board gen consumes the reserved RNG band (S1.1.2, `1_000_000+`); `playerOrder`
  is the deterministic seat order. No wall-clock, no ambient randomness — same seed ⇒ same board.
- **Boundaries:** `#queue`/persist-before-commit/seed-secrecy pipeline (S1.4.4b) unchanged — the
  start events flow through the SAME serialized append→commit→broadcast path, not a side channel.
  `packages/core` byte-unchanged (match-start uses existing `match.started`/`board.generated`
  events + `generateBoard`; if core lacks a needed genesis helper, hand-build the lobby→start
  events as S1.4.1 did — do NOT add core rules here).
- **Test (Phase A, can be boot-free):** seating N players triggers exactly one start; board is
  deterministic for a fixed seed; the start events land in the log; re-seating/idempotency guard
  (start fires once).

### Phase B — the cross-process E2E harness + replay-equality gate
- **Boot** the real server on an ephemeral port (S1.7.1 `startServer`/`createHttpServer` — confirm
  the exact surface at dispatch). One process.
- **Connect N real `@colyseus/sdk@0.17` clients** (`joinOrCreate(GAME_ROOM_NAME, {protocolVersion,
  guestId?})` — guest via `POST /auth/guest` if wired, else bare join). Each client is a **scripted
  test driver** (NOT a product bot — bots are M2): it folds `event.batch` through core `reduce`
  (reuse the S1.6.5 client fold, or a thin harness fold), and on its turn picks a **legal** move.
- **Drive a full match to `game.ended`:** snake-draft placements (S1.1.3) → turn loop
  (roll→produce→main→end, S1.2.4) → build settlements/roads/cities as affordable → to the victory
  threshold (`CLASSIC_VICTORY_PROFILE.vpToWin`=10, S1.3.4). The driver must be **deterministic and
  guaranteed to terminate**:
  - Legal-move selection is deterministic (fixed priority, e.g. build city > settlement > road >
    buy dev > end turn; accept no trades; discard deterministically on 7). No `Math.random` in the
    driver — determinism is the whole point.
  - **Termination:** the driver must provably reach `game.ended` OR the test fails loudly with the
    stuck state (never hang CI). If a pure greedy driver can deadlock (nobody can afford progress),
    author a **fixed intent script against a fixed seed** proven to reach 10 VP instead — whichever
    is robust. A hard turn/step cap that fails with a diagnostic (not a silent pass) is mandatory.
  - Trades are exercised at least once (the product heart) — e.g. one scripted bank/port trade
    (S1.3.3) or one p2p trade (S1.3.2) somewhere in the run — so the E2E covers the trade path, not
    just build/roll. Keep it minimal but present.
- **Assertions (the gate):**
  1. The match reaches `game.ended` / `finished` with a winner at ≥`vpToWin` (computed via
     `computeVictoryPoints`, the authoritative tally — NOT `player.victoryPoints`, S1.3.4 nit).
  2. **Determinism:** run the identical scripted sequence twice (same seed, same intents) → the two
     final `GameState`s are deep-equal.
  3. **Replay equality:** read the persisted `matches/{id}/events.ndjson` → `parseGameEventLog` →
     `replay` → deep-equal to the room's authoritative final `GameState`. (This is the event-sourcing
     promise + the seam S1.7.3's `/verify` needs.)
  4. **Seed secrecy:** assert no client ever received the raw seed (only `seedHash` in public state)
     — the commit half of commit-reveal holds end-to-end (S1.7.3 does the reveal half).
- **CI:** a named step (e.g. `E2E full-match gate`) in `.github/workflows/ci.yml` runs this test;
  document that breaking match flow or log fidelity fails exactly it (A2 discipline). Keep runtime
  bounded (a fixed short match; the turn cap guards against runaway).

## Key decisions (surface any deviation)

1. **Match-start = auto-fire on seats-full, deterministic, through the authoritative pipeline** —
   simplest M1 trigger; no lobby/host UI. Board from the room's secret seed via the existing
   `generateBoard` path; `playerOrder` = seat order.
2. **The E2E driver is a deterministic TEST script, not a bot** — fixed legal-move priority, no
   randomness, a hard termination cap that fails loudly. Determinism is the property under test.
3. **Replay-equality against the persisted ndjson is the core gate** — it proves event sourcing +
   underpins S1.7.3's `/verify`. Assert deep-equality to the room's authoritative final state.
4. **Both sides colyseus 0.17 (ADR-0011)** — the E2E drives clients with `@colyseus/sdk@0.17`
   (server-devDep), matching the S1.7.1-aligned client.
5. **Named CI gate (A2 discipline)** — corruption of match flow or log fidelity fails exactly this
   step; keep runtime short and bounded.

### Phase B — expansion-first driver reaches victory (2026-07-07)
- Files: `packages/server/src/e2e/scriptedDriver.ts` (strategy reorder + purposeful
  roads); deleted leftover `_debug.test.ts`. `scriptedDriver.test.ts` unchanged (4 assertions intact).
- Root cause of the plateau was NOT just the strategy ordering — the deeper driver is the
  **finite deflationary economy**: builds/discards `subtractResources` from the player and NEVER
  return them to the bank, and 4:1 bank-trades give surplus back (recycling), so the total
  spendable timber/clay for the WHOLE match ≈ 19 each. Production is all-or-nothing per resource,
  so once a resource's bank pool hits 0 it stops producing for everyone → permanent freeze.
- The old driver's `roadTowardSettlement` had a blind "toward open water" **fallback** that spent
  timber/clay on roads leading nowhere; three greedy seats drained bank timber/clay by ~turn 116
  with nobody past 8 VP. Fix: made roads PURPOSEFUL only — a road is built solely if its new empty
  endpoint IS an open settlement site or is a stepping-stone one hop from one (no fallback). Also
  reordered the main phase to expansion-first (settlement > road-that-opens-one > city > bank-trade
  toward cheapest reachable target) and added a piece-supply mirror (`BUILD_SUPPLY`) so the driver
  never emits a SUPPLY_EXHAUSTED intent.
- Result on seed `skervik-s1.7.2-e2e-match-seed` (N=3): **charlie wins at 10 VP = 4 cities (8) +
  longest road (2), 0 settlements, step 278** (well within the 6000 cap). 21 bank.trade events
  exercise the trade path. All 4 boot-free assertions green (victory, ≥1 trade, determinism,
  replay-equality). Core byte-unchanged (`check-core-no-runtime-deps.mjs` green); server 66 tests green.
- Deferred to the Queen's next resume (this dispatch was scoped to the driver only): the real
  socket harness (`fullMatch.e2e.test.ts`), the `@colyseus/sdk` server devDep, and the named CI step.

### Phase B — cross-process socket harness + named CI gate (2026-07-07)
- New file `packages/server/src/e2e/fullMatch.e2e.test.ts` (4 assertions); CI step added to
  `.github/workflows/ci.yml`. No source/dep changes (`@colyseus/sdk` + `@colyseus/testing` were
  already server devDeps; `packages/core`/`GameRoom`/`boot`/`scriptedDriver` untouched).
- Harness boots ONE real `createHttpServer({matchesDir, maxSeats:3, seed:E2E_SEED})` on an ephemeral
  port (`listen(0,'127.0.0.1')`), fetches a guest per client (`POST /auth/guest`), and joins 3 real
  `@colyseus/sdk` clients via `joinOrCreate(GAME_ROOM_NAME,{protocolVersion,guestId})`. The 3rd join
  fills seats → Phase A auto-fires `match.started`+`board.generated`.
- The harness is a central deterministic scheduler (NOT autonomous clients): it folds client[0]'s
  `event.batch` broadcasts through core `reduce` into one shared view, and each step picks the first
  seat (fixed player order) with a non-null `decideAction` and sends its intent over THAT seat's
  socket, then waits for the resulting broadcast before the next step. This mirrors the boot-free
  `simulateMatch` loop exactly, so socket timing can't reorder the applied-event sequence — the
  socket run reproduces the boot-free proof byte-for-byte: **278 steps, winner = seat index 2, 10 VP**.
- Authoritative final state read from `matchMaker.getLocalRoomById(roomId).gameState` (plain core
  GameState) BEFORE client teardown; log path `<matchesDir>/<roomId>/events.ndjson`.
- Assertions: (a) `game.ended.finalStandings[winner] >= vpToWin` (10) + ≥1 `bank.trade`; (b) run
  twice, canonicalize past the random sessionId/roomId labels (JSON string relabel by seat order),
  deep-equal; (c) `parseGameEventLog`→`replay` deep-equals `gameState`; (d) raw seed never appears in
  any client-visible message/Schema (only `seedHash`). CI step: `E2E full-match gate — cross-process
  match + replay-equality`. Verified a flipped persisted event breaks EXACTLY the replay-equality
  assert (A2). Two full socket matches run in ~0.7s; whole server suite 70 tests green.
