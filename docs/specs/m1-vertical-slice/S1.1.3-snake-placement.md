# S1.1.3 — Initial placement: snake draft with legality rules

## Goal

The setup phase of a Classic match: players place settlement+road in snake
order (1..N then N..1); the second settlement pays its adjacent tiles'
resources. All via the intent→validate→events→reduce pipeline, fully
replayable from the event log.

## Files

- `packages/core/src/types.ts` — additive: placement intents
  (`placeSettlement`, `placeRoad` or a combined setup intent — implementer's
  call, keep the union style), corresponding events, setup-phase fields on
  `GameState` (whose turn in the draft, what's already placed), player
  piece/resource state if not present yet.
- `packages/core/src/validate.ts` — setup-phase branch: turn order, legality.
- `packages/core/src/reduce.ts` — apply placement + resource payout events.
- `packages/core/src/setup.test.ts` (NEW) + fixture updates as needed.
- `packages/core/src/index.ts` (re-export anything new).

## Map slice

- S1.1.1 topology (vertex/edge adjacency), S1.1.2 layout in state.
- Existing FSM skeleton: `types.ts`/`reduce.ts` already model a minimal turn
  order from E0.5 — extend, don't fork; keep the exhaustive-`switch`+`never`
  reducer pattern and the "no input mutation" test convention.
- Plan §1 invariants: seed stays a `validate` param; profile constants
  (players count, pieces) go in a `ClassicProfile` object.

## Spec

- **Order:** with N players (3–4 in M1): rounds `P1..PN` then `PN..P1`; each
  turn = 1 settlement + 1 attached road, then the draft advances.
- **Settlement legality:** on a vertex; vertex empty; **distance rule** — no
  adjacent vertex holds any settlement; (setup only) no road-connection
  requirement.
- **Road legality:** on an edge touching the settlement just placed this draft
  turn; edge empty.
- **Second-settlement payout:** immediately on placing settlement #2, the
  player receives 1 resource per adjacent producing tile (desert pays nothing).
  Payout is part of the emitted events (explicit amounts — replay must not
  recompute).
- **Exit:** after the last placement the game transitions to the normal turn
  loop start state (first player's roll phase) — even if the roll phase itself
  is still rudimentary until E1.2.
- Reject reasons: out-of-turn, occupied, distance violation, detached road,
  wrong phase — extend `RejectReason` union accordingly.

## Acceptance criteria

- [ ] A scripted 4-player snake draft (fixture) replays from an event log to a
      deep-equal state: 8 settlements, 8 roads, correct payouts, correct next
      phase/player.
- [ ] Each legality rule has a negative test (occupied vertex, distance
      violation, detached road, out-of-turn, wrong phase) with the right
      `RejectReason`.
- [ ] Determinism: golden replay test extended/re-goldened consciously; reducer
      still pure (no-mutation test passes on new events).
- [ ] `pnpm -r typecheck && lint && test && build` green; zero runtime deps.

## Implementation notes
<!-- appended by the worker -->

Branch `feat/s1.1.3-snake-placement`, commit `3127c40`.

- **New intents**: `intent.placeSettlement { playerId, vertexId }`,
  `intent.placeRoad { playerId, edgeId }`.
- **New events**: `settlement.placed { playerId, vertexId, payout }` (payout
  is `{}` for a first settlement, explicit per-resource counts for a
  second — computed once in `validate`, applied verbatim by `reduce`);
  `road.placed { playerId, edgeId, nextPlayerId, nextPhase }` — the next
  player/phase are facts `validate` works out from the snake order, not
  recomputed by `reduce` (ADR-0003).
- **New `RejectReason`s**: `OCCUPIED`, `DISTANCE_VIOLATION`, `DETACHED_ROAD`,
  `WRONG_PHASE` (out-of-turn reuses the existing `NOT_YOUR_TURN`).
- **State/FSM**: `GameState.buildings? = { settlements: Record<VertexId,
  PlayerId>, roads: Record<EdgeId, PlayerId> }` and
  `GameState.pendingRoadVertexId?: VertexId` — both optional, populated only
  by the two new events (same "absent until its event lands" convention as
  `board?`). `pendingRoadVertexId` is exactly "the settlement placed this
  draft turn awaiting its road" — set by `settlement.placed`, removed
  (destructured out, not set to `undefined` — required by
  `exactOptionalPropertyTypes`) by `road.placed`. No new counter field:
  whose-turn/round is derived in `validate` from a pure `snakeOrder(playerIds)`
  helper (forward P1..PN then reverse PN..P1, length 2N) indexed by
  `Object.keys(buildings.roads).length` (completed turns so far); a
  player's "2nd settlement" (for payout) is derived from
  `Object.values(buildings.settlements).filter(owner === playerId).length`.
  `validate` still reuses `state.currentPlayerId`/`NOT_YOUR_TURN` uniformly
  for both setup and main-phase intents — `reduce` is the only place that
  advances `currentPlayerId` (via `road.placed`'s explicit `nextPlayerId`),
  so it always stays in sync.
- Extended `validate`'s top-level phase gate from a hardcoded `phase !==
  'main'` to a per-intent `requiredPhase` ('setup' for the two new intents,
  'main' for the existing two) — existing rollDice/endTurn behavior/tests
  are unchanged (same INVALID_PHASE/NOT_YOUR_TURN reasons, same order).
- `CLASSIC_SETUP_PROFILE = { settlementsPerPlayer: 2 }` added to
  `validate.ts` (rule-profile discipline) and re-exported from `index.ts`;
  the fixed forward+reverse snake shape isn't parameterized further since
  Classic never varies it (avoided speculative generality).
- **No re-goldening needed**: `board?`/`buildings?`/`pendingRoadVertexId?`
  are all absent unless their originating event was applied, and the
  `match.started`/`board.generated`/`dice.rolled`/`turn.ended` reduce cases
  were left untouched — `__fixtures__/golden.events.ndjson` and
  `golden.state.json` are byte-for-byte unchanged (confirmed via `git
  status`, not touched).
- `buildTopology()` (pure, per its own docstring: "callers should memoize
  the result") is memoized once at module scope in `validate.ts` rather
  than rebuilt every call, since `validate`'s signature couldn't grow a
  topology parameter.
- `types.test.ts`'s exhaustive `switch`/`never` blocks over `GameEvent` and
  `PlayerIntent` required updating (new cases) purely to keep `tsc` passing
  after the additive union growth — not a scope violation, a consequence of
  "keep the exhaustive-switch+never pattern."
- Added a small "never mutates its input state" unit test for
  `settlement.placed`/`road.placed` to `reduce.test.ts` (co-located with the
  existing reducer-purity tests) in addition to the new `setup.test.ts`.
- `setup.test.ts`: the scripted 4-player draft picks its 8 settlement
  vertices programmatically (`pickNonAdjacentVertices`, a greedy walk over
  `buildTopology()`'s vertex list) rather than hardcoding board IDs, so the
  fixture stays correct if the topology's enumeration order ever changes.
  The test board sets every tile to `'timber'` except the center tile
  (`'desert'`), so payout assertions exercise both "producing tile pays 1"
  and "desert pays nothing" without depending on `generateBoard`'s RNG
  shuffle (out of this story's scope).
