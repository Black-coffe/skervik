# S1.5.2 — Handshake + protocol version negotiation

## Goal

Make the WS connection **refuse a version-incompatible client at join time** and give
that refusal a typed, client-recognizable shape. On connect the client presents its
`protocolVersion`; the server compares it against the single source-of-truth
`PROTOCOL_VERSION` and, on mismatch, **rejects the join** with a typed `error.version`
reason (the incompatible client never enters the room). A compatible client joins and
receives the existing `state.snapshot` exactly as today. This closes E1.5 (protocol) so
E1.6's client has a stable, versioned contract to build against.

**Scope fence:** server + protocol only. Do NOT wire the CLIENT (no client WS until
E1.6 — the client will send `protocolVersion` and parse `error.version` THEN). Do NOT
touch `packages/core`. Do NOT add auth/identity/accounts (guest auth is **S1.7.1**,
Fastify) — this is purely protocol-version negotiation on the Colyseus join path. Builds
on `main` HEAD (S1.5.1 merged `2a95827`).

## Key decisions (locked by the spec — implement these, don't relitigate)

1. **Reject in `onAuth`, don't accept-then-error.** A protocol-version mismatch is a hard
   incompatibility — the client must not enter the room. Colyseus delivers a rejection by
   **throwing `ServerError(code, message)` from `onAuth`** (the join promise rejects on the
   client with that code+message). Put the version check in `onAuth` (add the hook if the
   room doesn't define one yet) so it runs BEFORE `onJoin`/seat assignment. Do not seat, do
   not broadcast, do not mutate state on a rejected join.
2. **`error.version` is a typed protocol message, authored for the client (E1.6) to
   recognize the rejection** — even though the transport delivery is a Colyseus
   `ServerError`. Carry a stable machine code + the two versions so the client can render a
   precise "update required" message. The `ServerError.message` should be the JSON of the
   `error.version` payload (or carry the code in `ServerError.code` + payload in message) so
   the reason survives the transport — pick the cleaner of the two and document it in a code
   comment.
3. **Compatibility rule = EXACT string equality with `PROTOCOL_VERSION`, in ONE helper.**
   Add `isCompatibleProtocolVersion(clientVersion: string): boolean` to `@skervik/protocol`
   returning `clientVersion === PROTOCOL_VERSION`. M2 loosens it (e.g. semver-major match) by
   editing this one function — do NOT scatter comparison logic. A **missing / non-string /
   malformed** client version is treated as **incompatible** (reject), not as legacy-allowed.
4. **`PROTOCOL_VERSION` stays the single source of truth** (currently in
   `packages/protocol/src/index.ts`). The handshake schema and the helper both reference it;
   never hardcode the version string a second time.
5. **No new `room.state` message.** The ROADMAP's "room.state" is already served by the
   existing `state.snapshot` (S1.4.1) a joined client receives — reuse it, don't duplicate.

## Files

  - `ConnectOptionsSchema` — the client-supplied join options: `{ protocolVersion: string }`
    (zod object; this is what arrives as Colyseus `client`/join `options`). Export its
    `z.infer` type (e.g. `ConnectOptions`).
  - `VersionErrorEnvelopeSchema` — the `error.version` server message:
    `{ v: 1, type: 'error.version', payload: { code: 'PROTOCOL_VERSION_MISMATCH',
    serverVersion: string, clientVersion: string | null } }`. Add `'error.version'` as a new
    discriminant in the outbound `ServerMessageSchema` discriminated union (so a client
    validates it like any other inbound server message). Keep the existing type-only envelope
    interfaces coherent — add a matching `VersionErrorMessage` interface if the file pairs
    hand-written types with schemas (mirror how S1.5.1 did `RejectMessage`).

    `ServerMessageSchema` touches an exhaustiveness pin, update it so the build still fails on
