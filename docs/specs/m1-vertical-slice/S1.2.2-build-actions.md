# S1.2.2 — Build actions: road / settlement / city (cost + legality)

## Goal

During the main phase a player spends resources to build: roads, settlements,
and city upgrades — each with Classic costs, network/distance legality, and
piece-supply limits. Pure intent→validate→events→reduce, replayable.

## Files

- `packages/core/src/types.ts` — additive: `buildRoad` / `buildSettlement` /
  `buildCity` intents; corresponding events; piece-supply counters + VP field on
  player state if absent; the `ClassicProfile` cost/limit constants.
- `packages/core/src/validate.ts` — build branch: phase guard (main phase),
  affordability, network/distance/upgrade legality; debit + place events.
- `packages/core/src/reduce.ts` — apply build events (debit resources, place
  piece, update VP + piece counts).
- `packages/core/src/build.test.ts` (NEW) + fixture updates.
- `packages/core/src/index.ts` (re-export).

## Map slice

- S1.1.1 topology (vertex/edge adjacency, edge↔vertex, own-network reachability).
- S1.1.3 setup placements (starting roads/settlements seed the network) + the
  distance-rule helper it introduced — REUSE it, don't duplicate.
- S1.2.1 main-phase entry + resource pool state.
- Plan §3 E1.2 build costs; §1 profile-as-config invariant.

## Spec — Classic costs (put in `ClassicProfile`, not scattered)

- road = 1 timber + 1 clay
- settlement = 1 timber + 1 clay + 1 fleece + 1 barley
- city = 3 iron + 2 barley (upgrades an existing OWN settlement)
- Supply limits per player: **15 roads, 5 settlements, 4 cities** (constants).

## Spec — legality

- **Road:** on an empty edge that connects to the player's own network (touches
  an own road or own settlement/city); respects supply.
- **Settlement:** on an empty vertex; **distance rule** (no settlement on an
  adjacent vertex); must touch the player's OWN road (this is the gameplay rule,
  unlike setup which waived it); respects supply. +1 VP.
- **City:** on a vertex holding the player's OWN settlement; replaces it (returns
  1 settlement to supply, consumes 1 city); +1 VP (settlement 1 → city 2 total).
- Reject reasons (extend union): can't-afford, occupied, distance-violation,
  not-connected, not-own-settlement, supply-exhausted, wrong-phase, out-of-turn.

## Acceptance criteria

- [ ] Each build type: one happy-path fixture (correct debit, placement, VP,
      supply decrement) + negative tests for every reject reason above.
- [ ] Network/distance legality reuses the S1.1.1/S1.1.3 helpers (no duplicated
      adjacency logic) — verified by test, not just by inspection.
- [ ] City upgrade correctly returns the settlement to supply and nets +1 VP.
- [ ] Determinism: replay deep-equal; reducer pure (no-mutation test passes);
      goldens re-goldened consciously if shape changed.
- [ ] `pnpm -r typecheck && lint && test && build` green; zero runtime deps.

## Implementation notes

- **Reused, not duplicated:** the S1.1.3 distance-rule adjacency walk is now
  a shared `violatesDistanceRule(vertex, buildings)` in `validate.ts`, called
  by both the free setup `intent.placeSettlement` branch (refactored) and
  the new paid `intent.buildSettlement` branch — one implementation, two
  callers. Road/settlement network legality (`touchesOwnNetwork`,
  `touchesOwnRoad`) is new (S1.2.2 has no S1.1.x precedent) but built on the
  S1.1.1 embedded topology (`VertexTopology.edgeIds`, `findVertex`) rather
  than any new graph traversal — Catan road legality only needs a one-hop
  "touches an existing own road/building" check, not full BFS reachability,
  since the network is built up incrementally and transitively.
- **New intents/events (additive):** `intent.buildRoad` / `BuildRoadIntent`,
  `intent.buildSettlement` / `BuildSettlementIntent`, `intent.buildCity` /
  `BuildCityIntent` → `road.built` / `RoadBuiltEvent`, `settlement.built` /
  `SettlementBuiltEvent`, `city.built` / `CityBuiltEvent`. Named `.built`
  (not `.placed`) deliberately, to keep the free setup-draft events
  (`settlement.placed`/`road.placed`) distinct from the paid main-phase
  ones — avoids ever conflating a free placement with a debited build.
- **New RejectReasons (additive):** `CANNOT_AFFORD`, `NOT_CONNECTED`,
  `NOT_OWN_SETTLEMENT`, `SUPPLY_EXHAUSTED`. `WRONG_PHASE`/out-of-turn are
  *not* duplicated — build intents fall through the existing
  `requiredPhase = 'main'` / `currentPlayerId` gate before the switch, so
  `INVALID_PHASE`/`NOT_YOUR_TURN` already cover those cases, verified by a
  dedicated test.
- **State additions:** `BuildingsState.cities?: Record<VertexId, PlayerId>`
  (optional, same "fact of an event landing" convention as `board`/`buildings`
  themselves) — a city vertex is removed from `settlements` when it moves
  here, never coexists with one. **No stored piece-supply counters** were
  added to `PlayerState`: supply is counted on the fly from `buildings`
  (`countOwned`, mirrors the pre-existing `priorSettlements` pattern in the
  setup branch) rather than a redundant field that could desync from the
  single source of truth — simpler and safer than the story text's "counters"
  wording implied (tradeoff, flagging per Law 4).
- **`ClassicProfile` costs/limits:** new exported `CLASSIC_BUILD_PROFILE`
  (`validate.ts`, re-exported from `index.ts`) — `costs.{road,settlement,city}`
  + `supply.{roads,settlements,cities}` (15/5/4), one object, no scattered
  magic numbers.
- **Closed an S1.2.1 seam:** `computeProduction` had a `TODO(S1.2.2)` for
  city payout — now a city pays 2 of its resource instead of 1
  (`buildings.cities?.[vertexId] ?? buildings.settlements[vertexId]`).
  In scope because the TODO explicitly named this story and cities didn't
  exist before it; left unfixed it would have been a live rules bug the
  moment cities shipped.
- **`reduce.ts`:** new `subtractResources` (mirrors the existing
  `addResources`), 3 new event branches; VP increments are computed directly
  in `reduce` (`victoryPoints + 1`), not carried as event data — same
  pattern `turn.ended` already uses for `turn + 1`, since it's a fixed rule
  constant, not something requiring a fact/recipe distinction.
- **No fixtures re-goldened** — `replay.test.ts`'s golden fixtures never
  exercise build events, so their shape is untouched; `BuildingsState.cities`
  being optional means old fixtures without it still parse/compare correctly.
- **Files touched beyond the story's list:** `types.test.ts` — its
  discriminated-union exhaustiveness switches (`never` checks) required the
  3 new event/intent variants and 4 new `RejectReason`s to be added or
  `tsc --noEmit` fails; this is a direct, mechanical consequence of the
  additive `types.ts` change, not scope creep — `pnpm -r typecheck` is this
  story's own verification gate.
- Verification: `pnpm --filter @skervik/core test` (96/96, +16 new) · `pnpm -r
  typecheck` · `pnpm -r lint` · `pnpm -r build` — all green.
