# S1.4.2 — Authoritative intent pipeline: validate → reduce → broadcast

## Goal

Wire the room's **authoritative gameplay pipeline**: a client sends an `intent`
envelope → the room runs `validate(gameState, intent, playerId, seed)` → on success it
folds the produced `GameEvent[]` through `reduce` into the authoritative `gameState`,
updates the public schema projection, and **broadcasts an `event.batch`** to every
client; on rejection it replies **privately to the sender** with the `RejectReason`.
This is the isomorphic-core payoff: clients apply the same `event.batch` through their
own bundled `reduce`.

**Scope fence (read first):** this story does NOT implement the seed reveal at game end
(**S1.4.3**) nor the actual ndjson persistence / core log-format change / re-golden
(**S1.4.4**). It DEFINES a clean **log-append seam** (an injectable sink the pipeline
calls with each validated `GameEvent`) but its default implementation here is a no-op /
in-memory buffer — S1.4.4 supplies the real FS writer. **Touch NOTHING in
`packages/core`** (call its existing `validate`/`reduce` only). Builds on S1.4.1
(`GameRoom`, `RoomSchema`, the protocol envelope) at `main` HEAD.

## Architecture (ADR-0009 — all 4 forks ratified)

- **Fork 1:** gameplay flows as `event.batch` broadcasts (the `GameEvent[]` from
  `validate`); clients fold them through their own `@skervik/core` `reduce`. The room
  keeps the authoritative **plain `GameState`**; the `@colyseus/schema` mirrors only the
  public projection (`seedHash`/`phase`/`currentPlayerId`/seats) — after each reduce,
  refresh `phase` + `currentPlayerId` in the schema so the lobby view stays current.
- **Seed:** pass the room's private `#seed` as `validate`'s 4th arg — never expose it.
- **Envelope:** import the `{v,type,payload}` types from `@skervik/protocol`
  (`intent`, `event.batch` already defined in `messages.ts` from S1.4.1). No zod yet
  (S1.5.1) — do a minimal structural guard on inbound messages (well-formed envelope,
  known `type`), rejecting malformed input with a `MALFORMED_INTENT`-style reply rather
  than throwing.

## Spec

- **Sender → playerId:** map the Colyseus client/session to the seated `playerId`
  (from the seat list S1.4.1 built). An intent from a client with no seat, or naming a
  different player, is rejected (don't trust client-supplied identity — the server binds
  identity to the connection). This is an authoritative-server invariant.
- **Validate:** call `validate(this.gameState, intent, playerId, this.#seed)`. Never
  throws — branch on `result.ok`.
- **On success:** fold each event through `reduce` (`events.reduce((s,e)=>reduce(s,e),
  gameState)`) to get the new authoritative `gameState`; assign it back; refresh the
  schema projection (`phase`, `currentPlayerId`, and any seat/turn change); **broadcast**
  an `event.batch` envelope carrying the `GameEvent[]` to ALL clients; hand the same
  events to the log-append sink. Order: reduce → persist-seam → broadcast (persist before
  broadcast so a future durable sink can't lose an acknowledged event; document the
  choice).
- **On reject:** send a private message to ONLY the sender with the `RejectReason`
  (a `reject`/`error` envelope). Do NOT broadcast rejects; do NOT mutate state.
- **Malformed envelope:** structural guard rejects (unknown `type`, missing `payload`,
  non-object) with a malformed reply — never throws out of the handler.
- **No seed leak:** the reject reply and the `event.batch` carry only public data
  (`validate` never returns the seed; events are public) — assert in a test.

## Acceptance criteria

- [ ] A seated client's valid intent → state advances via `reduce`, an `event.batch`
      with the exact `GameEvent[]` is broadcast to all clients, and the schema projection
      (`phase`/`currentPlayerId`) reflects the new state — tested on the real
      `@colyseus/testing` server with ≥2 clients (one acts, both receive the batch).
- [ ] An invalid intent → only the sender gets a reject with the correct `RejectReason`;
      no `event.batch` is broadcast; `gameState` is unchanged (deep-equal) — tested.
- [ ] Identity binding: an intent whose client isn't seated / claims another player's id
      is rejected (not applied) — tested.
- [ ] Malformed envelope (unknown type / missing payload) is rejected without throwing —
      tested.
- [ ] The log-append seam exists and is invoked once per validated batch with the events;
      default impl is a no-op/in-memory buffer (a test asserts it received the events).
      No FS write, no core format change (that's S1.4.4).
- [ ] No seed in any outbound message (reject or batch) — asserted.
- [ ] `pnpm -r typecheck && lint && test && build` green across all 5 packages;
      `@skervik/core` unchanged & still zero-dep.
