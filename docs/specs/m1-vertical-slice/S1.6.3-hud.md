# S1.6.3 — HUD: the Instruments layer (players rail · top bar · bottom deck)

## Goal

Build the **DOM "Instruments" surface** around the Pixi "Chart" canvas (DESIGN.md §1
two-surface model): the React HUD chrome that reads a `GameState` and renders the players
rail, top bar, and bottom deck per DESIGN.md §6 zoning, plus the M1 instrument component
primitives every later UI story reuses (§11). This is the first DOM/product surface
(S1.6.1/S1.6.2 were canvas-only). Every string flows through the S1.6.6a `t()` layer in
RU/UA/EN.

## Scope — build THIS, defer the rest (read carefully)

**Build:**
- **Two-surface layout** (§6 desktop ≥1280px zoning): a React app shell placing the
  `<GameTable>` canvas in the center, with `top bar`, `left players rail`, `right log
  panel (placeholder)`, and `bottom deck`. Canvas stays the hero; instruments frame it.
- **UI state store** — install `zustand`; a store holding the current `GameState` (from
  the dev fixture for now — no WS yet), the local `myPlayerId` (a dev constant until
  S1.6.5 auth/join sets it), and derived selectors (public Renown, hand size, isMyTurn).
- **Instrument primitives (§11), each with ALL states** (default/hover/focus/active/
  disabled + loading/error where meaningful) — build ONLY these this story: `Button`
  (primary/quiet/danger), `Pill` (resource / count / timer variants), `PlayerCard`,
  `Panel` (docked, collapsible), `PhaseIndicator`, `TimerDisplay`, `SeedChip`,
  `EmptyState`. Reuse `theme/tokens.css` + `flotillaColors.ts`.
- **Top bar:** short match id · `SeedChip` (fairness: `seedHash` first 8 chars, Ledger
  mono — see §3/§8) · `PhaseIndicator` (localized phase name) · `TimerDisplay` (idle/
  static — live countdown is S1.6.5).
- **Players rail (left):** one `PlayerCard` per player in **stable `playerOrder`** (NEVER
  reorder mid-match, §6): flotilla emblem + color (from `flotillaColors.ts`), **public
  Renown** (derived — see below), hand **size** (count only, not contents), ventures count
  (`publicDevCardCount`), award indicators (longest road / largest army holder), knights
  played; the current player's card carries the kerosene edge + emblem glow. Connection
  state = a stub ("online") until S1.6.5.

  first for colorblind read, §6); action `Button`s in FIXED positions all match long
  (build · trade · venture · end turn) — all **DISABLED** this story (no interaction until
  S1.6.5; buttons disable, never disappear/shift, §6). A tide-lot/die area placeholder.
- **Right panel:** a collapsible ship's-log `Panel` showing an `EmptyState` (localized) —
  the event-log CONTENT comes later; this story ships the panel + empty state only.
- **i18n:** every user-facing string is a typed `t()` key added to `i18n/keys.ts` +
  authored in `ru`/`uk`/`en` (ADR-0008; missing key = build fail via S1.6.6a's gate).
  Phase names reuse the `phase.*` seed keys from S1.6.6a. Numbers/timers via the i18n
  `formatNumber` (tabular, §10).
- **Mount** the S1.6.6a `LocaleSwitcher` in the real HUD chrome (e.g. top bar corner or a
  settings affordance) instead of its dev spot.

**DEFER — do NOT build here (each is its own later story):**

- Fairness "Честный жребий" panel + tide-lot **histogram** + income strip (DESIGN.md §8) —
  the `SeedChip` chip is in scope; the click-through dashboard is later.
- **Trade UI** (S1.6.4) — the trade button is a disabled placeholder here.
- **Any interactivity / play loop / WebSocket** (S1.6.5): no clicks that mutate state, no

## Core data contract (verified 2026-07-05 — read from these EXACT fields)

Import from `@skervik/core`. **No VP/selector helpers are exported — derive in the HUD.**

- **Public Renown (the crux — MUST NOT leak hidden VP):** `computeVictoryPoints` is NOT
  exported and INCLUDES hidden dev-card VP; `PlayerState.victoryPoints` is ALSO the full
  hidden-inclusive total. **Do NOT show either in the rail** — it would leak opponents'
  hidden VP cards. Derive **public Renown** per player:
  ```
  renown = settlements(p) + cities(p)*2
         + (state.longestRoadHolder === p ? CLASSIC_VICTORY_PROFILE.longestRoadVP : 0)
         + (state.largestArmyHolder === p ? CLASSIC_VICTORY_PROFILE.largestArmyVP  : 0)
  ```
  where `settlements(p)` = count of `state.buildings?.settlements` entries === p, and
  `cities(p)` = count of `state.buildings?.cities` entries === p. Read the award VP
  values from the **exported `CLASSIC_VICTORY_PROFILE`** (do NOT hardcode 2). The
  settlement=1 / city=2 point values are Classic constants — put them in ONE local
  `PUBLIC_RENOWN` constant with a comment that they mirror core's `computeVictoryPoints`
  sources (see the follow-up note below). Put this in a pure, unit-tested
  `hud/renown.ts` (or similar) — same discipline as `boardModel.ts`.
  - For the LOCAL player's OWN card, you MAY additionally show their own hidden VP
    (`state.devCards?.[myPlayerId]?.held.victoryPoint ?? 0`) since a player sees their own
    cards — but NEVER add hidden VP to any OTHER player's displayed renown.
- **Awards:** `state.longestRoadHolder?` / `largestArmyHolder?` (optional `PlayerId`);
  `state.knightsPlayed?: Record<PlayerId, number>` (public, per-player played-knight
  count). Thresholds in exported `CLASSIC_VICTORY_PROFILE` (`vpToWin` 10, `longestRoadMin`
  5, `largestArmyMin` 3, `longestRoadVP`/`largestArmyVP` 2). No public road-length is
  exposed (don't show it).
- **Resources / hand:** `PlayerState.resources: Record<ResourceType, number>`. Hand size =
  `Object.values(resources).reduce((a,b)=>a+b,0)` (no core helper). Show OPPONENTS' hand
  **size only** (count), MY hand as full per-resource pills. (Core exposes opponents'
  breakdown today; a server redaction layer is later — the HUD voluntarily shows only the
  count for opponents to match real play + that future.)
- **Dev cards:** `publicDevCardCount(holdings)` is EXPORTED — use it for any player's
  visible ventures total: `publicDevCardCount(state.devCards?.[p] ?? { held:{}, boughtThisTurn:{} })`.
  `state.devDeckRemaining?: number` (public deck count).
- **Phase/turn:** `state.phase: GamePhase` (`'lobby'|'setup'|'roll'|'main'|'robber'|
  'finished'`), `state.turn` (1-based), `state.currentPlayerId`, `state.playerOrder?`
  (fixed seat order; seat index = `playerOrder.indexOf(id)`; falls back to `players`
  order). `isMyTurn = state.currentPlayerId === myPlayerId`. Map each GamePhase to a
  localized `phase.*` key (reuse/extend S1.6.6a's seed).
- **Fairness:** `state.seedHash: string` (64-hex) → SeedChip shows first 8 chars.
- **NOT in core** (do not expect; use client/stub): turn timers, connection status, player
  display colors (use `flotillaColors.ts`).

## Fold in the S1.6.6a i18n-framework nits (natural home — this story extends i18n + mounts the switcher)

Three non-blocking nits from S1.6.6a's lead-review land HERE (you're already adding keys
and moving the `LocaleSwitcher` into the HUD chrome):
1. **`LocaleSwitcher` roving-tabindex + arrow keys** — it currently sets radio ARIA roles
   but every option is a tab stop with no arrow-key navigation. Implement the proper radio
   pattern: single tab stop (roving `tabIndex` 0 on active / -1 on others) + `onKeyDown`
   Left/Right/Up/Down to move selection (or switch to `role="group"` toggle buttons).
2. **Its hardcoded tri-lingual `aria-label="Language / Мова / Язык"`** bypasses the i18n
   gate — replace with a real trilingual `t()` key (e.g. `a11y.languageSwitcher`) authored
   in ru/uk/en. (The language endonyms stay non-`t()`; only this assistive label moves.)
3. **Route plural `{count}` through `formatNumber`** — `translate.ts` currently
   `String(count)`s the plural count, so it isn't locale-grouped. Either wire the count
   through the i18n `formatNumber`, or ensure HUD count displays use `formatNumber`
   (tabular, §10). Minimal fix acceptable; don't over-engineer.

## Address S1.6.2 nit-2 (fixture negatives) HERE

The S1.6.2 dev fixture applies a `CityBuiltEvent` that subtracts iron3/barley2 without
prior income, so a player can show NEGATIVE resources. Since this HUD reads the fixture and
renders resource pills, **fix the fixture** so no player has negative resources — grant the
city cost as income first (or otherwise ensure non-negative hands) — keeping the fixture
real (through `reduce`). Document the change.

## Key decisions (surface any deviation)

1. **`myPlayerId` is a dev constant** (e.g. `playerOrder[0]`) until S1.6.5 auth/join —
   the store exposes it; do not hardcode player identity into components.
2. **Public-Renown derivation lives in the client** for M1 (core exports no public-VP
   helper). **Follow-up (record, don't do here):** consider exporting a pure
   `publicVictoryPoints(state, playerId)` from `@skervik/core` so display VP is sourced
   from the rules core (single-source), removing this client-side mirror. Flagged as a
   tradeoff per the isomorphic-core principle; acceptable for M1 because the mirror is
   trivial and reads award values from the exported profile.
3. **No component library** for these primitives (DESIGN.md §11) — hand-built with tokens;
   headless a11y primitives (e.g. Radix) only if a later story (Dialog/Tooltip) justifies.
4. **Zustand** is this story's new dep (planned, ADR-aligned) — UI state only; the
   authoritative `GameState` still comes from core/(later)WS, never invented in the store.
