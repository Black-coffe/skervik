# S1.7.3 — Seed reveal + `GET /matches/{id}/verify` (provably-fair RNG, M1-gate closer)

## Goal

Deliver the **Verify** half of commit-reveal (`docs/wiki/fair-rng-commit-reveal.md`): after a
match ends, publish the raw `seed` durably, and expose an endpoint that lets **anyone recompute
every seed-derived random draw from the public event log and confirm nothing was altered** —
answering the competitor's biggest reputational failure (perceived rigged dice) with cryptographic
proof, not a promise. This is the year's headline feature («Честный жребий» — the Sealed Lot) and
the **last story that closes the M1 gate**.

Today the pieces exist but are not wired to a verifier:
- The secret `#seed` is revealed to a `MatchMetadataStore` seam (S1.4.3) **only on `game.ended`,
  exactly once** — but the default store is in-memory (`InMemoryMatchMetadataStore`), nothing
  survives the process, and there is NO durable reveal + NO verify endpoint.
- The event log (`{matchesDir}/{matchId}/events.ndjson`, `FsEventSink`, matchId = roomId) records
  every random event as **facts** (`dice.rolled` `{dieA,dieB,total}`, robber steals, dev-card
  draws) plus `match.started.seedHash` (the public commitment) — but nothing recomputes those facts
  from the revealed seed to prove they weren't forged.

S1.7.3 closes that loop: **durable reveal → recompute-and-compare verification → a public verdict.**

## What "verify" must actually prove

For a finished match, given the revealed `seed`, the persisted event log, and the public
`seedHash`, assert ALL of:

1. **Commitment holds:** `sha256Hex(seed) === match.started.seedHash` — the revealed seed is the
   one committed at match start (the server couldn't have swapped it).
2. **Every seed-derived draw is faithful** — recompute each random event from `seed` +
   its `rngStreamIndex` using the SAME core primitives the draws used, and deep-compare to the
   logged fact. The M1 random-draw surface (confirm the full set against the engine at dispatch):
   - **`dice.rolled`** — `rollDie(seed, gameplayStreamIndex(event.index, DICE_A))` and `DICE_B`
     must equal the logged `dieA`/`dieB` (and `total`).
   - **Robber steal** — the stolen card, drawn via `deriveValue(seed, gameplayStreamIndex(idx,
     STEAL))` (`validate.ts:731`), matches what the log recorded.
   - **Dev-card draw** — `shuffledDevDeck(seed)[drawIndex]` (`validate.ts:1204`) matches the logged
     drawn card.
   - **Board layout** — `generateBoard(seed, buildTopology())` (`BOARD_GEN_STREAM`) deep-equals the
     `board.generated` event payload (tileKinds/tileTokens/portContents/robberTileId).
3. **Reveal-timing invariant intact:** the seed is exposed ONLY because the match ended — a
   not-yet-ended match returns "not revealed", never the seed (the commit half stays sealed until
   `game.ended`). (Reveal on end is S1.4.3's job; this story must not weaken it.)

The endpoint returns a structured JSON verdict (ok + per-check results + `seedHash` + the revealed
`seed` + winner) — machine-checkable, the seam the M3 verification UI (S3.3.3) and roll-distribution
analytics (S3.4.1) later render.

## Scope — build THIS, defer the rest

**Build:**
1. **Core verification primitive (recommended — see Key decisions #1):** a pure, golden-tested
   `verifyMatchRandomness(seed, events)` in `@skervik/core` that recomputes every seed-derived event
   (dice, steal, dev-card, board) via the exact draw primitives and returns
   `{ ok, mismatches: [...] }`. Keeps the `rngStreamIndex` scheme (incl. the private `GAMEPLAY_SLOT`)
   as the single source of truth in the deterministic core — no duplication, no drift. This is an
   ADDITIVE core function + export (NO rule change); `reduce`/`validate` behavior byte-unchanged.
2. **Durable seed reveal:** an `FsMatchMetadataStore implements MatchMetadataStore` writing
   `{matchesDir}/{matchId}/seed-reveal.json` (a JSON sidecar NEXT TO `events.ndjson`, same dir/id)
   on `recordSeedReveal`, with a read path the endpoint uses. Wire it as the default store when
   `matchesDir` is set (mirror how `FsEventSink` is selected), falling back to the in-memory store
   otherwise. (`seed.reveal` stays OUT of the ndjson — Fork 3.)
3. **`GET /matches/:id/verify`** — a Fastify route (`packages/server/src/routes/matchVerify.ts`,
   `registerMatchVerifyRoute(fastify, deps)`, mirror `routes/guestAuth.ts`/`health.ts` + register in
   `boot.ts`). Handler: resolve `{matchesDir}/:id/` → read `events.ndjson`
   (`parseGameEventLog`) + `seed-reveal.json`; if no reveal (match not ended / unknown id) → a clean
   non-leaking response (`404`/`409` with an error envelope, NEVER the seed); else compute the
   verdict — `sha256Hex(seed) === seedHash` (server-side crypto) **and**
   `core.verifyMatchRandomness(seed, events)` (the draw check) — and return the JSON verdict.
4. **The fairness proof test** (the gate): a test that plays/loads a finished match, calls verify,
   asserts `ok: true`; then **tampers** (flip one `dieA` in the persisted log OR swap the revealed
   seed) and asserts verify returns `ok: false` naming the mismatch — corruption is caught, not
   masked. Plus: verify on a not-yet-ended match does NOT leak the seed. Wire it into a **named CI
   step** (A2 discipline — breaking the fairness math or reveal fails exactly it).

**DEFER — do NOT build here:**
- **Client verification UI / fairness dashboard** — S3.3.3 (M3), per DESIGN.md §8. This story is
  server + core only; no `packages/client` changes.
- **Roll-distribution analytics** — S3.4.1 (M3).
- **PostgreSQL `matches.seed`** — post-M1. The durable reveal is the FS JSON sidecar; the
  `MatchMetadataStore` interface already lets the DB writer drop in later with zero room change.
- **Auth / rate-limiting on `/verify`** — public verifiability IS the point (anyone can check);
  hardening is later.
- **Room create/join-by-code** (S1.7.1b), bots (M2), reconnect/timers/matchmaking (M2+).
- Any `reduce`/`validate` rule change — verification only READS + recomputes; it never alters play.

## Key decisions (surface any deviation)

1. **Verification math lives in `@skervik/core`, not the server (RECOMMENDED).** The endpoint is a
   thin I/O wrapper; the recompute-and-compare of every draw is a pure core function using the SAME
   `rollDie`/`gameplayStreamIndex`/`deriveValue`/`shuffledDevDeck`/`generateBoard` primitives (and
   the private `GAMEPLAY_SLOT` scheme) the engine draws with. **Why:** the plan's #1 cross-cutting
   risk is "stream-index drift between server draws and replay verification" — duplicating the slot
   scheme in the server would be a SECOND implementation that can silently drift from the real
   draws, making a "valid" verdict meaningless. Core-resident + golden-tested verification is the
   isomorphic-core philosophy and the only way the proof is trustworthy. **Rejected:** server
   re-implements the derivation (drift risk); exporting `GAMEPLAY_SLOT` alone and open-coding the
   recompute in the server (same drift risk, scatters the scheme). The core change is ADDITIVE
   (new pure fn + export) — the zero-runtime-deps invariant and all existing draws stay byte-equal.
2. **`sha256Hex(seed) === seedHash` stays server-side.** Core is browser-isomorphic + zero-dep and
   has no crypto; `sha256Hex` (`server/seed.ts`) does the commitment check. Clean split: core proves
   the DRAWS, the server proves the COMMITMENT.
3. **Durable reveal = a JSON sidecar next to the log** (`{matchesDir}/{matchId}/seed-reveal.json`),
   selected by `matchesDir` like `FsEventSink`. `matchId === roomId` today, so `:id` addresses both
   the log and the reveal in one dir. Keep `seed.reveal` OUT of `events.ndjson` (Fork 3 — it's not a
   `GameEvent`; polluting the replayable log would break replay-equality).
4. **Never leak the seed early.** No reveal file ⇒ verify responds without a seed (`404`/`409` +
   error envelope). The reveal-only-on-`game.ended` guard (S1.4.3, verified airtight) is untouched.
5. **Named CI gate (A2).** The fairness proof test runs as its own step; a deliberate log/seed
   tamper must fail EXACTLY it.

### Follow-up (lead-review B1 soundness fix, 2026-07-07)

Lead-review found the verifier keyed each seed-derived draw off log-author-controlled
fields (`event.index`, `event.deckRemaining`), so a compromised server could grind those
to pass a forged match. Closed **verify-side only** — `reduce`/`validate` PLAY behavior is
byte-unchanged (chose this over a `reduce` contiguity assert to avoid perturbing the 217
golden/determinism/e2e tests; `parseGameEventLog` left untouched for the same reason).

- **`packages/core/src/verify.ts`** — draws now bind to a verifier-owned `expectedIndex`
  counter (genesis 0, +1 per event) instead of `event.index`; every event's `index` is
  checked for contiguity (flags relabels/gaps). Dev-card `drawIndex` comes from a
  verifier-owned `devRemainingBefore` deck counter (not `event.deckRemaining`, which is
  itself flagged when it disagrees). Added logged `total === dieA + dieB` consistency check.
- **`packages/server/src/routes/matchVerify.ts`** — N1: gate seed release on a `game.ended`
  line in the parsed log, not just the sidecar's presence (belt-and-suspenders vs a
  stray/partial sidecar leaking an unfinished match's seed).
- **N2 (documented, out of M1 scope):** contiguity catches relabels and gaps, but seed+log
  alone cannot prove no event was OMITTED — a fully re-indexed deletion leaves no positional
  gap. Full protection needs a signed / hash-chained log. Noted in `verify.ts` header.
- Tests: `verify.test.ts` +4 (relabeled dice index, forged deckRemaining, total mismatch,
  index gap); `matchVerify.test.ts` +1 (N1 no-leak). Core 217→221, server 75→76. The three
  B1 core tests + the N1 server test fail against the pre-fix code (verified empirically);
  S1.7.2 `fullMatch.e2e.test.ts` replay-equality still green; core stays zero-runtime-deps.
