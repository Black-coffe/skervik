# S1.3.1 — The 7 / robber: discard, relocate, steal (+ knight play)

## Goal

Resolve rolling a 7 and playing a knight — the two ways the robber moves.
On a 7: every player holding >7 cards discards floor(half) (own choice via
intent); then the mover relocates the robber and steals 1 random card from an
adjacent victim. The **knight** dev card (deferred from S1.2.3) shares the exact
relocate+steal path and increments the player's played-knight count for largest
army (S1.3.4). The random steal-pick is the first user of the reserved
same-event RNG slots from S1.2.1.

## Map slice

- S1.2.1 gameplay RNG scheme (`streamIndex = eventIndex*K+slot`, K=8; slots 2–7
  reserved for same-event draws) — the steal-pick uses one of these slots.
- S1.2.4 turn FSM (the `robber` phase seam it left) + per-turn markers.
- S1.2.3 dev-card holdings + "bought this turn" + one-play-per-turn marker.

  param, the stolen card is chosen by PRNG, recorded in the event).

## Spec

- **Discard on 7:** every player with >7 resource cards must discard
  `floor(handSize / 2)`. The specific cards are the player's OWN choice (via a
  `discard` intent) — the FSM waits in the discard sub-phase until all owing
  players have discarded (order-independent). Amounts/cards explicit in events.
- **Relocate:** the roller (or knight-player) moves the robber to a DIFFERENT
  tile (not its current tile). Reject same-tile / off-board.
- **Steal:** from the settlements/cities adjacent to the new robber tile, the
  mover picks ONE victim who has ≥1 card; steal 1 card chosen by the PRNG
  (`deriveValue(seed, eventIndex*K + <steal slot>)` → index into the victim's
  sorted hand). Record the stolen resource explicitly in the steal event. If no
  adjacent victim has cards, no steal (documented no-op).
- **Knight:** `playDevCard('knight')` enters the SAME relocate+steal path
  (no discard step), respects one-dev-card-per-turn and not-bought-this-turn,
  and increments the played-knight counter (largest army, S1.3.4). May be played
  before the roll (Classic) — decide + document the phase guard.
- Reject reasons (extend): must-discard-first, wrong-discard-count,
  robber-same-tile, no-such-victim, victim-has-no-cards, not-in-robber-phase.

## Implementation notes
<!-- appended by the worker -->

- **Steal-pick slot:** gameplay slot `2` (`GAMEPLAY_SLOT.STEAL`, `validate.ts`), disjoint from dice (`0`/`1`) and the still-reserved `3`–`7`. Documented in `docs/wiki/rng-stream-map.md` §1. Draw is keyed to the `robber.moved` EVENT's own `index` — `state.eventIndex` for the 7-roll path (`intent.moveRobber`), `state.eventIndex + 1` for the knight path (paired after `devCard.knightPlayed`).
- **Discard-wait FSM:** `GameState.playersToDiscard?: readonly PlayerId[]` — present only while non-empty (dropped entirely once resolved, same "absent key" convention as `pendingRoadVertexId`). A rolled 7 computes it via `computePlayersOwingDiscard` (every player with `handSize > 7`, owing `floor(handSize/2)`) and carries it on `DiceRolledEvent.playersToDiscard` (present, possibly `[]`, only when `total===7`). `reduce`'s `dice.rolled` case reads it to decide `'robber'` vs `'main'`. `intent.discard` is the one intent NOT gated by `currentPlayerId` (any owing player, any order) — the top-level phase guard carves out this exception; ownership is checked inside the case via list membership (`NOT_OWED_DISCARD`). `intent.moveRobber` is blocked with `MUST_DISCARD_FIRST` while the list is non-empty.
- **Knight/7 shared path:** `resolveRobberMove(state, seed, stealEventIndex, playerId, tileId, victimId)` in `validate.ts` is the ONE relocate+steal legality+draw function both branches call — `intent.moveRobber` (7-roll finish, always `nextPhase: 'main'`) and `playDevCard`'s `case 'knight':` (no discard step, emits `devCard.knightPlayed` + `robber.moved` together, `nextPhase` = the phase captured BEFORE the play — `'roll'` if played pre-roll, `'main'` if post-roll, fixing what would otherwise be a bug: pre-roll knight play must NOT skip the turn's mandatory roll). Played-knight counter: `GameState.knightsPlayed?: Readonly<Record<PlayerId, number>>`, bumped in `reduce`'s new `devCard.knightPlayed` case, never reset by `turn.ended` (match-long total for S1.3.4).
- **Victim selection semantics (a design decision beyond the literal spec text):** if ANY adjacent owner (excluding the mover) holds ≥1 card, `victimId` is REQUIRED and must name one of them — omitting it or naming an empty-handed owner is rejected (`NO_SUCH_VICTIM` / `VICTIM_HAS_NO_CARDS`). Only when NO adjacent owner holds any card is the steal a true no-op regardless of `victimId`. This makes the two reject reasons meaningfully distinct and forces a real choice when one exists (undocumented in the story's literal spec text but consistent with Catan's actual rule that stealing is mandatory when a legal target exists).
- **New intents:** `intent.discard` (`resources` — the exact discard multiset), `intent.moveRobber` (`tileId`, optional `victimId`). `PlayKnightIntent` extended additively with `tileId`/`victimId` (was previously argument-less).
- **New events:** `resources.discarded` (`resources`, `remainingToDiscard`), `robber.moved` (`tileId`, optional `stolenFrom`/`stolenResource`, `nextPhase`), `devCard.knightPlayed` (bumps the counter, enters `'robber'`, mirrors `dice.rolled`'s zero-duration pass-through pattern). `DiceRolledEvent` extended additively with optional `playersToDiscard`.
- **New RejectReasons:** the 6 named in the story (`MUST_DISCARD_FIRST`, `WRONG_DISCARD_COUNT`, `ROBBER_SAME_TILE`, `NO_SUCH_VICTIM`, `VICTIM_HAS_NO_CARDS`, `NOT_IN_ROBBER_PHASE`) plus one addition, `NOT_OWED_DISCARD` (a non-owing player attempts `intent.discard` — not covered by any of the 6 named reasons; `NOT_YOUR_TURN` didn't fit since discard is explicitly allowed from non-current players). `KNIGHT_DEFERRED` is left in the `RejectReason` union unused (never repurposed, per the append-only-union invariant) — no code path emits it anymore.
- **Off-board tile / undefined board:** reuses `MALFORMED_INTENT` (consistent with `findVertex`/`findEdge`'s existing pattern), not a new reason.
- **Goldens:** NOT re-goldened. `__fixtures__/golden.events.ndjson` contains no 7-roll (totals 8 and 5 only), so wiring `dice.rolled`'s 7-case into `'robber'` doesn't touch it — verified before assuming.
- **Existing tests touched (pre-existing behavior that changed, not scope creep):**
  - `turn.test.ts`: the multi-turn scripted fixture's `SEED` coincidentally rolled a 7 at its very first roll under the new wiring (previously invisible since a 7 used to fall through to `'main'` like any other roll) — brute-forced a replacement seed (`skervik-turn-fsm-seed-32`) where none of the fixture's 6 scripted rolls total 7 and `DECK[0]` is still `'yearOfPlenty'` (preserving every other assertion unchanged). Also updated the "a rolled 7 still lands on main" test to assert `'robber'` instead (the documented seam this story fills).
  - `production.test.ts`: updated the 7-deferral test's name/assertions to check `playersToDiscard: []` is now present on the event (production/no-steal behavior itself — 1 event, no `resources.produced` — is unchanged).
  - `devcards.test.ts`: removed the obsolete `KNIGHT_DEFERRED` rejection test (knight is un-deferred); kept the "knight count tracked on buy" test, renamed the `describe` to point at `robber.test.ts` for full play coverage.
  - `types.test.ts`: extended the `GameEvent`/`PlayerIntent`/`RejectReason` exhaustive-narrowing fixtures with the new variants (required for the `never`-exhaustiveness checks to typecheck).
- **New file `packages/core/src/robber.test.ts`** (24 tests): deterministic seeded steal + replay, steal-index formula verification, no-op-when-nobody-has-cards, self-exclusion, full scripted 7→discard(order-independent)→relocate→steal→replay flow, empty-discard-list 7 case, knight before/after roll, one-per-turn/not-bought-this-turn guards, and one negative test per new reject reason.
