# S1.4.3 — Commit-reveal RNG: seed lifecycle + reveal at game end

## Goal

Complete the **provably-fair commit-reveal** loop on the server: the room commits to
its secret seed by publishing `seedHash` at match start (S1.4.1 already sets it), keeps
the raw seed private and feeds it only to `validate` (S1.4.2), and — **only after a
`game.ended` event** — reveals the raw seed into durable **match metadata** (NOT the
event log, per ADR-0009 Fork 3). This directly answers the competitor's "rigged dice"
reputation: anyone can later recompute every roll from the event log + revealed seed.

**Scope fence:** does NOT implement the event-log ndjson persistence / core format
change (**S1.4.4a**, running now) nor the durable FS/DB writer + `GET /matches/{id}/verify`
endpoint (**S1.4.4b / S1.7.3**, brings Fastify). It records the reveal via a small
**metadata-store seam** (default in-memory; the real FS/DB impl lands with the verify
endpoint). **Touch NOTHING in `packages/core`.** Builds on S1.4.2's merged pipeline
(`main` HEAD `381d72d`) — the reduce-fold there surfaces the `game.ended` event.

## Architecture (ADR-0009 Fork 3 — ratified)

- Crypto seed generated at `onCreate` (S1.4.1), held in the private `#seed` field.
- `seedHash = sha256(seed)` is the ONLY public seed artifact (`GameState.seedHash`).
- Raw seed → only `validate`'s 4th arg (S1.4.2).
- **Reveal:** when the pipeline applies a batch containing `game.ended`, the room writes
  the raw seed to **match metadata** via the seam — never into the event log, never a
  `GameEvent`, strictly AFTER `game.ended`, exactly once.
- **Mirror the S1.4.2 seam pattern:** S1.4.2 shipped `GameEventSink` (interface +
  `InMemoryEventSink`/`NoopEventSink`, injected via `GameRoomOptions.sink`). Add the
  metadata seam the SAME way (`GameRoomOptions.metadataStore`) for consistency + testability.
- **Leak-prevention checklist (ADR — enforce + test):** (1) no seed field on any
  `@colyseus/schema`; (2) reject/error replies never echo the seed; (3) structured logs
  emit `seedHash` only; (4) `state.snapshot` sends public `GameState` (seed-free);
  (5) reveal happens strictly after `game.ended`, never earlier.

## Spec

- **Commit** (already done S1.4.1): confirm `seedHash` is public/visible before any roll
  (commit genuinely precedes randomness).
- **Reveal:** on a batch containing `game.ended`, call
  `metadataStore.recordSeedReveal(matchId, this.#seed)` exactly once; never earlier;
  idempotent if `game.ended` somehow re-applies (it can't after freeze, but guard anyway).
- **`sha256Hex`** pure exported fn + known-vector unit test (regression guard — S1.4.1 nit #1);
  `GameState.seedHash === sha256Hex(seed)` now directly testable.
- **Leak checklist** — explicit tests: reveal does NOT fire on any pre-`game.ended`
  batch; no seed on schema/snapshot/broadcast/reject at any point; only `seedHash` public.
