# S1.3.2 — Player↔player trade: offer / counter / accept (atomic swap)

# NOTE: This is the CORE-side domain logic for the product's heart (the Trade
# UI is S1.6.4). Correctness + atomicity here; the UX lives in the client.

## Goal

The current player proposes a resource trade (give X / get Y) to other players;
recipients accept, reject, or counter; on acceptance the swap is **atomic** —
one event moves both bundles, never a partial state. No resources are created or
destroyed. Only the current player initiates; trades happen in the main phase.

## Spec

- **Propose:** current player, main phase; `give`/`get` are non-empty resource
  bundles; proposer must currently hold the full `give`. Targets = all other
  players (or a named subset — keep it all-others for M1). Opens an offer.
- **Respond:** a targeted player may `accept` (must hold the full `get`),
  `reject`, or `counter` (which opens a new offer with swapped roles — bounded:
  no infinite counter chains; keep it to the simple offer→counter→accept/reject
  for M1, document the depth rule).
- **Execute (atomic):** on accept, emit ONE `trade.executed` event carrying both
  concrete bundles + both party ids; `reduce` applies both transfers together.
  Never emit a state where one side paid and the other didn't.
- **Close:** accept executes+closes; reject by all targets closes; proposer may
  `cancel` while open. Only one open offer at a time (M1 simplification).
- **No bank interaction** here (that's S1.3.3). Pure player↔player.
- Reject reasons (extend): not-current-player, wrong-phase, proposer-cant-afford,
  responder-cant-afford, no-open-offer, not-a-target, empty-bundle,
  offer-already-open.

## Acceptance criteria

## Implementation notes

- **State model:** `GameState.openTradeOffer?: TradeOffer` — `{ proposerId, give, get, targets, depth }`, absent when no offer is pending (same optionality convention as `pendingRoadVertexId`). `give`/`get` are always from `proposerId`'s perspective. Only one offer lives on state at a time (`TRADE_OFFER_ALREADY_OPEN` guards a fresh `proposeTrade`).
- **Atomicity:** one `trade.executed` event (`proposerId`, `accepterId`, `give`, `get`) resolves the swap in `reduce`'s single matching `case` — both hands move in the same state transition, offer dropped in the same transition. No other case can leave a half-applied trade; conservation is asserted in `trade.test.ts`.
- **Counter-offer bound:** `depth` on `TradeOffer`, `0` for the original proposal, `1` for its (at most one) counter. `counterTrade` reuses the SAME `trade.offered` event type (swapped `proposerId`/`give`/`get`, `targets` narrowed to just the original proposer, `depth + 1`). A second counter (`depth >= 1`) is rejected `TRADE_COUNTER_LIMIT_REACHED` — no chains beyond offer -> counter -> accept/reject/cancel.
- **New intents:** `intent.proposeTrade`, `intent.acceptTrade`, `intent.rejectTrade`, `intent.counterTrade`, `intent.cancelTrade`. New events: `trade.offered`, `trade.executed`, `trade.rejected`, `trade.cancelled`. New `RejectReason`s: `TRADE_OFFER_ALREADY_OPEN`, `NO_OPEN_TRADE_OFFER`, `NOT_A_TRADE_TARGET`, `NOT_TRADE_PROPOSER`, `TRADE_COUNTER_LIMIT_REACHED` (affordability/empty-bundle reuse existing `CANNOT_AFFORD`/`MALFORMED_INTENT`; non-current-player propose/cancel-by-wrong-actor reuse `NOT_YOUR_TURN` where applicable).
- **Authorization carve-out:** `validate`'s top-level "only current player acts" guard now also excludes `acceptTrade`/`rejectTrade`/`counterTrade`/`cancelTrade` (mirrors the S1.3.1 `intent.discard` carve-out) — each checks membership itself (`offer.targets.includes(playerId)` for responses, `offer.proposerId === playerId` for cancel). This correctly handles a `counterTrade`'s role swap: the counter-offer's proposer can be a non-current player, and can still `cancelTrade` their own live counter.
- **Both-sides affordability:** `proposeTrade`/`counterTrade` check the proposer/counterer can afford their own `give`; `acceptTrade` checks the accepter can afford `get` AND re-checks the ORIGINAL proposer can still afford `give` (resources may have shifted via other main-phase actions while the offer sat open) — both checked before the `trade.executed` event is ever emitted.
- **Turn-boundary cleanup:** `reduce`'s `turn.ended` case now also drops `openTradeOffer` (implicit cancel) — an open offer never survives past the turn it was proposed in, so callers don't need to `cancelTrade` before ending their turn.
- **Goldens:** untouched — verified via `git diff --stat` (only `types.ts`/`validate.ts`/`reduce.ts`/`types.test.ts`/`trade.test.ts` changed; `__fixtures__/golden.*` not in the diff).
- **`types.test.ts`:** the file has its own exhaustive-switch exercise for `GameEvent`/`PlayerIntent`/`RejectReason` unions (a `never`-typed `default` branch) — extending the trade unions required adding matching fixtures/cases there too, or `tsc` fails (caught by `pnpm -r typecheck`, not `pnpm --filter @skervik/core test` alone).
- **Files touched:** `packages/core/src/types.ts`, `packages/core/src/validate.ts`, `packages/core/src/reduce.ts`, `packages/core/src/types.test.ts` (exhaustiveness fixtures), `packages/core/src/trade.test.ts` (new).
