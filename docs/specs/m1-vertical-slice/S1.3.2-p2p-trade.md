# S1.3.2 — Player↔player trade: offer / counter / accept (atomic swap)

# NOTE: This is the CORE-side domain logic for the product's heart (the Trade
# UI is S1.6.4). Correctness + atomicity here; the UX lives in the client.

## Goal

The current player proposes a resource trade (give X / get Y) to other players;
recipients accept, reject, or counter; on acceptance the swap is **atomic** —
one event moves both bundles, never a partial state. No resources are created or
destroyed. Only the current player initiates; trades happen in the main phase.

## Spec

- **Propose:** current player, main phase; `give`/`get` are non-empty resource
  bundles; proposer must currently hold the full `give`. Targets = all other
  players (or a named subset — keep it all-others for M1). Opens an offer.
- **Respond:** a targeted player may `accept` (must hold the full `get`),
  `reject`, or `counter` (which opens a new offer with swapped roles — bounded:
  no infinite counter chains; keep it to the simple offer→counter→accept/reject
  for M1, document the depth rule).
- **Execute (atomic):** on accept, emit ONE `trade.executed` event carrying both
  concrete bundles + both party ids; `reduce` applies both transfers together.
  Never emit a state where one side paid and the other didn't.
- **Close:** accept executes+closes; reject by all targets closes; proposer may
  `cancel` while open. Only one open offer at a time (M1 simplification).
- **No bank interaction** here (that's S1.3.3). Pure player↔player.
- Reject reasons (extend): not-current-player, wrong-phase, proposer-cant-afford,
  responder-cant-afford, no-open-offer, not-a-target, empty-bundle,
  offer-already-open.

## Acceptance criteria

- [ ] Atomicity: a `trade.executed` fixture shows both hands change in one event;
      a mid-trade replay never exposes a half-applied swap; total resources in
      play are conserved (asserted).
- [ ] Affordability enforced on BOTH sides (proposer for `give`, accepter for
      `get`) with negative tests.
- [ ] Only current player proposes; only targeted players respond; one open
      offer at a time — each guarded with a negative test.
- [ ] Counter-offer opens a swapped-role offer and is bounded (no infinite loop).
- [ ] Determinism: replay deep-equal; reducer pure; goldens conscious.
- [ ] `pnpm -r typecheck && lint && test && build` green; zero runtime deps.
