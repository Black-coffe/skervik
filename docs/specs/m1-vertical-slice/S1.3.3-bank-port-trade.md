# S1.3.3 — Bank & port trade (4:1, 3:1, 2:1)

## Goal

The current player trades with the bank at their best available rate: 4:1
always; 3:1 at any generic port they own; 2:1 at a resource-specific port they
own (for that resource). Deterministic, no PRNG.

## Files

- `packages/core/src/types.ts` — additive: `bankTrade` intent (give-resource +
  count, get-resource); `bank.trade` event; reject reasons.
- `packages/core/src/validate.ts` — compute the player's best rate for the given
  resource from owned port vertices; verify the give count matches rate; verify
  affordability + bank stock of the get-resource.
- `packages/core/src/reduce.ts` — apply the exchange (debit player + bank credit;
  credit player + bank debit).
- `packages/core/src/banktrade.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).

## Map slice

- S1.1.1 port slots + S1.1.2 port contents (which slot is 3:1 vs 2:1-resource).
- S1.1.3 / S1.2.2 settlement placement (a player "owns" a port if they have a
  settlement/city on a vertex incident to that port slot's edge) — REUSE the
  vertex↔port mapping; do not re-derive geometry.
- S1.2.x resource pool + bank stock.
- Plan §3 E1.3 "Bank 4:1 always; port rates from owned vertex ports".

## Spec

- **Rate resolution:** best (lowest) rate the player qualifies for on the give
  resource — 2:1 if they own a matching resource port, else 3:1 if they own any
  generic port, else 4:1. Give count must be an exact multiple of the rate for
  the requested number of get-units (M1: single-unit trades are enough; support
  N units if trivial, else document single-unit).
- **Bank stock:** the bank must hold the get-resource; returned resources go back
  to the bank pool. No PRNG, no other players involved.
- Reject reasons (extend): wrong-rate-count, cant-afford, bank-out-of-resource,
  wrong-phase, not-current-player.

## Implementation notes

- **Intent shape:** `BankTradeIntent` (`intent.bankTrade`) is `{ give: ResourceType,
  count: number, get: ResourceType }` — `count` is the GIVE amount for exactly
  1 unit of `get` (no separate `getCount`; a multi-unit get would just repeat
  the intent). Matches the story's literal "give-resource + count,
  get-resource" wording — chose this over a generic `getCount` field to avoid
  an unused parameter (Law 2).
- **Event:** `BankTradedEvent` (`bank.trade`) carries `playerId, give, count,
  get, bank` — `bank` is the FULL resultant pool after the trade (both the
  `get` debit and the `give` credit), same explicit-fact discipline as
  `ResourcesProducedEvent`/`YearOfPlentyPlayedEvent`.
- **Rate resolution** (`validate.ts`'s `bestBankRate`): 2:1 if
  `ownedPortContents` contains a `{kind:'resource', resource: give}` match;
  else 3:1 if it contains any `{kind:'generic'}`; else the base
  `CLASSIC_BANK_TRADE_PROFILE.baseRate` (4). The "2:1 for a DIFFERENT resource
  doesn't help" edge case falls out naturally — the resource-match check is
  keyed to the specific `give` resource, so an unrelated resource port never
  matches and the logic falls through to the generic/base check exactly as if
  no port were owned at all.
- **Port ownership** (`ownedPortContents`): walks `topology().portSlots` (S1.1.1,
  fixed geometry, index-paired with `state.board.portContents` per S1.1.2's
  documented convention), and for each slot resolves its edge via `findEdge`
  then checks `edge.vertexIds.some(v => buildings.settlements[v] === playerId
  || buildings.cities?.[v] === playerId)` — owning a settlement/city on EITHER
  endpoint counts, reusing S1.1.3/S1.2.2's existing building records with no
  new geometry derivation.
- **Profile constant:** `CLASSIC_BANK_TRADE_PROFILE = { baseRate: 4 }`,
  exported from `validate.ts` and re-exported from `index.ts` alongside
  `CLASSIC_BUILD_PROFILE`/`CLASSIC_SETUP_PROFILE`.
- **Reject reasons:** added ONE new reason, `WRONG_RATE_COUNT` (`count` doesn't
  match the resolved rate). Reused `MALFORMED_INTENT` (non-positive/non-integer
  `count`), `CANNOT_AFFORD` (can't cover `count` of `give`), `BANK_EXHAUSTED`
  (bank holds 0 of `get`), `NOT_YOUR_TURN`/`MUST_ROLL_FIRST`/`INVALID_PHASE`
  (bank trade falls into the existing main-phase-only, current-player-only
  guard bucket — no top-level guard changes needed).
- **Validation order:** shape (`MALFORMED_INTENT`) -> rate match
  (`WRONG_RATE_COUNT`, independent of the player's hand) -> affordability
  (`CANNOT_AFFORD`) -> bank stock (`BANK_EXHAUSTED`).
- **Bank bookkeeping:** `nextBank[get] = available - 1` computed first, then
  `nextBank[give] = (nextBank[give] ?? default) + count` reads back off the
  already-updated `nextBank` (not the pre-trade snapshot) — this makes a
  same-resource trade (`give === get`, legal but degenerate, not forbidden)
  net out correctly instead of double-counting one side.
- **`reduce.ts`'s `bank.trade` case:** debits `give`×`count` and credits
  `get`×1 from the acting player via the existing `addResources`/
  `subtractResources` helpers, sets `state.bank = event.bank` wholesale (same
  pattern as `resources.produced`/`devCard.yearOfPlentyPlayed`).
- **`types.test.ts`:** the file's exhaustive-`never`-switch pattern over
  `GameEvent`/`PlayerIntent`/`RejectReason` required touching it additively
  (new event/intent fixtures + switch cases + the new reason string) — not in
  the story's file list, but a direct, unavoidable consequence of extending
  those unions (the switches don't compile otherwise). No behavior in that
  file changed beyond recognizing the new variants.
- **Goldens:** untouched — verified via `git status` (no diff under
  `__fixtures__/`), and no bank-trade event is added to any golden log.
- **Test file:** `packages/core/src/banktrade.test.ts` (NEW), 13 tests:
  rate resolution ×4 (no-port 4:1, generic-port 3:1, matching-port 2:1,
  different-resource-still-4:1 edge with both the wrong-count rejection and
  the right-count success), negative cases ×5 (WRONG_RATE_COUNT,
  MALFORMED_INTENT, CANNOT_AFFORD, BANK_EXHAUSTED, NOT_YOUR_TURN,
  MUST_ROLL_FIRST — 6 actually), reduce/conservation ×3 (debit+credit+bank
  conservation, no-mutation, determinism). Port fixtures built from the real
  `buildTopology()` (S1.1.1) rather than fabricated ids, so the port-slot ↔
  edge ↔ vertex geometry is exercised for real, not mocked.
- **Verification:** `pnpm --filter @skervik/core test` — 195/195 passed (was
  182 before this story). `pnpm -r typecheck && pnpm -r lint && pnpm -r build`
  — all green across all 5 workspace packages.
