# S1.3.3 — Bank & port trade (4:1, 3:1, 2:1)

## Goal

The current player trades with the bank at their best available rate: 4:1
always; 3:1 at any generic port they own; 2:1 at a resource-specific port they
own (for that resource). Deterministic, no PRNG.

## Files

- `packages/core/src/types.ts` — additive: `bankTrade` intent (give-resource +
  count, get-resource); `bank.trade` event; reject reasons.
- `packages/core/src/validate.ts` — compute the player's best rate for the given
  resource from owned port vertices; verify the give count matches rate; verify
  affordability + bank stock of the get-resource.
- `packages/core/src/reduce.ts` — apply the exchange (debit player + bank credit;
  credit player + bank debit).
- `packages/core/src/banktrade.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).

## Map slice

- S1.1.1 port slots + S1.1.2 port contents (which slot is 3:1 vs 2:1-resource).
- S1.1.3 / S1.2.2 settlement placement (a player "owns" a port if they have a
  settlement/city on a vertex incident to that port slot's edge) — REUSE the
  vertex↔port mapping; do not re-derive geometry.
- S1.2.x resource pool + bank stock.
- Plan §3 E1.3 "Bank 4:1 always; port rates from owned vertex ports".

## Spec

- **Rate resolution:** best (lowest) rate the player qualifies for on the give
  resource — 2:1 if they own a matching resource port, else 3:1 if they own any
  generic port, else 4:1. Give count must be an exact multiple of the rate for
  the requested number of get-units (M1: single-unit trades are enough; support
  N units if trivial, else document single-unit).
- **Bank stock:** the bank must hold the get-resource; returned resources go back
  to the bank pool. No PRNG, no other players involved.
- Reject reasons (extend): wrong-rate-count, cant-afford, bank-out-of-resource,
  wrong-phase, not-current-player.

## Acceptance criteria

- [ ] Rate resolution tested for 4:1 (no port), 3:1 (generic port owned), and
      2:1 (matching resource port owned) — including a player who owns a 2:1 for
      a DIFFERENT resource still getting 4:1/3:1 for the traded one.
- [ ] Give-count validation (exact multiple) + affordability + bank-stock
      negative tests.
- [ ] Bank conservation: player+bank totals conserved across the trade.
- [ ] Determinism: replay deep-equal; reducer pure; goldens conscious.
- [ ] `pnpm -r typecheck && lint && test && build` green; zero runtime deps.
