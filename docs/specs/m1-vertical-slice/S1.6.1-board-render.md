# S1.6.1 — Board render from GameState (+ client foundation: design tokens, app shell)

## Goal

Stand up the **real product client** by rendering the board **from an authoritative
`@skervik/core` `GameState`** (never from proto ad-hoc data). This is the first
E1.6 story, so it also lays the client foundation every later UI story reuses:

1. **Design-token substrate** — DESIGN.md §2 tokens as CSS custom properties (DOM)
   + a frozen sRGB-hex constants module (Pixi canvas needs numeric colors).
2. **App shell** — replace the E0.4 proto mount with a `<GameTable>` React
   component that takes a `GameState` and renders "The Chart" (the Pixi canvas).
3. **Board tile layer** — the 19 hex tiles painted from `GameState.board`:
   resource kind → color token + stroke-pattern (a11y second cue), number tokens
   as aged chart-paper discs with probability pips, the robber marker on
   `robberTileId`, sea beneath the tiles, pan/zoom. Rendered from real core types.
4. **Quarantine the proto** — port the reusable hex-math out of `src/proto/`, then
   delete `src/proto/` (its perf role is done; E0.4 results are locked in docs and
   the `feat/e04-pixi-prototype` branch preserves it).

**This makes `pnpm --filter @skervik/client dev` show a real, correctly-colored
19-hex board generated by core** — the first playable-looking surface.

## Core contract (render from these EXACT types — verified 2026-07-05)

Import from `@skervik/core`. Do not re-derive or duplicate these shapes.

- `buildTopology(): BoardTopology` — **call once, cache module-level.** Pure &
  deterministic; gives every tile's `coord: AxialCoord {q,r}`, its 6 `vertexIds`
  & `edgeIds`, plus `vertices`, `edges`, `portSlots`. Geometry never changes.
- `GameState.board?: BoardState` = `{ tileKinds: Record<TileId, TileKind>,
  tileTokens: Record<TileId, number>, portContents: PortContent[],
  robberTileId: TileId }`. `board` is **optional** (present once `board.generated`
  landed) — render an empty sea if absent, do not crash.
- `TileKind = 'timber' | 'clay' | 'fleece' | 'barley' | 'iron' | 'desert'`.
- **Desert:** has a key in `tileKinds` (`'desert'`), NO key in `tileTokens`.
  Non-desert tiles: `tileTokens[id]` ∈ {2,3,4,5,6,8,9,10,11,12} (no 7).
- ID formats: `TileId = "q,r"` · `VertexId = "q,r|q,r|q,r"` (3 sorted tile-coords,
  `|`-joined) · `EdgeId = "vid::vid"`. Helpers: `tileId(coord)`,
  `findTile/findVertex/findEdge(topology, id)`.
- `robberTileId: TileId` — the tile the robber sits on (starts on the desert).
- **No player→color mapping in core** (players are opaque `PlayerId` strings).
  **This story owns the flotilla palette** — see below. (Buildings/roads are
  S1.6.2, so no player-colored pieces render here yet; still define the palette
  module now as foundation.)
- **No pixel math in core** — the client owns 100% of hex→pixel.

## Key decisions (make these; surface any deviation)

1. **Two color modules, kept in sync by construction (DESIGN.md §2):**
   - `theme/tokens.css` — `:root { --bg-abyss: oklch(...); ... }` for every §2
     token (DOM/React surfaces consume these).
   - `theme/canvasColors.ts` — the **frozen sRGB hex** equivalents as numeric
     literals for Pixi (`bgAbyss: 0x040c12`, `chartPaper: 0xe1d6c2`,
     `chartPaperInk: 0x392a1e`, `hotNumber: 0xc53637`, resources
     `timber: 0x428252`, `clay: 0xb16246`, `fleece: 0xd6d1c3`, `barley: 0xc0aa54`,
     `iron: 0x737b86`, `line: 0x29353c`, `primary: 0xf2af48`, …). Copy hex values
     **verbatim from DESIGN.md §2** — do not eyeball or convert OKLCH yourself.
   - `theme/flotillaColors.ts` — the 4 flotilla identities (§2.2: Petrel
     `0x4682cc`, Orca `0xeeeeee`, Walrus `0xc26030`, Narwhal `0x60ccc5`) with a
     stable `PlayerId`/seat-index → flotilla mapping helper (used by S1.6.2+).
     Color NEVER without an emblem (a11y §2.2) — for now expose the emblem id
     alongside each color; actual glyph rendering is S1.6.2.
2. **Port the proto hex-math into a pure, tested module** `board/hexGeometry.ts`:
   `HEX_SIZE = 46`, `Y_SCALE = 0.6`, `EXTRUDE_DEPTH = 16` (locked to Pixi v8 per
   E0.4 — do NOT retune), `parseTileId(id): AxialCoord`, `axialToPixel(coord)`,
   `hexCorners(radius)`, and `tokenPipCount(token): number` (probability frequency
   `= 6 - |7 - token|`, so 2/12→1 … 6/8→5). Keep it DOM/Pixi-free (pure numbers)
   so it unit-tests without a canvas.
3. **Board descriptor layer** `board/boardModel.ts` (pure): map
   `GameState.board` → an array of render descriptors
   `{ tileId, coord, kind, token: number | null, isDesert, isRobber, pipCount,
   fillHex, patternKind }` — the single place `TileKind → §2 color + pattern`
   and `token → pips / hot-number` decisions live. Pure & unit-tested; the Pixi
   layer just paints descriptors.
4. **Dev fixture uses REAL core board generation.** Build the preview `GameState`
   by producing a real `board.generated` (via core's board generator / reducing
   the event), NOT by hand-authoring tile data — so the render proves the actual
   type contract end-to-end. Fixed dev seed for reproducibility. Fixture +
   dev-only entry live under `src/dev/` and are clearly throwaway (superseded by
   the WS client in S1.6.5).
5. **Ambient mist pause under `prefers-reduced-motion`** (DESIGN.md §9 merge
   gate) — keep the proto's slow mist alpha pulse but swap to a static frame when
   the media query matches. Ambient period ≥4s.

## Spec (what "rendered correctly" means)

- **Sea first:** the canvas background is `--bg-abyss #040c12`; tiles read as
  sitting on water (DESIGN.md §12 "the Chart should read as water, not void" —
  a subtle sea gradient/texture beneath the tile field, canvas-layer only).
- **Tiles:** each of the 19 tiles painted at its `axialToPixel` position with the
  y-flatten + extrusion 2.5D read; fill = the resource's §2.3 color; the proto's
  per-kind **stroke pattern** kept as the a11y second cue (resource is never
  hue-only). Desert tile visually distinct, hosts the robber, no number.
- **Number tokens:** aged **chart-paper discs** (`--chart-paper #e1d6c2` fill,
  `--chart-paper-ink #392a1e` digits) with **probability pips** (dot count =
  `tokenPipCount`); **6 and 8 render their digits/pips in `--hot-number #c53637`**
  (tide marks). Digits rendered at 2× and scaled down for crispness (§12); digits
  only (locale-independent, no text baked otherwise).
- **Robber:** a clear marker on `board.robberTileId` (a simple, on-brand piece —
  no player color; robber is neutral). Reads at a glance over any tile.
- **Interaction:** drag-pan + wheel-zoom (port the proto feel, clamp as proto
  did). Resize-aware. Clean `destroy()` on unmount (no leaked Pixi app / ticker).
- **Absent board:** if `state.board` is undefined, render the sea + nothing else
  (no crash) — a valid pre-`board.generated` state.
- **Determinism of layout:** same `GameState` → identical tile pixel positions
  every render (pure `hexGeometry`); no `Math.random`/`Date` in the render path.
