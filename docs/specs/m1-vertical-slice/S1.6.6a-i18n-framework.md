# S1.6.6a — i18n framework (custom typed layer over platform `Intl`)

## Goal

Materialize the client i18n **mechanism** decided in ADR-0010 — a small, first-party,
zero-dependency typed layer over the platform `Intl` APIs — so that from the very next
UI story (S1.6.3 HUD) **every user-facing string is a typed key present in all three
locales, enforced at build time.** This is the framework portion of E1.6's i18n, pulled
ahead of S1.6.3 as its own story (the full per-story locale content grows story-by-story
thereafter; ADR-0008).

The deliverable is the call-site contract every later UI story uses: `t(key, params?)`,
`useTranslation()`, `<I18nProvider>`, a `LocaleSwitcher`, plural + number/date formatting
via `Intl`, and three typed locale record files — plus a small **real seed** of keys that
proves every mechanism with tests.

## Scope fence

- **`packages/client` ONLY.** Do NOT touch core/protocol/server/bots,
  DESIGN.md/PRODUCT.md/docs/design/, docs/adr/, governance, or memory/.
- **NO runtime dependency** (ADR-0010 invariant 3). This is a custom layer over built-in
  `Intl.PluralRules` / `Intl.NumberFormat` / `Intl.DateTimeFormat` + React context. Do NOT
  add `i18next`, `react-intl`, `zustand`, or any package. If you think you need one, STOP
  and report.
- **NO network fetch of locale data** — locale records are bundled TS modules (AGPL/no-CDN,
  ADR-0010 invariant 3). No lazy HTTP loading.
- **Do NOT build the HUD** (S1.6.3) or translate the board canvas (it has no strings). Do
  NOT alter the S1.6.1/S1.6.2 board rendering. This story adds the i18n layer + wraps the
  app in the provider + a demo/seed; the HUD consumes it next.
- **Fonts:** DESIGN.md §3 requires self-hosted OFL faces covering RU+UA+EN. If they are
  not yet vendored in the repo, **do NOT add font binaries in this story** (that's an
  asset task) — rely on the fallback stack (`system-ui` etc.) and note the gap; do NOT
  fetch fonts from a CDN.

## Design (ADR-0010 realized)

### Locale ids
`type Locale = 'ru' | 'uk' | 'en'` — BCP-47 codes (Ukrainian = `uk`, used by `Intl`).
Default `ru` (user base). Persist the choice in `localStorage`; fall back to `ru` if
absent/invalid. (The product brands Ukrainian as "UA"; the `Intl`/code id is `uk`.)

### Typed key catalogue — the build-time trilingual gate (the crux)
- `i18n/keys.ts` — a single `TranslationKey` union (string-literal union OR a `const`
  keys object whose value type is the union). This is the single source of truth for
  every user-facing string id. Namespaced dotted keys (e.g. `common.cancel`,
  `phase.trade`, `hud.renown`).
- `i18n/messages.ts` — `type MessageValue = string | PluralForms` where
  `PluralForms = { other: string } & Partial<Record<Intl.LDMLPluralRule, string>>`
  (`Intl.LDMLPluralRule` = `'zero'|'one'|'two'|'few'|'many'|'other'`); at minimum `other`.
- `i18n/locales/ru.ts`, `uk.ts`, `en.ts` — each `const <loc>: Messages = { ... }` where
  `type Messages = Record<TranslationKey, MessageValue>`. **Because each locale is typed
  `Record<TranslationKey, …>`, a missing key (or an extra/typo'd key) is a `tsc` ERROR** —
  this is ADR-0008's "no string in fewer than three languages" enforced at compile time,
  not a runtime fallback. Demonstrate this is real (see acceptance).

### `t()` + hook
- `i18n/translate.ts` — pure `translate(messages, locale, key, params?)`:
  - plain string message → interpolate `{placeholder}` tokens from `params`.
  - `PluralForms` message → pick the form via `new Intl.PluralRules(locale).select(count)`
    (fall back to `other`), then interpolate (including `{count}`). Plural keys require a
    `count` param — if absent, dev-warn and use `other` (do NOT throw in prod).
  - unknown/missing at runtime shouldn't happen (types prevent it), but be defensive:
    return the key string + dev-warn rather than crashing.
- `i18n/format.ts` — `makeFormatters(locale)` → `{ formatNumber, formatDateTime }` over
  `Intl.NumberFormat` / `Intl.DateTimeFormat` (tabular-friendly; DESIGN.md §10).
- `i18n/I18nProvider.tsx` + `useTranslation()` — React context holding `locale` +
  `setLocale`; `useTranslation()` returns `{ t, locale, setLocale, formatNumber,
  formatDateTime }`. `t` is bound to the active locale's `Messages`.

### LocaleSwitcher (DESIGN.md §11 component)
- `i18n/LocaleSwitcher.tsx` — switch ru/uk/en. Its option labels are the language
  **endonyms** (`Русский` / `Українська` / `English`) — these are proper nouns, NOT
  translatable keys (the one legitimate non-`t` UI text). Full keyboard reachability +
  visible focus ring (`--accent`, DESIGN.md §10); ≥44px hit targets; uses §2/§4 tokens
  (`tokens.css` from S1.6.1). All states (default/hover/focus/active) per §11.

### Seed keys (small but REAL — enough to test every mechanism)
Author, in all three locales, a minimal seed that exercises: (a) a plain string, (b) an
interpolated string with a `{placeholder}`, and (c) a **pluralized** string that shows
correct Slavic forms. Suggested real, reusable seed (lore-primer-sourced where relevant):
- `common.cancel`, `common.confirm` (plain).
- `phase.setup` / `phase.roll` / `phase.main` / `phase.finished` (plain; DESIGN.md §6
  phase names — the HUD will reuse these). Use the lore glossary tone
  (`docs/wiki/lore-primer.md`): e.g. Постановка / Прилив / Торговля-Стройка / Итог.
- `hud.resourceCards` (plural; count of resource cards) — prove RU `1 карта / 2 карты /
  5 карт`, UK forms, EN `1 card / 2 cards`. This single key demonstrates the plural gate.
Keep the seed small; S1.6.3 grows the catalogue with HUD keys. (Author from the glossary;
do not invent lore terms — mechanical UI words are fine.)

### App integration
Wrap the app root in `<I18nProvider>` (in `main.tsx`, around `<GameTable>`). Render the
`LocaleSwitcher` somewhere unobtrusive for now (a dev corner is fine; S1.6.3 places it in
the real HUD chrome). Optionally show one `t()`-rendered demo line proving live switching.
Do NOT restructure the board.

## Suggested file layout

```
packages/client/src/i18n/
  keys.ts               # TranslationKey union / const keys
  messages.ts           # Messages, MessageValue, PluralForms types
  locales/ru.ts         # const ru: Messages
  locales/uk.ts         # const uk: Messages
  locales/en.ts         # const en: Messages
  translate.ts          # pure translate() + interpolation + plural select
  translate.test.ts     # interpolation, plural (ru/uk/en), missing-count dev fallback
  format.ts             # Intl.NumberFormat / DateTimeFormat helpers
  I18nProvider.tsx      # context + useTranslation()
  LocaleSwitcher.tsx    # ru/uk/en switch (endonym labels)
  i18n.test.ts          # locale completeness (all 3 have all keys) + type-gate note
  index.ts              # re-exports (t/useTranslation/I18nProvider/LocaleSwitcher/Locale)
packages/client/src/main.tsx   # wrap in <I18nProvider>
```

## Acceptance criteria

- [ ] `Locale = 'ru'|'uk'|'en'`; three `Messages` locale files typed
      `Record<TranslationKey, MessageValue>`; **a missing key in any one locale fails
      `pnpm --filter @skervik/client typecheck`** — prove it in the report (temporarily
      delete one key from `uk.ts`, show tsc errors, restore). A runtime completeness test
      (`i18n.test.ts`) also asserts all three locales cover every key.
- [ ] `translate()` handles plain + `{placeholder}` interpolation + `PluralForms` via
      `Intl.PluralRules(locale).select(count)`; tested for RU **and** UK correct
      one/few/many (e.g. 1/2/5 → distinct forms) and EN one/other; missing-`count` on a
      plural key dev-warns and uses `other` (no throw).
- [ ] `useTranslation()` / `<I18nProvider>` provide `{ t, locale, setLocale, formatNumber,
      formatDateTime }`; locale persists to `localStorage`, defaults to `ru`.
- [ ] `LocaleSwitcher` switches ru/uk/en live, labels = endonyms, keyboard-reachable with
      visible focus ring, ≥44px targets, token-styled (all §11 states).
- [ ] Seed keys authored in all three locales (plain + interpolated + plural); app wrapped
      in `<I18nProvider>`; `pnpm --filter @skervik/client dev` shows switching working.
- [ ] **NO runtime dependency added** (`package.json` deps unchanged); no network locale
      fetch; no fonts fetched from a CDN; no files outside `packages/client/`; the
      S1.6.1/S1.6.2 board render is unchanged.
- [ ] The ONLY non-`t` user-facing text is the LocaleSwitcher's language endonyms (proper
      nouns). No other hardcoded translatable string anywhere.
- [ ] `pnpm -r typecheck && pnpm -r lint && pnpm -r test && pnpm -r build` green.
