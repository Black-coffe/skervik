# S1.1.1 — Hex board model: tiles, tokens, ports, adjacency graph

## Goal

A pure, serializable board model for the radius-2 hex board (19 tiles) with
canonical IDs and adjacency queries for tiles, **vertices (54)** and **edges
(72)** — the geometric foundation every later rule (placement, production,
roads) builds on. Pure data + pure functions, zero runtime deps.

## Files

- `packages/core/src/board.ts` (NEW — model + adjacency functions)
- `packages/core/src/board.test.ts` (NEW)
- `packages/core/src/index.ts` (re-export, additive)
- Do not touch `reduce.ts` / `validate.ts` / `rng.ts` / existing tests.

## Map slice

- Core conventions: plain objects/arrays only (no classes/Map/Set), strict TS
  (`noUncheckedIndexedAccess`), ESLint determinism guard (no Math.random/Date).
- Existing types in `packages/core/src/types.ts` (GameState etc.) — this story
  does NOT wire the board into GameState yet (S1.1.2/S1.1.3 do); board types
  live in `board.ts` and are exported standalone.

## Spec

- **Coords:** axial `{q, r}` for tiles; radius-2 hexagon (19 tiles) enumerated
  in a fixed deterministic order (same spiral/ring order every call).
- **Canonical IDs (string keys, stable):**
  - `tileId = "q,r"`;
  - `vertexId` = the 3 adjacent tile coords, sorted lexicographically, joined
    (off-board neighbor coords included — a vertex on the coast still has 3
    defining hex coords, some off-board);
  - `edgeId` = its 2 endpoint vertexIds, sorted, joined.
- **Model type** `BoardTopology` (computed, not stored in GameState):
  tiles with coords; vertex list; edge list; and adjacency lookups
  (tile→6 vertexIds, vertex→adjacent vertexIds (≤3), vertex→edgeIds,
  edge→2 vertexIds, vertex→adjacent tileIds).
- **Port slots:** define the 9 classic coastal port slots as fixed
  `{edgeId → portSlotIndex}` positions (evenly spaced around the coast; exact
  choice is the implementer's, but MUST be deterministic and documented in a
  comment). Port *contents* (which is 3:1 vs 2:1-resource) are assigned in
  S1.1.2, not here.
- A single exported `buildTopology()` (memoizable by caller) returns the whole
  structure; all functions pure.

## Acceptance criteria

- [ ] Radius-2 topology yields exactly **19 tiles, 54 vertices, 72 edges**
      (asserted in tests).
- [ ] Adjacency is symmetric and consistent (property tests: every edge's two
      vertices list that edge; every tile's 6 vertices list that tile; interior
      vertex has 3 edges, coastal 2–3).
- [ ] IDs are canonical: recomputing topology twice gives deep-equal results;
      vertex/edge IDs are order-independent of construction.
- [ ] Zero runtime deps (guard passes); no classes/Map/Set in exported data.
- [ ] `pnpm --filter @skervik/core test` green (existing 36 tests untouched);
      `pnpm -r typecheck && lint && build` green.
