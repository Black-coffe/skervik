# S1.4.1 — Colyseus GameRoom: authoritative state shell + seed + join/snapshot

## Goal

Stand up the **authoritative game room**: a Colyseus `Room` subclass that holds the
complete deterministic `@skervik/core` `GameState` in plain room memory, generates a
private crypto seed at creation, publishes only `seedHash` to clients, exposes a
**minimal public projection** as its `@colyseus/schema`, and handles player
join/leave/seat assignment with a one-shot `state.snapshot` to joiners. This is the
room SHELL only — it wires no gameplay yet.

**Scope fence (read first):** this story does NOT implement the intent→validate→
broadcast pipeline (that is **S1.4.2**), the seed-reveal at game end (**S1.4.3**), or
event-log persistence / any change to core's log format or goldens (**S1.4.4**). Touch
NOTHING in `packages/core`. If you find you need core changes to stand up the room,
STOP and report — you don't (the room imports core's existing public API and initial
state only). See ADR-0009 "Ratification note": the event-log-format and reveal-location
decisions are HELD pending owner sign-off, so this story must not depend on them.

## Architecture (from ADR-0009 — do not relitigate)

- **Fork 1 (state-sync):** the room holds the authoritative **plain `GameState`** (not
  a Schema) + the secret seed in room memory. The `@colyseus/schema` mirrors **only**
  the lobby/late-join public projection — `seedHash`, `phase`, `currentPlayerId`, and
  the seat/player list (id, seat order, connection status). Gameplay does NOT flow
  through the Schema; it will flow as `event.batch` broadcasts in S1.4.2.
- **Fork 3 (seed, the already-locked part only):** generate a crypto seed at `onCreate`
  (Node `crypto`), hold it in a **private room-memory field** — never in `GameState`,
  never in the Schema, never broadcast, never logged. Publish `seedHash = sha256(seed)`
  into `GameState.seedHash` at match start. **Do NOT implement the reveal** (S1.4.3).
- **Fork 4 (deps):** add `colyseus` + `@colyseus/schema` to `@skervik/server` (pin the
  current stable major; resolve exact versions with `pnpm add` and record them here).
  **Do NOT add Fastify** (deferred). `@skervik/protocol` gains the WS envelope as a
  **type-only** definition (no runtime dep, no zod — that's S1.5.1).

## Spec

- **Room creation (`onCreate`):**
  - generate a cryptographically-random seed (Node `crypto.randomBytes` → the `Seed`
    shape core expects; check `rng.ts`/`index.ts` for the `Seed` type/how a seed is
    represented — match it exactly). Store as a **private** field (e.g. `#seed` or a
    non-enumerable instance field), never on state/schema.
  - build the initial `GameState` (lobby/setup phase, no players yet or seated as they
    join — follow whatever core's init path dictates) and set `seedHash` = SHA-256 of the
    seed (Node `crypto.createHash('sha256')`).
  - initialize the Schema projection from that state.
- **Join (`onJoin`):** assign the next seat (deterministic seat order); add the player to
  the public projection (id, seat, connected); **send that client one `state.snapshot`
  message** carrying the full **public** `GameState` (seed-free by construction — assert
  in a test that no seed field is present). Reject joins beyond the max seat count
  (Classic 3–4 for M1; make it a room option with a sane default).
- **Leave (`onLeave`):** mark the seat disconnected in the projection (no removal, no
  bot-fill, no grace timer — M2 owns reconnect). Keep the authoritative `GameState`
  intact.
- **Dispose (`onDispose`):** release resources; no persistence here (S1.4.4).
- **Colyseus spike (Fork 4 risk — retire it in THIS story):** confirm the chosen Colyseus
  major **boots clean under Node 22 + ESM + tsup** — the room instantiates, a client can
  join, `pnpm --filter @skervik/server build` and `test` are green. If Colyseus fights
  ESM/Node 22 or its Schema model can't express the minimal projection cleanly, STOP and
  report to the Queen (this reopens Fork 1/4 per ADR "Revisit when") — do not force a
  workaround.
