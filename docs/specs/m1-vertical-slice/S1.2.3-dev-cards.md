# S1.2.3 — Development cards: deck, buy, play

## Goal

A seed-shuffled development-card deck, buying a card (Classic cost), and playing
the non-robber card types. The **knight** card's effect (move robber + steal)
is a robber action — it is DEFERRED to S1.3.1, which owns robber relocation for
both the 7-roll and the knight; this story defines the knight in the deck and
makes it buyable, but wires its *play* in S1.3.1 (documented dependency).

## Files

- `packages/core/src/types.ts` — additive: `buyDevCard` + `playDevCard(kind, …)`
  intents; deck state (counts, not identities exposed to other players); events
  for buy/play; per-player dev-card holdings + "bought this turn" marker +
  "dev card played this turn" marker + knight-count (for largest army in S1.3.4).
- `packages/core/src/validate.ts` — buy (affordability, deck non-empty, one draw)
  and play branches (one dev-card play per turn; a card bought this turn is
  unplayable this turn except VP counting toward win).
- `packages/core/src/reduce.ts` — apply buy (draw top, debit) and play effects.
- `packages/core/src/devcards.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).
- `docs/wiki/rng-stream-map.md` — record the deck-shuffle draw range.

## Map slice

- S1.2.1 gameplay RNG scheme (`eventIndex*K+slot`) + `rng.ts` `shuffle`.
- S1.2.2 resource pool / cost pattern (`ClassicProfile`).

## Spec

- **Deck (Classic, 25 cards):** 14 knight, 2 road-building, 2 year-of-plenty,
  2 monopoly, 5 victory-point. Shuffled from the seed **at game start** — decide
  and DOCUMENT its stream range in `rng-stream-map.md` (either the reserved
  board-gen-style band alongside layout, or an `eventIndex*K` slot at the setup
  event; be explicit and disjoint from dice draws).
- **Buy:** cost = 1 fleece + 1 barley + 1 iron; deck must be non-empty; draw the
  top card; it is private to the buyer; marked "bought this turn" (unplayable
  same turn, except VP cards silently count toward victory).
- **Play (one per turn):**
  - road-building: place 2 roads free (reuse S1.2.2 road legality; may place
    fewer if no legal edge / supply exhausted).
  - year-of-plenty: take any 2 resources from the bank (respect bank supply).
  - monopoly: name a resource; all other players hand you their entire holding
    of it (explicit transfer amounts in the event).
  - victory-point: not "played" — hidden, counts toward the win threshold
    (surfaced only at victory per E1.3 S1.3.4).
  - **knight: DEFERRED to S1.3.1** — reject `playDevCard('knight')` here with a
    documented `TODO(S1.3.1)` reject reason, but DO count bought knights so
    S1.3.4 largest-army has the data. (Alternatively coordinate with S1.3.1;
    default is defer.)
- Reject reasons (extend): can't-afford, deck-empty, card-not-held,
  bought-this-turn, already-played-dev-card, wrong-phase, out-of-turn,
  knight-deferred.

## Implementation notes
<!-- appended by the worker -->

- **Deck-shuffle stream range:** new reserved band `DEV_DECK_STREAM.SHUFFLE =
  1_010_000` (`devcards.ts`), consuming `1_010_000..1_010_023` (25 items → 24
  Fisher-Yates draws). Disjoint from gameplay (`eventIndex*8+slot`,
  headroom-guarded below `1_000_000`) and from `BOARD_GEN_STREAM`'s worst-case
  ceiling (`1_007_316`) — documented in `docs/wiki/rng-stream-map.md` new §2.5.
  Unlike board generation (applied outside `validate` at match creation), the
  deck's order is recomputed fresh on every `buyDevCard` call via
  `shuffledDevDeck(seed)` and indexed by `deckSize - devDeckRemaining` — the
  order itself never lives on `GameState`, only the remaining count
  (`GameState.devDeckRemaining`), so a serialized state snapshot can't predict
  future draws (same discipline that keeps `seed` off `GameState`).
- **New types (`types.ts`):** `DevCardKind`, `DevCardHoldings` (`held` +
  `boughtThisTurn`, both per-kind counts); `GameState.devDeckRemaining?`,
  `GameState.devCards?: Record<PlayerId, DevCardHoldings>`,
  `GameState.devCardPlayedThisTurn?`; intents `BuyDevCardIntent`,
  `PlayDevCardIntent` (union of `PlayKnightIntent` / `PlayRoadBuildingIntent`
  / `PlayYearOfPlentyIntent` / `PlayMonopolyIntent`, discriminated on `card`);
  events `DevCardBoughtEvent`, `RoadBuildingPlayedEvent`,
  `YearOfPlentyPlayedEvent`, `MonopolyPlayedEvent`; new `RejectReason`s
  `DECK_EMPTY`, `CARD_NOT_HELD`, `BOUGHT_THIS_TURN`, `DEV_CARD_ALREADY_PLAYED`,
  `KNIGHT_DEFERRED`, `BANK_EXHAUSTED`.
- **Privacy / public projection:** `devCards[playerId].held` is a per-KIND
  count (not a list of card identities) — a future per-viewer redaction layer
  (server package, not built yet) can trivially collapse another player's
  entry to a single total. Added `devcards.ts`'s `publicDevCardCount(holdings)`
  as that exact projection function (sums `held` values), tested directly.
  `GameState.devCards` itself still carries the full authoritative breakdown
  for every player (same shared-state shape `PlayerState.resources` already
  uses today) — actual per-client filtering is a server-layer concern that
  doesn't exist in this codebase yet for resources either.
- **Knight deferral:** `intent.playDevCard` with `card: 'knight'` is rejected
  unconditionally with `KNIGHT_DEFERRED` (checked first, before any
  held/turn-marker checks) — `TODO(S1.3.1)` comment points at the real robber
  action. Held knight count is still tracked normally via `devCard.bought` →
  `devCards[playerId].held.knight` increments on every knight draw, ready for
  S1.3.1 (play) / S1.3.4 (largest army) to consume; nothing increments a
  "played" counter in this story since knight can never be played yet.
- **Per-turn markers:** `devCardPlayedThisTurn` set `true` by any of the 3
  played-event `reduce` branches; `held - boughtThisTurn` fungible-count
  check (not per-instance tracking) gates "bought this turn is unplayable".
  Added a **minimal** reset in `reduce.ts`'s existing `turn.ended` case:
  drops `devCardPlayedThisTurn` (destructure-omit, matching the
  `pendingRoadVertexId` convention) and clears every player's
  `boughtThisTurn` to `{}` (their `held` counts are untouched) — flagged in a
  comment for S1.2.4 to formalize the full per-turn-marker architecture.
- **Road-building card:** reuses `touchesOwnNetwork` (S1.2.2) incrementally —
  each requested edge is legality-checked against a running `workingRoads`
  copy so the 2nd road can chain off the 1st just-placed one in the same
  play. Malformed edge ids reject the whole play (`MALFORMED_INTENT`);
  occupied/detached/supply-exhausted edges are silently skipped ("place
  fewer", per spec) rather than rejecting.
- **No re-goldening:** no existing fixtures/goldens changed — all additions
  are additive unions; `types.test.ts`'s exhaustiveness switches (pre-existing
  pattern from S1.2.2) were extended with the 4 new event variants + the new
  intent variants (nested switch on `card`) and the 6 new `RejectReason`
  strings — required for `never`-exhaustiveness to typecheck, not a scope
  creep (same file every prior story that added event/intent variants touched).
- **Verification:** `pnpm --filter @skervik/core test` → 121 tests, 11 files,
  all green. `pnpm -r typecheck && lint && build` → all green across all 5
  workspace packages.
