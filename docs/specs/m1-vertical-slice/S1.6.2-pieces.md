# S1.6.2 — Pieces: settlements, cities, roads, ports (vertex/edge layer)

## Goal

Render the **vertex/edge layer** of the board from `GameState` + board topology, on top
of the S1.6.1 tile layer: **placed settlements & cities** (on vertices), **roads** (on
edges), and the **9 ports** (on coastal edges). This story owns ALL vertex/edge→pixel
geometry (the tile layer was tile-centered; this is corner/edge-centered) and the
flotilla-colored piece visuals. Pieces are game-critical information, so they render in
the **crisp layer above the ambient mist** (consistent with S1.6.1a's token layering).

## Core contract (render from these — verified from the S1.6.1 scout)

- **Topology** (already used in S1.6.1): `buildTopology()` — cached; gives `vertices`
  (`VertexTopology`), `edges` (`EdgeTopology`), `portSlots` (`PortSlot { edgeId, index }`).
- **Vertices:** `VertexId = "q,r|q,r|q,r"` — the 3 defining hex tile-coords, sorted,
  `|`-joined (a coastal vertex still lists 3, some off-board). `EdgeTopology.vertexIds =
  [VertexId, VertexId]` gives an edge's 2 endpoints.
- **Buildings:** `GameState.buildings?` (optional — render nothing if absent):
  - `settlements: Record<VertexId, PlayerId>` — a settlement's owner.
  - `cities?: Record<VertexId, PlayerId>` — a city's owner (a city vertex is REMOVED from
    `settlements` and lives here; render it as a city, not a settlement).
  - `roads: Record<EdgeId, PlayerId>` — a road's owner.
- **Ports:** for each `topology.portSlots[i]` (has `edgeId`), pair with
  `GameState.board?.portContents[i]`: `{ kind: 'generic'; rate: 3 }` OR
  `{ kind: 'resource'; rate: 2; resource: ResourceType }`. The port sits on that coastal
  `edgeId` (a real edge; both its endpoint vertices are on the board).
- **Player → flotilla color:** NO mapping in core. Use the existing
  `theme/flotillaColors.ts` (from S1.6.1) — map each `PlayerId`/seat to a flotilla
  color + emblem id. If that module doesn't already expose a `PlayerId → flotilla`
  resolver keyed off `GameState.players`/`playerOrder` seat order, add one (seat index →
  flotilla, stable, deterministic).
- **No pixel math in core** — this story owns vertex/edge→pixel (below).

## Key geometry (the crux — implement in the existing pure `board/hexGeometry.ts`)

Extend the pure, Pixi-free `board/hexGeometry.ts` (keep it unit-testable headless):

1. `parseVertexId(id: VertexId): [AxialCoord, AxialCoord, AxialCoord]` — split on `|`,
   parse each `"q,r"`.
2. `vertexToPixel(id: VertexId): Point` — **the average of `axialToPixel` of the vertex's
   3 defining tile-coords.** This is exact, not an approximation: three mutually-adjacent
   flat-top hex centers form an equilateral triangle whose centroid is equidistant (=
   circumradius) from each center — i.e. exactly the shared corner. The `Y_SCALE`
   y-flatten is linear, so it commutes with the average (centroid of flattened points =
   flatten of centroid). Works for coastal vertices too (average all 3 listed coords,
   including off-board ones — they still define the corner). Verify against the fact that
   every vertex pixel is at distance `HEX_SIZE` (pre-flatten) from each of its on-board
   tile centers.
3. `edgeToPixel(id: EdgeId, topology): { a: Point; b: Point; mid: Point; angle: number }`
   — endpoints = `vertexToPixel` of the edge's 2 `vertexIds` (look up via
   `findEdge(topology, id)`); `mid` = their midpoint; `angle` for orienting a road
   segment / a port marker.

Add focused unit tests: all 54 vertices → distinct pixels; a known interior vertex's
pixel equals the expected shared corner; edge midpoint = mean of its endpoints; a road's
endpoints match its edge's two vertex pixels.

## Piece visuals (DESIGN.md-binding)

- **Flotilla color + a NON-COLOR cue is mandatory** (DESIGN.md §2.2 a11y invariant:
  "color NEVER without the flotilla emblem glyph"). Every piece must carry a per-flotilla
  shape/emblem cue so the 4 flotillas are distinguishable without color (deutan/protan).
  Minimum: a distinct simple flag/marker silhouette per flotilla (4 clearly-different
  shapes) drawn on/with the piece. Full engraved emblem art (§5) can come later, but a
  color-only piece does NOT merge.
- **Settlement vs city vs road are distinguishable by SHAPE, not just size:** settlement =
  one silhouette (e.g. a small anchorage hut/tent), city = a clearly different, larger
  silhouette (harbor/tower), road = a thick segment along the edge. Reuse §2 tokens
  (`--line` for outlines, elevation via background step per §4 — no drop shadows on
  pieces; the one allowed shadow is for floating DOM layers, not canvas pieces).
- **Roads** render as a flotilla-colored segment centered on the edge, oriented by
  `edgeToPixel(...).angle`, inset so it reads as sitting on the edge between two vertices.
- **Ports:** at each coastal port edge, a small dock/marker showing the **rate** as
  locale-independent digits (`"3:1"` generic, `"2:1"` resource) AND, for a 2:1 resource
  port, the resource identity via its **existing §2.3 color + stroke pattern** (reuse the
  S1.6.1 resource color/pattern helpers — do NOT invent new resource icon art this
  story). Optionally a short "dock line" from the port marker toward its edge's 2
  vertices. Ports are neutral (no flotilla color).
- **Layering:** pieces + ports render in the crisp layer **above the ambient mist**
  (same discipline as S1.6.1a's tokens/robber). Built once from state; no per-frame
  re-render. (Robber stays as rendered in S1.6.1 — do not duplicate it.)
- **Determinism/purity:** the geometry module stays pure (no `Math.random`/`Date`/DOM);
  same `GameState` → identical piece positions.
