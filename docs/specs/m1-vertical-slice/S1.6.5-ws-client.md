# S1.6.5 — WebSocket client: connect · fold · send (the live wire)

## Goal

Wire the client to the authoritative Colyseus room so a real `GameState` flows in and player
intents flow out. This turns the S1.6.1–S1.6.4 static-fixture UI into a **live client**:
join the room → seed the store from `state.snapshot` → fold every `event.batch` through core
`reduce` (ADR-0009 Fork 1, the isomorphic-core promise) → **replace S1.6.4's `dispatchIntent`
stub** with a real `room.send('intent', …)` → surface rejections + connection state. This is
the last E1.6 client story before E1.7 closes the M1 gate with a scripted end-to-end match.

## The seam this fills (why S1.6.5 comes after S1.6.4)

S1.6.4 built the whole Trade-UI interaction against a **`store.dispatchIntent(intent)` stub**
(no network) and a local `pendingSeal` marker. S1.6.5 **replaces only the stub's body** with
the real WS send and reconciles `pendingSeal` on the server's echo — the component layer
S1.6.4 shipped must NOT change. If filling this seam forces a change to any Trade-UI component
(not just the store action + net layer), STOP and report — the S1.6.4 seam was mis-shaped and
that's a finding, not a silent fix.

## The transport contract (verified 2026-07-05 against server/protocol — code to THIS)

Server room: `packages/server/src/room/GameRoom.ts`; matchmaking name
`GAME_ROOM_NAME = 'skervik_game'` (currently exported from `@skervik/server`; this story
hoists it to `@skervik/protocol` — see Files). Protocol envelopes: `@skervik/protocol`
`messages.ts`. All messages are `{ v: 1, type, payload }`.

- **Join:** connect via `colyseus.js` `Client` → `joinOrCreate(GAME_ROOM_NAME, { protocolVersion: PROTOCOL_VERSION })`.
  The join options MUST carry `protocolVersion` (S1.5.2's `onAuth` rejects a join without it).
- **Identity:** after a successful join, `myPlayerId = room.sessionId` — the server seats each
  client under its `sessionId` as the `PlayerId` (`onJoin`: `playerId: client.sessionId`).
  This REPLACES the S1.6.3 dev-constant `myPlayerId` in the store.
- **Initial state:** the server sends `state.snapshot` (`{ type:'state.snapshot', payload: GameState }`)
  to the joining client immediately in `onJoin`. Seed `store.gameState` from `payload` (it's
  the FULL public `GameState` — `PublicGameState = GameState`, seed is never in it).
- **Live updates:** the server broadcasts `event.batch` (`{ type:'event.batch', payload: GameEvent[] }`)
  after every validated intent. **Fold each batch into `store.gameState` via core `reduce`**
  (`payload.reduce((s, e) => reduce(s, e), gameState)`) — do NOT expect the server to send full
  state; the client rebuilds it exactly like the server did (Fork 1). Use `GameState.eventIndex`
  to stay ordered/idempotent (drop a batch whose first event's index ≤ the last applied — a
  cheap guard against a snapshot/batch race at join; document the assumption).
- **Send an intent:** `room.send('intent', { v: 1, type: 'intent', payload: <PlayerIntent> })`
  (matches the room's `onMessage('intent', …)` + `ClientMessageSchema`). **The intent DOES
  carry `playerId`** (core `BaseIntent` requires it — verified in `types.ts`, and S1.6.4
  already composes intents with `playerId: myPlayerId`). Set `payload.playerId = myPlayerId`
  (= `room.sessionId` once joined). This is NOT spoofable: the server passes the SEAT id
  (`sessionId`) to `validate`, and `validate` rejects any intent whose `playerId` ≠ the seat
  (`validate.ts`: `intent.playerId !== playerId → MALFORMED_INTENT`). So the client sends its
  own id and the server double-binds it to the seat — matching means the S1.6.4 seam (which
  set `playerId = myPlayerId`) works unchanged once `myPlayerId` becomes the real `sessionId`.
- **Private rejections (sender only):**
  - `intent.rejected` → `{ payload: { reason: RejectReason } }` — a `validate` refusal (turn/
    affordability/phase/trade…). Surface it to the UI and reconcile pending state.
  - `intent.error` → `{ payload: { code: 'INTERNAL_ERROR' } }` — infra failure, state NOT
    advanced. Surface a generic "try again".
- **Version rejection at join:** an incompatible `protocolVersion` makes `joinOrCreate` REJECT
  with a Colyseus error whose `.message` is the JSON of an `error.version` message
  (`{ type:'error.version', payload:{ code:'PROTOCOL_VERSION_MISMATCH', serverVersion, clientVersion } }`).
  Catch the join rejection, `JSON.parse` the message, validate it under `ServerMessageSchema`,
  and drive an "update required" UI state. A parse failure / non-version error → a generic
  "can't connect" state (don't crash).

## Scope — build THIS, defer the rest

**Build:**
- **Net layer** (`packages/client/src/net/`, NEW): a `wsClient.ts` wrapping `colyseus.js` —
  `connect(url, { onSnapshot, onBatch, onReject, onError, onConnectionChange })` returning a
  handle with `sendIntent(intent: PlayerIntent)` and `disconnect()`. It owns the `colyseus.js`
  `Client`/`Room`, registers the message listeners above, maps them to typed callbacks, and
  translates join/leave/error/reconnect events into a small `ConnectionStatus` union
  (`connecting | connected | reconnecting | disconnected | version-mismatch | error`). Keep it
  framework-free (no React/zustand import here) so it's unit-testable against a mock room.
- **Store wiring** (`hud/store.ts`): 
  - `myPlayerId` becomes settable (from `room.sessionId` on join) — no longer a hardcoded dev
    constant; keep a dev fallback for the no-connection dev view.
  - **Replace `dispatchIntent`'s stub body** to call the net layer's `sendIntent` + keep the
    `pendingSeal` optimistic-preview behavior (§7.6: preview, never confirm).
  - New actions: `applySnapshot(state)` (set `gameState` + `myPlayerId`), `applyEventBatch(events)`
    (fold via `reduce`, ordered by `eventIndex`), `setConnectionStatus(status)`,
    `applyReject(reason)` / `applyIntentError()` — the last two **reconcile `pendingSeal`**
    (a rejected/failed trade clears the pending seal and records a trace entry) and push a
    localized, dismissable notice.
  - `pendingSeal` is CLEARED when the server's echo of the corresponding trade event lands in a
    folded batch (server truth) OR on `intent.rejected`/`intent.error` (the deal didn't seal).
- **Connection UI:** replace the S1.6.3 rail "online" stub + top-bar/rail connection affordance
  with the real `ConnectionStatus` (localized; color + ICON/text, never color-only). A
  `version-mismatch` status shows the "update required" message (localized, using the
  `serverVersion`/`clientVersion` from the `error.version` payload). A `reconnecting` state is
  visible and non-alarming.
- **Rejection surfacing:** a localized, `aria-live="polite"` notice for `intent.rejected`
  (map the common trade/turn `RejectReason`s to `reject.*` keys; a generic
  `reject.generic` fallback carrying the machine code is acceptable for the long tail — do NOT
  author all ~30 reasons if that's disproportionate; cover the trade + turn ones the player
  will actually hit and note the rest as follow-up).
- **Config:** WS URL from a Vite env var (e.g. `import.meta.env.VITE_WS_URL`) with a sane
  `ws://localhost:2567` dev default; documented. No secrets.
- **i18n:** every new string a typed `t()` key in ru/uk/en (connection statuses, update-required,
  the reject notices). Missing key = build fail (S1.6.6a gate).
- **Tests:** unit-test the net layer + store wiring against a **mock/fake `colyseus.js` room**
  (no real server): join → `state.snapshot` seeds store + sets `myPlayerId`; `event.batch`
  folds correctly (assert a real 2-event batch advances state exactly like server-side reduce);
  `dispatchIntent` → `room.send('intent', envelope)` with the right shape; `intent.rejected` →
  `pendingSeal` cleared + notice; a version-mismatch join rejection → `version-mismatch` status
  with parsed `error.version`; connection-status transitions.

**DEFER — do NOT build here:**
- **Runnable server boot (`listen()`) + real cross-process E2E** — E1.7 (`createGameServer`
  intentionally has no `listen()`; the full 3–4-client scripted match + `/verify` endpoint is
  S1.7.1–S1.7.3). S1.6.5 is verified against a **mock transport**; note that live wiring is
  proven in E1.7.
- **Match-start orchestration** (lobby→setup trigger, `match.started`/`board.generated`
  emission) — no `startMatch` seam exists yet; that's E1.7 (rooms/lobby). The client renders
  whatever `GameState` the snapshot/batches give it (a `lobby` snapshot → pre-match view; the
  board appears when the start events arrive). Do NOT invent a client-side match start.
- **Reconnect grace / bot-fill / karmic-ban-free rejoin** — M2 (`onLeave` is a no-op stub
  server-side by design). S1.6.5 shows a `reconnecting` status and may let `colyseus.js`
  attempt its default reconnect, but no grace/seat-reclaim logic.
- **Server-enforced turn timers** — M2 (no server timer authority in M1). The S1.6.3
  `TimerDisplay` stays idle/cosmetic; a purely local turn-change countdown is OPTIONAL and must
  not pretend to be authoritative. Prefer to leave it idle and note the deferral.
- **Guest auth / accounts / room codes** — S1.7.1 (Fastify). S1.6.5 uses `joinOrCreate` with no
  identity beyond the Colyseus `sessionId`.
- **Board-click → build/other non-trade intents' UI** — the `sendIntent` path is generic (any
  `PlayerIntent`), but wiring board interactions is not required here; trade is the exercised
  path (it already has UI from S1.6.4). Note that `sendIntent` is intent-agnostic for later.

## Carried-over nits from the S1.6.4 lead-review (fold in HERE — natural home)

## Key decisions (surface any deviation)

1. **Isomorphic fold, not state mirroring** (ADR-0009 Fork 1): the client rebuilds `GameState`
   by folding broadcast events through its own bundled core `reduce`, seeded by the snapshot —
   never a parallel hand-maintained state. Order by `eventIndex`; guard the snapshot/batch race.
2. **Server is truth** (§7.6): `dispatchIntent` previews (`pendingSeal`) but the deal is sealed
   only when the server's `trade.executed`/`trade.offered` echo folds in; `intent.rejected`
   clears the pending seal. No optimistic authoritative mutation.
3. **Net layer is framework-free** so it unit-tests against a mock room without React/DOM.
4. **`myPlayerId` from `sessionId`** — the store stops hardcoding it; the dev fixture view keeps
   a fallback so `pnpm dev` renders without a server.
5. **Mock-transport verification** — real cross-process play is E1.7; S1.6.5 proves the client
   contract against a faithful mock (same envelope shapes), so E1.7 only wires the boot.
