# S1.2.4 — Turn FSM: phases, turn order, phase guards

## Goal

Formalize the per-turn state machine that ties S1.2.1–S1.2.3 together:
`roll → produce → main (trade+build interleaved) → end`, with clockwise turn
order and phase guards enforced in `validate`. Consolidates the ad-hoc phase
transitions the earlier stories added into one coherent, guard-checked FSM.

## Files

- `packages/core/src/types.ts` — additive/consolidating: an explicit `phase`
  enum/union on `GameState` (if the earlier stories left it implicit),
  `currentPlayer` / turn-order fields, an `endTurn` intent + `turn.ended` event.
- `packages/core/src/validate.ts` — a single phase-guard layer: every existing
  intent (roll, build, buy/play dev card, and the E1.3 trade/robber intents once
  they exist) is gated by the phase it's legal in. Do NOT rewrite the rule bodies
  the earlier stories shipped — wrap them with consistent guards.
- `packages/core/src/reduce.ts` — apply `turn.ended` (advance to next player's
  roll phase, reset per-turn markers: dev-card-played, bought-this-turn, etc.).
- `packages/core/src/turn.test.ts` (NEW) + fixtures.
- `packages/core/src/index.ts` (re-export).

## Map slice

- S1.1.3 setup→"first player's roll phase" transition (the FSM starts there).
- S1.2.1 roll→produce→main transition; S1.2.2 build (main); S1.2.3 dev cards
  (buy in main; one play per turn) — this story unifies their phase handling.
- Plan §3 E1.2 "Turn FSM: roll → (resolve 7) → main → end; phase guards in
  validate"; §1 invariants (profile-as-config, determinism).

## Spec

- **Phases:** `roll` → `produce` (automatic, emitted by the roll per S1.2.1) →
  `main` → `end`. The 7-resolution sub-phase (discard/move-robber) is E1.3
  (S1.3.1) — leave a documented seam (a `robber` phase slot) the FSM can enter,
  but don't implement 7 here.
- **Guards (in `validate`):** cannot build/trade/buy/play before rolling;
  cannot roll twice in a turn; `endTurn` only from `main`; only the
  `currentPlayer` may act (except responses to trades, E1.3). Reset per-turn
  markers on `turn.ended`.
- **Turn order:** fixed clockwise seat order; after the last player, wrap to the
  first. Store order in state; `endTurn` advances `currentPlayer`.
  - **Deferred nit from S1.1.3 review:** the setup FSM derives `nextPlayerId`
    from the road count trusting the `currentPlayerId` gate, an *implicit*
    seating-order coupling (genesis seeds `currentPlayerId = players[0]`). Make
    the turn order EXPLICIT here — a canonical seat array in state — and have
    both setup-exit and the main loop advance against it, so the coupling is
    stated once, not re-derived per story.
- **One dev-card play per turn** guard consolidated here (S1.2.3 set the marker;
  this story owns the reset on `turn.ended`).
- Reject reasons (extend/consolidate): not-your-turn, wrong-phase,
  already-rolled, must-roll-first.

## Acceptance criteria

- **`GamePhase` union** (`types.ts`): `'lobby' | 'setup' | 'roll' | 'main' | 'robber' | 'finished'`.
  `roll` is real (only `intent.rollDice` legal there); `robber` is a
  **documented seam only** — no code path enters it, S1.3.1 owns wiring a
  rolled 7 (or a knight) into it. Deliberately did NOT add a persisted
  `'produce'` or `'end'` state: production is a zero-duration pass-through
  (`dice.rolled`'s own `reduce` case lands phase on `main` directly, whether
  or not a paired `resources.produced` follows) and `endTurn` is likewise
  momentary (the ACT of ending, not a state a turn sits in) — this mirrors
  how `match.started` already hardcodes `phase: 'setup'` in `reduce.ts`
  rather than carrying it as an event field, so I followed that same
  precedent instead of adding a `nextPhase` field to `TurnEndedEvent`.
- **Guard map** (`validate.ts`, one phase-guard block before the intent
  switch): `intent.placeSettlement`/`intent.placeRoad` → `setup`
  (unchanged, `INVALID_PHASE` otherwise); `intent.rollDice` → `roll`
  (`ALREADY_ROLLED` if phase is `main`, `INVALID_PHASE` for anything else);
  every other intent (`endTurn`, `buildRoad`, `buildSettlement`, `buildCity`,
  `buyDevCard`, `playDevCard`) → `main` (`MUST_ROLL_FIRST` if phase is
  `roll`, `INVALID_PHASE` for anything else). `NOT_YOUR_TURN` still checked
  right after the phase guard, unchanged order/behavior.
- **Explicit `playerOrder`** (`types.ts`, `GameState.playerOrder?:
  ReadonlyArray<PlayerId>`): set once by `match.started` from
  `event.playerIds` (`reduce.ts`), OPTIONAL (not required) — follows the
  same "absent = fact hasn't landed" convention as `board`/`buildings`
  rather than forcing every hand-built test `GameState` literal across the
  suite to add it. A new `seatOrder(state)` helper in `validate.ts` reads
  `state.playerOrder ?? state.players.map(p => p.id)` (defensive fallback,
  documented as NOT a second source of truth) and is now the ONE place both
  `intent.placeRoad`'s setup-exit rotation (via `snakeOrder(seatOrder(state))`,
  replacing `snakeOrder(state.players.map(...))`) and `intent.endTurn`'s
  main-loop rotation (replacing `players.findIndex`/`% players.length`) read
  from — removes the two separate implicit `players`-array-order
  derivations S1.1.3's review flagged. A dedicated `turn.test.ts` test
  proves the decoupling by shuffling `players` relative to `playerOrder` and
  asserting rotation follows the latter.
- **Consolidated per-turn reset** (`reduce.ts`'s `turn.ended` case): on top
  of S1.2.3's existing `devCardPlayedThisTurn` drop + per-player
  `boughtThisTurn` reset, now also sets `phase: 'roll'` (the FSM's own way of
  encoding "hasn't rolled yet" — no separate boolean flag needed) and drops
  `pendingRoadVertexId` defensively (should never be set post-setup, but a
  turn should never persist a dangling one regardless).
- **Setup-exit** (`validate.ts`'s `intent.placeRoad`, last draft turn):
  `nextPhase` changed from `'main'` to `'roll'` — the first player now lands
  on the turn loop's mandatory first step, not directly in `main`.
- **Re-goldened fixtures/assertions** (all consciously, reasons above):
  - `setup.test.ts`: the draft's last `road.placed` event's `nextPhase` and
    the final `state.phase` assertions changed `'main'` → `'roll'` (setup-exit

  - `production.test.ts`: `makeState()`'s default `phase` changed `'main'` →
    `'roll'` (rollDice now requires `roll`, not `main`) — every test in the
    file uses this fixture for a successful roll, so this one line fixes
    them all; updated 2 stale comments (one about the "S1.2.4 will add a roll
    phase" TODO, one test title) to reflect the now-real phase. No production
    math/legality assertions changed.
  - `reduce.test.ts`: added a `rollState` fixture (`{...mainState, phase:
    'roll'}`) and switched the `'validates intent.rollDice...'` test to use
    it (was incorrectly using `mainState`, which is now post-roll); added
    3 new assertions to existing tests (not new tests) — `match.started`'s

  - `__fixtures__/golden.state.json`: `"phase"` changed `"setup"` → `"roll"`

    each `TURN_ENDED` now lands the next player on `'roll'` — final phase is

  - `devcards.test.ts`: no phase changes needed (its `makeGenesis()` already
