# S1.2.1 — Resource production on roll (+ the gameplay RNG stream scheme)

## Goal

Rolling the dice on a player's turn produces resources: for the rolled total,
every tile carrying that number token pays its adjacent settlements (1) and
cities (2), unless the robber sits on the tile. This story also **fixes the
gameplay RNG stream scheme** (`streamIndex = eventIndex * K + slot`) that every
future random draw (dev-deck shuffle, robber steal) will obey — the counterpart
to the reserved board-gen band from S1.1.2.

## Files

- `packages/core/src/types.ts` — additive: a `rollDice` intent, a `dice.rolled`
  event (carries both die faces + the total), a `resources.produced` event
  (explicit per-player resource grants), phase field(s) if not already present
  from S1.1.3's FSM, bank/resource-pool state if absent.
- `packages/core/src/validate.ts` — `rollDice` branch: only the current player,
  only in the roll phase; draw the two dice from the seed; compute production;
  emit `dice.rolled` + `resources.produced`.
- `packages/core/src/reduce.ts` — apply both events (advance phase, credit
  players, debit bank).
- `packages/core/src/rng.ts` — **only if** a helper is needed to express
  `eventIndex * K + slot` cleanly; keep existing `deriveValue`/`shuffle` intact.
- `packages/core/src/production.test.ts` (NEW) + fixture / golden updates.
- `packages/core/src/index.ts` (re-export).
- `docs/wiki/rng-stream-map.md` — **extend** with the gameplay band scheme
  (this story owns that decision).

## Spec — gameplay RNG scheme (decide here, NEVER change)

- Gameplay draws live in the low band `[0, 1_000_000)`; board-gen owns
  `[1_000_000, …)` (S1.1.2). Scheme: **`streamIndex = state.eventIndex * K + slot`**
  with a fixed small `K` (pick `K = 8`) and a documented slot map per event type
  (slot 0 = die A, slot 1 = die B; slots 2–7 reserved for later same-event draws
  like the robber steal-pick in S1.3.1). Write the slot map into
  `docs/wiki/rng-stream-map.md`.
- **Headroom guard (deferred nit from S1.1.2 review):** with `K = 8` the
  gameplay band reaches `1_000_000` only at `eventIndex = 125_000` — far beyond
  any real match. Encode this as an explicit invariant: assert (or document with
  a cheap runtime check + comment) that `eventIndex * K + K <= 1_000_000`, so a
  gameplay draw can never collide with the board-gen band. Note it in the wiki.
- Each die is a `1..6` draw from `deriveValue(seed, streamIndex)`; record both
  faces in `dice.rolled` so replay recomputes nothing from the seed.

## Spec — production

- On roll total `T` (≠7; the 7 branch is S1.3.1 — for now reject or no-op 7 with
  a documented `TODO(S1.3.1)` reason, do NOT implement robber here):
  for every non-desert tile whose token == `T` and which the robber is NOT on,
  each adjacent settlement's owner gains 1 of that tile's resource, each adjacent
  city's owner gains 2.
- **Bank exhaustion (Classic):** if the bank cannot pay the full amount owed of
  a given resource to ALL entitled players, NOBODY receives that resource this
  roll (all-or-nothing per resource type). Compute against the finite bank pool.
- Payout amounts are **explicit** in `resources.produced` (replay must not
  recompute). Robber-on-tile tiles pay nothing.
- Phase: `roll` → after producing, advance to the `main` phase (build/trade land
  in S1.2.2+/E1.3); S1.2.4 formalizes the full FSM — keep the transition minimal
  but correct here.

## Implementation notes
<!-- appended by the worker -->

- **RNG scheme (fixed, S1.2.1):** `gameplayStreamIndex(eventIndex, slot) =
  eventIndex * K + slot`, `K = 8` (`GAMEPLAY_STREAM_SLOTS`, `rng.ts`). Slot
  map (owned by `validate.ts`, `GAMEPLAY_SLOT`): `0` = die A, `1` = die B,
  `2`-`7` reserved. `rng.ts` only knows `K`; `validate.ts` owns slot meaning
  (parallel to `boardgen.ts` owning `BOARD_GEN_STREAM`). Full table in
  `docs/wiki/rng-stream-map.md` §1.
- **Headroom guard:** `gameplayStreamIndex` throws if
  `eventIndex * K + K > 1_000_000` (i.e. `eventIndex > 124_999`) — a
  duplicated literal `1_000_000` in `rng.ts` (not imported from
  `boardgen.ts`, to avoid a `rng.ts -> boardgen.ts` import cycle since
  `boardgen.ts` already imports `shuffle` from `rng.ts`). Covered by a
  dedicated test in `production.test.ts`.
- **New types (additive):** `ResourcesProducedEvent` (`grants`,
  `bank` — both full facts, no recompute on replay) added to the
  `GameEvent` union. `GameState.bank?: Record<ResourceType, number>` added,
  optional/absent = "full Classic pool, untouched" (same pattern as
  `board`/`buildings`) — first debited resource seeds its own key.
- **Breaking change, consciously made (NOT purely additive):**
  `DiceRolledEvent.value: number` (a single 1-6 die — an M0-skeleton stub
  that never matched real 2d6 Catan) was replaced with `dieA`/`dieB`/`total`.
  This is the one deliberate exception to "add union members additively" —
  the field was structurally wrong for the real ruleset, not just missing a
  field, so extending it in place (not adding a parallel type) was the
  correct fix per plan §4 ("...or re-golden fixtures consciously"). Ripple,
  all updated: `replay.ts` (`DiceRolledLogData`: `result` -> `dieA/dieB/total`;
  `rngStreamIndex` reinterpreted as the *base* index `gameplayStreamIndex`
  derives both draws from), `replay.test.ts` (audit test rewritten for 2
  draws), `reduce.test.ts`/`types.test.ts` (literal event fixtures updated),
  `golden.events.ndjson` (2 DICE_ROLLED lines' `data` re-recorded with real
  dieA/dieB/total values recomputed for the new scheme, seed
  `skervik-golden-seed-3`). **`golden.state.json` did NOT change** — the
  golden log's genesis has no `board.generated` line, so production is
  inherently a no-op either way, and `replay.ts`'s wire-format mapper
  deliberately does NOT synthesize a `resources.produced` event from a
  `DICE_ROLLED` log line (see next point) — so the final replayed state is
  byte-identical to before.
- **Event-log (ndjson) scope seam, documented, not fixed here:** `replay.ts`
  (`tech spec §6.4` wire format) only maps `DICE_ROLLED` -> `dice.rolled`; it
  does not persist/replay `resources.produced` (no `RESOURCES_PRODUCED` log
  line type exists). `validate`/`reduce` (the actual in-memory engine
  contract this story is scoped to) are fully correct; wiring production
  into the persisted match log is follow-up scope (naturally lands with
  E1.4's log-persistence stories, S1.4.4) — flagged here so it isn't lost.
- **7-deferral:** roll always resolves (2 dice always drawn, `dice.rolled`
  always emitted); on `total === 7`, `resources.produced` is simply not
  emitted (documented `TODO(S1.3.1)` in `validate.ts`) — robber
  move/discard is entirely S1.3.1's job.
- **City seam:** `computeProduction` (`validate.ts`) only knows
  `BuildingsState.settlements` (pays 1); a `TODO(S1.2.2)` comment marks the
  exact line (`const amount = 1`) where a future city marker should branch
  to pay 2. Not testable yet (no city state exists) — noted in
  `production.test.ts`'s test titles instead of a stub city test.
- **Bank:** `CLASSIC_PRODUCTION_PROFILE = { bankPerResource: 19 }`
  (`validate.ts`, physical-Catan parity), all-or-nothing per resource type
  computed against `state.bank ?? implicit-full`.
- **Phase FSM:** kept minimal per spec — no new `GamePhase` value added;
  `rollDice` stays gated to the existing `'main'` phase (already the
  post-setup turn-loop phase from S1.1.3), so "advance to main after
  producing" is a no-op today. A dedicated pre-roll phase is S1.2.4's job.
