# S1.4.4b — Durable event-log writer + pipeline persist-ordering fix

## Goal

Make the match event log **durable**: implement the real `FsEventSink` (fulfilling the
`GameEventSink` seam S1.4.2 shipped) that appends each validated `GameEvent` as one
ndjson line to `matches/{id}/events.ndjson`, wire it as the room's production sink, and
prove the round-trip (`parseGameEventLog` → `replay` reconstructs the exact state).
**AND fix S1.4.2 NIT-1** — the pipeline currently commits state before persistence is
confirmed, which a durable writer would turn into a real log-divergence + node-crash
bug. This story closes E1.4.

**Scope:** server-only. Uses core's `parseGameEventLog` (merged in S1.4.4a) for the
read path — do NOT edit `packages/core`. Does NOT build the `/matches/{id}/verify` REST
endpoint or Fastify (S1.7.3). Builds on S1.4.2 (pipeline + seam) and S1.4.3 (reveal) —
dispatch only AFTER both merge (all three touch `GameRoom.ts`).

## 🔴 Precondition: fix S1.4.2 NIT-1 (state-before-persist) — do this FIRST

Current pipeline (from S1.4.2, `GameRoom.ts`): `this.gameState = <reduce-fold>` runs,
THEN `await eventSink.append(events)`, THEN broadcast. With the in-memory sink (sync,
never rejects) this is inert — but `FsEventSink` (this story) can reject transiently
(disk/FS error), and today the reduce-fold + `await append` sit OUTSIDE the try/catch
(which wraps only `validate`) on a voided floating-promise handler. So a sink rejection
would: (a) leave `gameState` advanced past an event that never hit the log → replay
divergence; (b) escape uncaught → Node unhandled-rejection → **whole-node crash (all
rooms)**.

**Fix (reviewer's direction — implement exactly):**
1. Compute the next state into a LOCAL (`const nextState = events.reduce(reduce,
   this.gameState)`) — do NOT assign `this.gameState` yet.
2. `await this.eventSink.append(events)` — persist FIRST.
3. ONLY on success: `this.gameState = nextState`, refresh the schema projection,
   broadcast `event.batch`, and (S1.4.3) fire the reveal on `game.ended`.
4. Wrap the reduce-fold + append (the whole async body) in try/catch → on error, send a
   PRIVATE error reply to the sender and DO NOT advance state / broadcast; nothing may
   escape the voided handler (no unhandled rejection). Log the failure with `seedHash`
   only, never the seed.
- Invariant after the fix: **no client ever sees (via broadcast) or acts upon an event
  that was not durably recorded first**, and a sink failure degrades gracefully (reject
  to sender, state untouched) instead of crashing the node.

## Also fold in (small S1.4.2 review nits)
- **NIT-2:** narrow the broad `catch` around `validate` so it maps ONLY the known
  "unknown intent type throws" case to `MALFORMED_INTENT`; a genuinely unexpected throw
  should surface (debug-log / rethrow-to-handled), not be silently reported to the client
  as a malformed intent. Keep it defensive (still no node crash) but not blanket-swallowing.
- **NIT-3:** add a server-level test: a client seated as A, on B's turn, sending a valid
  own-id intent → `NOT_YOUR_TURN` (turn-gate at the server boundary, completing the
  identity-binding coverage).
