# S2.1.2 — Balanced Deck randomness (activate `profile.randomness:'balanced_deck'`)

## Goal

Turn the LOCKED product intent — *"swingy dice RNG… explicitly designed out"* (CLAUDE.md) —
into the game's first alternative randomness source, and activate the `randomness` flag S2.1.1
planted (flag-only) on `BALANCED_PROFILE`. Under `randomness:'dice'` (Classic/Blitz) a roll is two
independent 2d6 draws (unchanged). Under `randomness:'balanced_deck'` (Balanced) a roll is a draw
**without replacement** from a deck of the **36 equiprobable 2d6 outcomes**; over each 36-roll cycle
every sum appears EXACTLY its natural count (7 six times, 2 and 12 once each, …), so the distribution
is identical to dice in expectation but its **variance is smoothed** — no cold streak of no-7s, no hot
streak of one number. When the 36 are exhausted the deck reshuffles (a fresh seed-derived permutation).

**The load-bearing design decision: the balanced deck is literally the 36 ordered `(dieA, dieB)`
outcome pairs** — `[1,1],[1,2],…,[6,6]` — drawn without replacement, NOT a synthesized sum. So each
drawn card yields a genuine `(dieA, dieB, total)`, the **`dice.rolled` event shape stays byte-identical**,
and every downstream consumer (`reduce`, production distribution, robber-on-7, the client's two-dice
render) needs **zero change** — only the *source* of the pair changes from independent rolls to a
without-replacement draw. Classic stays **byte-frozen** (its `rollDie` path is untouched).

## What to build

### 1. The balanced-deck draw primitive (core, `rng.ts` or new `balancedDeck.ts`)
- **`BALANCED_ROLL_DECK: readonly (readonly [number, number])[]`** — the 36 ordered pairs
  `(a,b)` for `a,b ∈ 1..6`. A `sumHistogram(BALANCED_ROLL_DECK)` must equal the 2d6 histogram
  (`{2:1,3:2,4:3,5:4,6:5,7:6,8:5,9:4,10:3,11:2,12:1}`) — assert this in a test (it is the fairness
  contract).
- **`shuffledRollDeck(seed: Seed, round: number): readonly (readonly [number,number])[]`** — a
  deterministic Fisher-Yates of the 36 pairs via the EXISTING `shuffle(items, seed, streamIndex)`
  helper (`rng.ts:113`), keyed to a NEW reserved stream band per reshuffle round so each cycle is a
  *different* permutation (else every 36-cycle repeats and becomes predictable). Add
  **`ROLL_DECK_STREAM.SHUFFLE_BASE`** (suggest `1_020_000`, stride e.g. `1000` per round) — CONFIRM it
  does not overlap `DEV_DECK_STREAM.SHUFFLE=1_010_000`, the board bands (`1_000_000`/`1_000_100`/
  `1_001_000+`), or the `gameplayStreamIndex` range; document it alongside the others.
- **`drawBalancedRoll(seed: Seed, drawCount: number): { dieA: number; dieB: number; total: number }`**
  — `round = Math.floor(drawCount / 36)`, `pos = drawCount % 36`, `[dieA,dieB] =
  shuffledRollDeck(seed, round)[pos]`, `total = dieA + dieB`. `drawCount` is the number of balanced
  rolls ALREADY drawn (0-based position of THIS draw). Pure, deterministic, no wall-clock/RNG.

### 2. State: a balanced-roll position counter (core, `types.ts` + `reduce.ts`)
- **`GameState.balancedRollsDrawn?: number`** — OPTIONAL & append-compatible (same discipline as
  S2.1.1's `profileId?`). It is the cumulative count of balanced rolls drawn so far. Present/incremented
  ONLY for `balanced_deck` matches, so **Classic state never gains the key → golden fixtures untouched**.
  `reduce`'s `dice.rolled` case increments it by 1 **iff** the resolved profile's randomness is
  `balanced_deck` (resolve via `loadRuleProfile(state.profileId ?? 'classic').randomness`). Do NOT add
  a "remaining/reshuffle-reset" field — the cumulative counter + modular arithmetic handles reshuffle
  with no mid-cycle reset bug surface.

### 3. Branch the roll in `validate` (core, `validate.ts` ~891–939)
In the `intent.rollDice` handler, resolve `profile = loadRuleProfile(state.profileId ?? 'classic')`
and branch on `profile.randomness`:
- **`'dice'`** → the CURRENT path verbatim: `rollDie(seed, gameplayStreamIndex(state.eventIndex,
  DICE_A))` + `DICE_B` (untouched — Classic byte-frozen).
- **`'balanced_deck'`** → `drawBalancedRoll(seed, state.balancedRollsDrawn ?? 0)` → `{dieA,dieB,total}`.
The emitted `dice.rolled` event is the **same shape** in both branches (`dieA`,`dieB`,`total`, and the
`total===7` → `playersToDiscard` computation is IDENTICAL and unchanged — a balanced 7 fires the robber
exactly like a dice 7). No new event type.

### 4. Make the fairness verifier profile-aware (core, `verify.ts` — the fairness-critical part + carry-forward)
- **The `dice.rolled` recompute case (`verify.ts:206–226`) MUST branch on the folded profile's
  randomness.** Resolve `profile = loadRuleProfile(state.profileId ?? 'classic')` (state is folded, so
  `profileId` is already set by the `match.started` event at index 0). For `'dice'` → the current
  `rollDie(seed, gameplayStreamIndex(expectedIndex, …))` path (unchanged). For `'balanced_deck'` →
  recompute `drawBalancedRoll(seed, balancedRollsSeen)` where **`balancedRollsSeen` is the verifier's
  OWN counter** of `dice.rolled` events folded so far (a new local, incremented per `dice.rolled`),
  **NEVER `state.balancedRollsDrawn` or any log-supplied field** — this is the S1.7.3 positional-binding
  discipline applied to the new draw (a dishonest server must not be able to grind a position field to
  forge a favorable draw that still passes). Check recomputed `dieA`/`dieB`/`total` against the event's,
  flagging mismatches exactly as the dice path does.
- **Discharge the S2.1.1 carry-forward [[verify-profile-blindness-carryforward]]:** replace the two
  Classic-hardcoded dev-deck reads with profile-aware ones —
  `verify.ts:147` `CLASSIC_DEV_CARD_PROFILE.deck.length` → `loadRuleProfile(state.profileId ??
  'classic').devCards.deck.length`, and `verify.ts:236` `shuffledDevDeck(seed)[drawIndex]` →
  `shuffledDevDeck(seed, loadRuleProfile(state.profileId ?? 'classic').devCards.deck)[drawIndex]`.
  (Balanced shares Classic's dev deck today, so this is debt-discharge + correctness hardening, not
  required-for-Balanced-to-pass — but it is the right home and closes the carry-forward. **Board-aware
  verify stays DEFERRED to S2.1.3** — no board divergence exists yet.)
- Export `BALANCED_ROLL_DECK`, `shuffledRollDeck`, `drawBalancedRoll`, `ROLL_DECK_STREAM` from
  `@skervik/core` (`index.ts`).

## Key decisions (surface any deviation)

1. **The balanced deck is the 36 ordered `(dieA,dieB)` outcome pairs drawn without replacement — not a
   synthesized sum.** Why: each card carries a REAL die pair, so `dice.rolled` stays byte-identical and
   `reduce`/production/robber-7/client need zero change; the 2d6 distribution is reproduced exactly
   (six 7-pairs per cycle → robber fires at the natural 1/6), and variance smoothing (the product goal)
   falls out of without-replacement. Rejected: carrying only `total` + synthesizing faces (changes the
   event shape, forces optional fields through reduce/verify/client, and invents dice that weren't
   "rolled"); a separate `roll.drawn` event (forks the union, churns every roll consumer).
2. **Draw derives from `seed` + a cumulative roll-position counter, recomputable from the log; the deck
   order is NEVER stored in `GameState`.** Why: commit-reveal integrity (CLAUDE.md principle 5) — a
   serialized state must not reveal future draws; the verifier recomputes every draw from the revealed
   seed + its own count, exactly as dev-card draws work today. Storing shuffled order in state is the
   same threat as storing the raw seed.
3. **Position counter is cumulative (`balancedRollsDrawn`), reshuffle via `round=floor(n/36)` — no
   remaining/reset field.** Why: modular arithmetic makes reshuffle a pure function of the count with no
   mid-cycle mutation to get wrong; a distinct per-round stream band makes each cycle an independent
   permutation.
4. **The verifier anchors the balanced draw to its OWN `dice.rolled` counter, not `state.balancedRolls
   Drawn`.** Why: S1.7.3 positional-binding — trusting a log-supplied position lets a dishonest server
   forge draws that still verify (the exact hole [[commit-reveal-verify-positional-binding]] caught for
   dice/dev-cards). A false-assurance verifier is worse than none.
5. **Balanced proven at the core level; `GameRoom` stays `'classic'`.** Why: lobby mode-select is
   S2.5.4; the engine + verifier are where fairness/correctness are decided, so a core full-roll-cycle
   match + verify test is the honest proof without pulling in unbuilt lobby/protocol surface (VULYK Law
   3, no out-of-scope edits). End-to-end-via-WS Balanced play lands with the lobby.
6. **No ADR needed** — "profiles as config" + commit-reveal are already locked; this is implementation.
   Flag for an ADR only if the stream-band/verifier-branch shape proves contentious in review.
