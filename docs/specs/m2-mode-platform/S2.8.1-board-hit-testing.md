# S2.8.1 — Board hit-testing + interaction layer (foundation)

**Epic:** E2.8 interactive human play (`E2.8-interactive-play.md`) · **Tier:** 2–3
(client rendering + pure geometry) · **Status:** DISPATCH-READY.

## Goal

Give the board a reusable, phase-agnostic **pick** capability: convert a pointer
click/hover to a `vertexId` / `edgeId` / `tileId`, and surface it via a callback +
a hover highlight. NO game logic, NO intents — this is the foundation S2.8.2+
consume to place/build/move-robber. When unused (`pickMode: 'none'`), the board
behaves EXACTLY as today (pure additive).

## Context (recon 2026-07-14)

- Board is Pixi; `world` container holds the field and carries pan (`world.x/y`)
  + zoom (`world.scale`). Screen→world inversion already exists in the wheel
  handler: `worldX = (pointerX - world.x) / world.scale.x` (`BoardScene.ts:541`).
- Forward geometry is pure in `board/hexGeometry.ts`: `axialToPixel(coord)` (tile
  centre), `vertexToPixel(vertex)`, `edgeToPixel`/edge midpoint. Vertices/edges
  come from `buildTopology()` (`TOPOLOGY` in `GameTable.tsx:17`).
- There is currently NO `eventMode`/`hitArea`/pointer-pick on game pieces — only
  the pan/zoom canvas/window listeners. This story adds the pick layer.

## Requirements

### 1. Pure inverse-geometry helpers (new module `board/picking.ts`, unit-tested)

Operate in WORLD coordinates (board space), given the topology:
- `nearestVertex(worldPoint, topology, maxDistPx): VertexId | null` — the vertex
  whose `vertexToPixel` is closest, or `null` if none within `maxDistPx`.
- `nearestEdge(worldPoint, topology, maxDistPx): EdgeId | null` — nearest by edge
  midpoint (or point-to-segment distance — your call; document it), else `null`.
- `tileAt(worldPoint, topology): TileId | null` — the tile whose hex contains the
  point (point-in-hex, accounting for the render's Y-flatten `Y_SCALE` if the
  forward transform applies it), else `null` (sea/gap).
Pure, deterministic, no Pixi imports. Unit tests: a point ON a known vertex/edge/
tile resolves to it; a point in open sea resolves to `null`; a point just beyond
`maxDistPx` of every vertex → `null`. Reuse `hexGeometry` forward transforms +
`HEX_SIZE`/`Y_SCALE` as the ground truth (do not hardcode a second copy).

### 2. Pick layer in `BoardScene.ts` (additive to the handle)

- Extend `BoardSceneHandle` with:
  - `setPickMode(mode: 'none' | 'vertex' | 'edge' | 'tile'): void` — default `'none'`.
  - a way to register a pick callback: `onPick(cb: (pick: { kind: 'vertex'|'edge'|'tile'; id: string } ) => void): void` (or accept it in `createBoardScene` opts — your call; keep it settable so React can re-bind).
- On pointer move (when `pickMode !== 'none'`): compute the nearest target (screen→
  world using the LIVE `world.x/scale` — read at event time, never cached, so it
  stays correct after pan/zoom AND after S2.7.2 changes the transform) and draw a
  **hover highlight** at that target (a Graphics overlay above pieces: a ring on a
  vertex, a thick segment on an edge, a hex outline on a tile). Clear it when none.
- On pointer **click** (down→up with < ~5px movement, so a PAN DRAG is NOT a pick):
  resolve the target for the current `pickMode` and invoke the callback with
  `{kind, id}`; ignore clicks that resolve to `null`.
- Highlight styling uses existing design tokens (`canvasColors`/DESIGN.md); the
  highlight is a SHAPE (ring/outline), not a hue-only cue.

### 3. Thread through `GameTable.tsx`

- New optional props: `pickMode?: 'none'|'vertex'|'edge'|'tile'` (default `'none'`)
  and `onPick?: (pick) => void`. Wire them to the live scene via the same
  non-remounting ref pattern S2.7.1 established (`sceneRef` + an effect keyed on
  `pickMode`; bind `onPick` through a ref so a changing callback never remounts).
- Default/absent props → `pickMode 'none'`, no callback → **zero behavior change**
  (existing GameScreen passes nothing new; board identical to today).

## Explicitly OUT of scope (later stories)

- Composing/dispatching any intent, legal-move highlighting, phase/turn gating —
  all S2.8.2+. This story only turns a click into an id + shows a hover shape.
- Wiring GameScreen to a real pick mode. (You MAY add a tiny `import.meta.env.DEV`
  harness that sets a pick mode + logs picks, like `TradeDemoControls`, to make
  the layer eyeball-verifiable — optional, dev-only, remove-safe.)

## Constraints

- Pan/zoom MUST keep working unchanged; a drag is never a pick (movement threshold).
- Hit-testing reads the LIVE `world` transform at event time (correct under pan/
  zoom and forward-compatible with S2.7.2 auto-fit-zoom).
- No new user-facing strings (pure interaction layer → no i18n). Core/protocol/
  server byte-untouched; client never gains the seed or calls `validate`.
- Touch only: `packages/client/src/board/picking.ts` (new) + `picking.test.ts`
  (new) + `BoardScene.ts` + `GameTable.tsx` (+ optional dev harness file). Do NOT
  touch core/protocol/server or `buildTopology`.
