# S2.6.1 — Postgres schema + Drizzle migrations + typed repositories

The **first database surface in the monorepo**. Build the persistence foundation E2.6 sits on:
the three M2 tables, generated migrations, a connection factory, and typed repositories — all
inside `packages/server`, all governed by **ADR-0012** (read it and `docs/wiki/persistence.md`
first — the 9 invariants are binding). **This story does NOT rewire the room, does NOT touch
`boot.ts`'s default behavior, and does NOT add auth routes** (those are S2.6.2/S2.6.3). It is a
pure additive change: with no `DATABASE_URL`, the server boots exactly as it does today.

## Goal (terminal, forcing observable)

Running `runMigrations` against a fresh PGlite instance creates the `users`, `matches`, and
`match_players` tables, and the three typed repositories can round-trip rows through them
(insert → read back → the typed result matches) — all proven by a hermetic test suite that
needs no docker and no external DB.

## Scope — build exactly this (nothing more)

**All new files/deps live in `packages/server` ONLY. Do NOT touch `packages/core` or
`packages/protocol`. Do NOT modify `boot.ts` / `createHttpServer` / `startServer` behavior
(no `DATABASE_URL` wiring into the boot path yet — that's dead plumbing until S2.6.2 consumes
it; the ONLY `DATABASE_URL` reader in this story is the migrate CLI).**

1. **Dependencies** (add to `packages/server/package.json` only):
   - runtime: `drizzle-orm`, `pg`
   - dev: `drizzle-kit`, `@electric-sql/pglite`, `@types/pg`
   - Use `pnpm --filter @skervik/server add …`. Pin whatever pnpm resolves; confirm build+test green.

2. **`packages/server/drizzle.config.ts`** (package root) — `dialect: 'postgresql'`,
   `schema: './src/db/schema'`, `out: './src/db/migrations'`.

3. **`packages/server/src/db/schema/`** — Drizzle table definitions per ADR-0012 Fork 2:
   - `users.ts`, `matches.ts`, `matchPlayers.ts`, plus an `index.ts` barrel.
   - Columns EXACTLY as ADR Fork 2 specifies:
     - `users`: `id` uuid PK (app-generated, NOT a DB default — Invariant 5), `username` text unique
       not null, `email` text unique (nullable), `auth_provider` text, `is_guest` boolean not null
       default false, `created_at` timestamptz not null default now(), `deleted_at` timestamptz (nullable).
     - `matches`: `id` uuid PK, `profile` jsonb not null (fully-resolved RuleProfile), `seed_hash` text
       not null, `seed` text (nullable — reveal), `player_count` int, `status` text not null, `started_at`
       timestamptz, `finished_at` timestamptz, `event_log_uri` text, `winner_id` uuid references users(id).
     - `match_players`: `match_id` uuid not null references matches(id), `user_id` uuid references
       users(id), `seat` int not null, `final_vp` int, `result` text; **PK (match_id, seat)**.
   - `status`/`result`/`auth_provider` are `text` (Invariant 8, NOT pg `enum`). Export TS union types
     (e.g. `type MatchStatus = 'live' | 'finished' | 'abandoned'`) for app-level validation, and use
     Drizzle's `$type<…>()` on those columns so the repository API is typed — but the DB column stays `text`.

4. **`packages/server/src/db/migrations/`** — GENERATE via `pnpm --filter @skervik/server exec drizzle-kit
   generate` (add a `db:generate` script). Commit the generated `.sql` + `_journal.json`. Never hand-edit
   generated SQL (Invariant 3).

5. **`packages/server/src/db/client.ts`** — connection factory returning a typed `drizzle(...)` instance:
   - a `createPgDb(databaseUrl: string)` path using `drizzle-orm/node-postgres` (for prod/migrate CLI),
   - a `createPgliteDb(client?: PGlite)` path using `drizzle-orm/pglite` (for tests / ephemeral in-memory).
   - Both return the same typed `db` shape over the schema barrel so repositories are driver-agnostic.

6. **`packages/server/src/db/migrate.ts`** — a single `runMigrations(db, migrationsFolder?)` wrapping
   drizzle's migrator (`migrationsFolder` resolved relative to the package so it works from `dist/` too;
   use the driver-appropriate `migrate` — `drizzle-orm/pglite/migrator` for pglite, `drizzle-orm/node-postgres/migrator`
   for pg — dispatched by the db instance). Plus a CLI entry (the `migrate` npm script) that reads
   `process.env.DATABASE_URL`, builds a pg db, runs `runMigrations`, exits. **No auto-migrate on server
   boot** (Invariant 4).

7. **`packages/server/src/db/repositories/`** — typed repos, the ONLY DB surface the rest of the server
   will call (no raw Drizzle leaks into rooms/routes later):
   - `UserRepository` — `create({username, email?, authProvider, isGuest})` (generates `id` via
     `crypto.randomUUID()` — Invariant 5), `findById(id)`, `findByUsername(username)`; results filter
     `deleted_at IS NULL` where a "live user" is meant (document the soft-delete filter — S2.6.4 uses it).
   - `MatchRepository` — `create({...match-start fields...})`, `findById(id)`, an `update` for the
     `game.ended` fields (`seed`, `winner_id`, `status`, `finished_at`). (S2.6.3 calls these; here just
     build + unit-test them.)
   - `MatchPlayerRepository` — `create({matchId, userId?, seat, finalVp?, result?})`, `findByMatch(matchId)`.
   - Each takes the `db` instance via constructor injection (so a test passes a PGlite-backed db).

8. **`packages/server/package.json` scripts** — add `"migrate"` (runs the migrate CLI, e.g.
   `tsx src/db/migrate.ts` or the built equivalent — match how the package runs other node entrypoints)
   and `"db:generate"` (`drizzle-kit generate`).

## Acceptance criteria (each a real assertion)

- **AC1 (migrations create the schema — forcing):** a test spins a fresh in-memory `PGlite`, calls
  `runMigrations`, and asserts all three tables exist (e.g. query `information_schema.tables` or insert a
  row into each). This runs the REAL generated migration files (Invariant 2), not a hand-built DDL.
- **AC2 (repository round-trip):** for each repository, a PGlite-backed test inserts a row and reads it
  back, asserting the typed result equals what went in (including: `users.id` is a valid app-generated
  UUID; `matches.profile` jsonb round-trips a real RuleProfile object; `match_players` composite PK
  `(match_id, seat)` rejects a duplicate seat).
- **AC3 (FK + soft-delete semantics):** inserting a `match_players` row with a `match_id` that doesn't
  exist fails the FK; `UserRepository`'s live-user read excludes a row with `deleted_at` set.
- **AC4 (hermetic):** the full `pnpm -r test` passes with NO docker and NO external DB — PGlite only.
  State this explicitly in your report.
- **AC5 (no regression):** `boot.ts`/`createHttpServer`/`startServer` are byte-unchanged; the existing
  server suite (146 tests: fullMatch/twoPlayerMatch/private/readyUp/matchmakingByMode e2e etc.) stays
  green unchanged. `packages/core` + `packages/protocol` git-byte-unchanged. Core stays zero-runtime-dep
  (`node scripts/check-core-no-runtime-deps.mjs` passes).

## Invariant checklist (ADR-0012)

- [ ] New deps in `packages/server` ONLY; core zero-dep guard passes; protocol type-only.
- [ ] App-side UUIDs via `crypto.randomUUID()` — no DB default/extension (Invariant 5).
- [ ] Generated migrations committed, never hand-edited (Invariant 3); one `dialect:'postgresql'` set
      runs on both PGlite (tests) and would run on pg (prod) — same files (Invariant 2).
- [ ] No auto-migrate on boot; migrations only via `runMigrations`/`migrate` script (Invariant 4).
- [ ] No `events` table — event log stays ndjson; only `event_log_uri` in `matches` (Invariant 6).
- [ ] Only `users`/`matches`/`match_players` — NO `player_ratings`, NO `donations` (Invariant 7).
- [ ] `status`/`result`/`auth_provider` are `text` + app union types, not pg enum (Invariant 8).
- [ ] `boot.ts` untouched; DB optional; no `DATABASE_URL` wiring into the boot path (Invariant 9).
