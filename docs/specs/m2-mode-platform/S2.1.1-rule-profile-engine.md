# S2.1.1 — RuleProfile type + loader + Classic/Balanced/Blitz presets (M2 config backbone)

## Goal

Turn the LOCKED product invariant — *"Rule Profiles are config objects, not code branches
(`classic | balanced | blitz | deep`); the multi-mode platform is ONE engine configured
differently"* — into real code. Today the engine's rules are eight **module-local hardcoded
constants** (`CLASSIC_BOARD_PROFILE`, `CLASSIC_DEV_CARD_PROFILE`, `CLASSIC_SETUP_PROFILE`,
`CLASSIC_PRODUCTION_PROFILE`, `CLASSIC_BUILD_PROFILE`, `CLASSIC_BANK_TRADE_PROFILE`,
`CLASSIC_ROBBER_PROFILE`, `CLASSIC_VICTORY_PROFILE`) that `validate`/`reduce`/`boardgen`/`devcards`
read directly by name. That is the "code branch per mode" anti-pattern waiting to happen — the M2
mode work (Balanced deck, Blitz, adaptive duration, catch-up) has nowhere config-shaped to land.

S2.1.1 introduces a single **`RuleProfile`** aggregate, a deterministic **loader** (`id → RuleProfile`),
the **Classic / Balanced / Blitz** presets, and — crucially — **rewires the engine's rule-consumption
to read from a resolved profile instead of the module globals**, with a `profileId` carried in
`GameState` (fixed at `match.started`). Classic stays **byte-identical** (every M1 golden /
determinism / replay-equality / verify test green); Balanced and Blitz land as **declarative presets**
whose mode-specific *mechanics* are switched on by later stories — this story makes them selectable
and makes their already-consumed knobs (e.g. `vpToWin`) live, not their unimplemented behaviors.

## What to build

### 1. The `RuleProfile` type (core)
A single readonly aggregate composing the existing sub-profiles (reuse their shapes — do NOT
re-invent fields), plus mode metadata. Indicative shape (confirm exact sub-fields against the
constants at dispatch):
```
type RuleProfileId = 'classic' | 'balanced' | 'blitz';   // 'deep' reserved (M4) — do NOT add yet
interface RuleProfile {
  readonly id: RuleProfileId;
  readonly name: string;                    // human label (i18n key comes later, S2.5.4 lobby)
  readonly randomness: 'dice' | 'balanced_deck';  // FLAG only; the balanced_deck mechanic is S2.1.2
  readonly board: BoardProfile;             // = today's CLASSIC_BOARD_PROFILE shape
  readonly devCards: DevCardProfile;        // = CLASSIC_DEV_CARD_PROFILE
  readonly setup: SetupProfile;             // = CLASSIC_SETUP_PROFILE
  readonly production: ProductionProfile;   // = CLASSIC_PRODUCTION_PROFILE (bankPerResource)
  readonly build: BuildProfile;             // = CLASSIC_BUILD_PROFILE (costs, supply)
  readonly bankTrade: BankTradeProfile;     // = CLASSIC_BANK_TRADE_PROFILE (baseRate)
  readonly robber: RobberProfile;           // = CLASSIC_ROBBER_PROFILE (handLimit)
  readonly victory: VictoryProfile;         // = CLASSIC_VICTORY_PROFILE (vpToWin, longestRoad*, largestArmy*)
}
```
Name the sub-profile types from the existing constants (extract/export their `interface`s where they
are currently inline/anonymous). Zero new runtime deps.

### 2. The presets + loader (core)
- **`CLASSIC_PROFILE: RuleProfile`** — composes the EXISTING constants unchanged (it is the single
  source of truth; the old constants either become fields of it or are re-derived from it — pick the
  path that keeps values byte-identical and prove it).
- **`BALANCED_PROFILE`**, **`BLITZ_PROFILE`** — declarative presets. For M1-parity safety, restrict
  their differences to knobs the engine ALREADY consumes: Balanced = Classic with
  `randomness:'balanced_deck'` (flag only — S2.1.2 implements the number-deck draw); Blitz = Classic
  with a lower `victory.vpToWin` (e.g. 8) for a shorter game. Board-size / timer / parallel-phase
  differences are DEFERRED (they need S2.1.3 adaptive + S2.1.4 timers + boardgen radius support) —
  do NOT fabricate fields the engine can't yet honor. Document each preset's "activated later" knobs.
- **`loadRuleProfile(id: RuleProfileId): RuleProfile`** — a pure total function over a registry
  `{ classic, balanced, blitz }`; unknown id → throw a typed error (or return classic + a documented
  fallback — surface the choice). Deterministic; no wall-clock/RNG.

### 3. Deliver the profile to the pure engine + rewire consumption (the load-bearing part)
- **`GameState` gains `readonly profileId: RuleProfileId`** (append-compatible new field), fixed
  when the match starts. `match.started` carries it (the log records it, so replay/verify resolve the
  SAME rules — event-sourcing). Lobby/pre-match defaults to `'classic'` for now (mode selection UI =
  S2.5.4); GameRoom passes `'classic'`.
- **`validate`/`reduce`/`boardgen`/`devcards` read their knobs from `loadRuleProfile(state.profileId)`
  (a resolved `RuleProfile`) instead of the module-global `CLASSIC_*` constants.** Mechanical
  substitution `CLASSIC_X_PROFILE.field → profile.x.field` at every call site (validate.ts lines
  ~368–1341, boardgen, devcards). `generateBoard`/`shuffledDevDeck` take the relevant sub-profile
  (or the resolved profile) as a param rather than reaching for a global.
- **Determinism/contract guard:** `reduce(state, event)` and `validate(state, intent, playerId, seed)`
  keep their EXACT signatures (the engine contract, CLAUDE.md §4.1) — the profile flows via
  `state.profileId`, NOT a new positional arg. No wall-clock, no ambient RNG. With `profileId:'classic'`
  the engine must produce byte-identical output to today (this is THE acceptance bar).

- **Turn timers** (soft/hard, anti-AFK) — **S2.1.4**. No timer fields wired to behavior here.

  plumbing, not a balance change.

## Key decisions (surface any deviation)

1. **Profile delivered via `state.profileId` + `loadRuleProfile`, resolved inside the pure engine —
   NOT a new `reduce`/`validate` parameter.** Why: the engine contract signatures are locked
   (CLAUDE.md §4.1); a `profileId` in `GameState` is small, serializable, set once at `match.started`,
   recorded in the log (so replay + the S1.7.3 verifier resolve identical rules — event-sourcing
   integrity), and keeps the functions pure (`id → profile` is a deterministic total function).
   Rejected: threading a full `RuleProfile` as a param (bloats the contract + every call site);
   storing the whole profile object in `GameState` (bloats state/schema with static data — the small
   id + a pure loader is leaner and equally deterministic).
2. **`CLASSIC_PROFILE` is the single source of truth; Classic is byte-frozen.** The rewire is a
   mechanical global→profile substitution proven non-behavioral by the unchanged M1 test suite
   (golden replay, determinism, `fullMatch.e2e` replay-equality, `verifyMatchRandomness`). If ANY M1
   test needs a value change to pass, STOP — that means the refactor altered behavior (a bug), not a
   reason to re-golden.
3. **Balanced/Blitz presets are declarative + minimal.** Only knobs the engine already honors differ
   (randomness flag, `vpToWin`); unimplemented mode mechanics are NOT faked as fields. This avoids
   speculative/dead config (VULYK Law 2) — each later story adds its own profile field WHEN it
   implements the behavior.
4. **No ADR needed.** The "profiles as config" decision is already locked (ADR-0003/0004 + CLAUDE.md);
   this is its implementation. If the delivery mechanism proves contentious in review, an ADR can
   follow — flag it, don't pre-write it.
