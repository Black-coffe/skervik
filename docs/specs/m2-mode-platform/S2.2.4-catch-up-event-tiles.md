# S2.2.4 — Catch-up event tiles (deterministic poverty-token boost on flagged storms)

## Goal

Fourth and final catch-up mechanic (roadmap principle 3 — *catch-up over runaway-leader*). A 7 ("storm")
today only HURTS: it triggers the robber + forces discards. For a trailing player a storm is pure
downside. **Owner decisions 2026-07-08 (both recommended options, locked):**

1. **Form — a DETERMINISTIC boost on a SUBSET of 7-rolls, ADDITIVE to the normal robber/discard flow.**
   A new `catchUp.eventTiles` flag. On a deterministic cadence (every `eventTilesInterval`-th storm,
   counted by a persistent `sevensRolled` counter in state), the storm ALSO fires a catch-up "event"
   that helps the player(s) who are behind. The robber/discard mechanics of the 7 are **completely
   unchanged** — the event boost is emitted alongside, not instead. This is why the mechanic touches
   NO per-action legality and does NOT re-open the forced-action hang risk.
2. **Payload — a poverty token (REUSE the S2.2.2 machinery).** The event grants the trailing player(s)
   (by PUBLIC VP, via the existing `isTrailing` → `computePublicVictoryPoints`) a **poverty token** —
   the discounted-bank-trade currency S2.2.2 already built (`povertyTokens` field +
   `poverty.tokensGranted` event + `computePovertyGrants` selection/cap). Zero new economy, zero new
   event, zero new randomness. The storm becomes a SECOND emission site for the SAME grant that S2.2.2
   emits on empty non-7 rolls.

Both are **profile-gated `CatchUpProfile` fields**, off on every shipping preset for now (liveness via
test profiles — the S2.1.5/S2.2.1/S2.2.2/S2.2.3 discipline).

**This is a DETERMINISTIC-from-state mechanic** — the cadence (a state counter), the trailing-player
selection (public VP), and the grant (capped +1) are all pure functions of `state` + the profile. **NO
seed slot, NO new PRNG, `verify.ts` UNCHANGED.** The owner chose this design specifically to avoid opening
a new seed slot (which would have forced positional-binding + verify coverage per
[[commit-reveal-verify-positional-binding]]). The seed-derived draws (dice, dev-card, board, steal) are
untouched.

**Why T2 (lightest of the E2.2 mechanics):** no new `GameEvent` (reuses `poverty.tokensGranted`), no
protocol change (the schema already exists — messages.ts:466), no win-check touch, no new economy, no
seed. It is one profile flag + one interval param + one additive counter field + one extra emission site
that calls an EXISTING helper. It is still a core determinism/fairness/golden-freeze diff → **mandatory
lead-review** on the byte-freeze of the OFF path and the reuse correctness.

## Mechanic (precise)

### Cadence (which storms are "event tiles")

A persistent counter `state.sevensRolled` (absent until the first storm under `eventTiles:true`) counts
storms. A storm is an **event storm** iff:

```
eventStorm = catchUp.eventTiles && (((state.sevensRolled ?? 0) + 1) % eventTilesInterval === 0)
```

i.e. this storm is the `(sevensRolled+1)`-th since the flag turned on, and that index is a multiple of the
interval. `eventTilesInterval` is a **provisional balance knob** (default `3` = every third storm; off on
presets → changes no shipping behavior). Interval `1` = every storm is an event storm (allowed).

- **validate** computes `eventStorm` from the PRE-roll counter (`state.sevensRolled ?? 0`) — this storm is
  the `(k+1)`-th.
- **reduce** increments the counter to `k+1` when it applies the `dice.rolled` event for a total of 7 under
  `eventTiles:true`. validate's `(k+1)` and reduce's post-increment `k+1` agree by construction — anchor
  the cadence to the SAME counter the reducer advances (no parallel counting).

### Grant (who gets what)

On an event storm, REUSE `computePovertyGrants(state, {})` (validate.ts:488-505). On a 7 there is zero
production, so passing an empty production map means every player has "produced nothing" this roll →
`isTrailing` + the `robinHoodTokenCap` cap decide who qualifies (the SAME trailing definition and cap
S2.2.2 uses on non-7 rolls). If the resulting grants map is non-empty, emit `poverty.tokensGranted`
(index-correct) IN ADDITION to the storm's normal events; reduce applies it into the shared `povertyTokens`
pool (reduce.ts:683-692, unchanged). The grant reuses the shared cap `catchUp.robinHoodTokenCap` (both
grant sources feed one pool; a roll is either a 7 or a non-7, never both, so no double-grant in one roll).

### 7 (robber/discard) flow — UNCHANGED

The storm still emits `dice.rolled` + sets up the discard/robber phase EXACTLY as today (validate.ts:1156,
returns early after the discard setup). The `poverty.tokensGranted` event is inserted **immediately after
`dice.rolled` and before the early return**, so on an event storm the batch is `[dice.rolled,
poverty.tokensGranted, …discard setup…]` in a fixed deterministic order. Per-action legality (who must
discard, robber placement, steal eligibility) is byte-identical to today.

### `eventTiles` OFF (every shipping preset — byte-frozen)

`sevensRolled` is NEVER written (the counter only advances under `eventTiles:true`); no `poverty.tokensGranted`
ever emits from the 7 path; the storm batch is byte-identical to today. Classic/Balanced/Blitz/twoPlayer +
golden/replay/verify stay byte-frozen.

## Key decisions (surface any deviation)

1. **Deterministic → verify untouched.** Cadence (state counter), trailing selection (public VP), and grant
   (capped +1) are pure functions of `state` + profile. No new PRNG slot, no verify branch. This is the
   owner's explicit reason for choosing this design over a seed-random "event deck" (which would have forced
   positional-binding + verify coverage). Same discipline as S2.2.1/S2.2.2/S2.2.3.
2. **REUSE, do not fork.** `computePovertyGrants(state, {})` is the trailing-selection + cap engine — call it
   with an empty production map on the 7 path. The `poverty.tokensGranted` event + reducer are reused verbatim.
   If reuse feels wrong (e.g. `computePovertyGrants` has a hidden non-7 assumption), STOP + report before
   copying logic.
3. **Additive counter, absent when off.** `sevensRolled?` optional + only written under `eventTiles:true` →
   golden byte-frozen under `eventTiles:false`. This is the headline determinism risk; lead-review verifies the
   OFF storm batch + state shape are byte-identical and the field is genuinely ABSENT (`Object.keys`).
4. **PUBLIC VP for trailing, never a hidden leak.** The grant goes to `isTrailing` players, which reads
   `computePublicVictoryPoints` (validate.ts:416-431) — dev-card VP excluded. No hidden-VP leak (consistent
   with the S2.2.1/S2.2.2/S2.2.3 gates).
5. **Forced-action hang stays CLOSED (does NOT re-open).** The 7 branch's robber/discard legality is UNCHANGED
   — the boost is additive + system-generated (no player choice, no new phase). So [[turn-timer-forced-action-hang-risk]]
   is NOT re-opened; no re-arm watchdog is mandated. Still add the forced-7-on-event-tiles test to prove it. If
   the worker finds the extra emission could ever make a forced roll fail validate, STOP + report (that would be
   the hang the memory warns about).
6. **Shared pool + shared cap.** Both grant sources (non-7 robin-hood, event-storm) feed one `povertyTokens`
   pool and honor `robinHoodTokenCap`. A roll is either a 7 or a non-7, so the two sites never fire in the same
   roll; the cap is enforced at each emission via `computePovertyGrants`.
7. **Interval is a provisional balance knob** (default 3). Off on presets → changes no shipping behavior. Set
   it, don't agonize; tune in the M2 balance-sim/playtest workstream.
8. **No ADR needed.** Profiles-as-config + catch-up-profile-gating are locked (S2.1.1/S2.2.2); this is their
   application + reuse. If the worker judges otherwise, STOP + report before writing one.
