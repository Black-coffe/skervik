# S2.8.3a — Roll dice + end turn (main-loop skeleton)

**Epic:** E2.8 · **Tier:** 2 · **Depends on:** S2.8.2 (merged) · **Status:**
DISPATCH-READY. Split from the planned S2.8.3 — **S2.8.3b** (build settlement/road/
city via clicks + main-phase legality/affordability) follows separately, so each
is small + reviewable.

## Goal

Wire the two resource-free turn actions so a human can drive the main loop:
**roll the dice** (phase `roll` → advances to `main`, triggering production) and
**end the turn** (phase `main` → next player's `roll`). This is the step that
takes a completed setup into the actual playing phase — production flows, and the
Trade UI (S2.7.1, already gated to `main`) becomes usable. No building yet (3b).

## Core contract (verified)

- Intents (both extend `BaseIntent`, need `playerId`; `store.dispatchIntent` sends
  any intent, `hud/store.ts:186`):
  - `{ type: 'intent.rollDice', playerId }` — legal in phase `roll`, current player.
  - `{ type: 'intent.endTurn', playerId }` — legal in phase `main`, current player.
- Turn detection: `selectIsMyTurn(gameState, myPlayerId)` = `currentPlayerId===
  myPlayerId` (`hud/store.ts:278`) — reuse it (do NOT reimplement).
- 🔴 **7 → robber (verify, do not trust the stale `types.ts:50` "7 falls through to
  main" comment — S1.3.1 wired the robber).** A rolled 7 (or the bots' 7s) enters
  the `robber` phase (discard + move robber). The HUMAN robber UI is **S2.8.4**, so
  after THIS story a human who rolls a 7 lands in `robber` with nothing to click
  yet (bots resolve their own 7s via the server bot driver). That's an accepted
  interim gap — most rolls aren't 7, and S2.8.4 closes it. Do NOT try to handle the
  robber here.

## Requirements (in `hud/BottomDeck.tsx`)

1. **Roll control.** In the tide-lot area (currently the `hud.tideLotPlaceholder`
   "Кости не брошены" text), render a **roll button** enabled ONLY when
   `phase==='roll' && selectIsMyTurn(...)`. On click →
   `dispatchIntent({ type:'intent.rollDice', playerId: myPlayerId })`. After the
   roll the phase leaves `roll`, so the button naturally disables (no double-roll
   guard needed beyond the phase check). If `GameState` carries the last roll
   result (check `reduce.ts`/`types.ts` for a dice field written by the
   `dice.rolled` case — e.g. a `lastRoll`/`dice` field), SHOW it here (e.g. the
   total) instead of the placeholder once rolled; if there is no such field, leave
   the placeholder unchanged and just show the button (don't invent core state).
2. **Wire «Завершить ход».** The existing `hud.actionEndTurn` primary button:
   enabled ONLY when `phase==='main' && selectIsMyTurn(...)`; on click →
   `dispatchIntent({ type:'intent.endTurn', playerId: myPlayerId })`.
3. **Leave Build / Trade / Venture buttons DISABLED** — Build = S2.8.3b, Venture =
   S2.8.5. (The Trade UI already appears in `main` via `TradeZone`/S2.7.1; wiring
   the «Торговать» button to focus/toggle it is out of scope here.)
4. Read `phase`, `myPlayerId`, `dispatchIntent` from the store (BottomDeck already
   pulls `gameState` + `myPlayerId`). Gating logic may be a tiny pure helper
   (`canRoll(state, myPlayerId)`, `canEndTurn(state, myPlayerId)`) with a unit test,
   or inline — your call, but if inline keep it trivially correct.
