## Goal

In the `main` phase, on the local player's turn, let a human **build** by clicking
the board: enter a build submode via the «Строить» button (currently disabled from
S2.8.3a), pick a piece type (settlement / road / city), see legal-target highlights
+ affordability, click a target → dispatch the matching build intent. After this a
human can grow their network turn-over-turn toward victory. **Server stays the sole
authority** — client legality/affordability are advisory HINTS only; an illegal or
unaffordable click still dispatches and surfaces the server reject via `NoticeBar`.

## Core contract (verified — do NOT call `validate` client-side; mirror it)

Intents (all extend `BaseIntent`, need `playerId`; send via `store.dispatchIntent`,
`hud/store.ts:186`):
- `{ type: 'intent.buildRoad', playerId, edgeId }` (`core/types.ts:939`)
- `{ type: 'intent.buildSettlement', playerId, vertexId }` (`core/types.ts:949`)
- `{ type: 'intent.buildCity', playerId, vertexId }` (`core/types.ts:955`)

Costs + supply from `CLASSIC_BUILD_PROFILE` (`core` export; `ruleProfile.ts:403`):
- road `{ timber:1, clay:1 }`, settlement `{ timber:1, clay:1, fleece:1, barley:1 }`,
  city `{ iron:3, barley:2 }`; supply roads 15 / settlements 5 / cities 4.
- **Load the ACTIVE profile, not the constant** where possible — resources/costs are
  Classic here, but resolve via the player's `gameState.profileId` if a helper exists
  (`loadRuleProfile`); Classic is the only profile that reaches `main` today, so
  `CLASSIC_BUILD_PROFILE` is an acceptable source if profile-resolution adds friction.
  State the choice you make.

Main-phase legality, mirrored from `validate.ts` (`1344`–`1454`) — the SERVER rules
you replicate for highlighting (each is advisory):
- **Road** (`1344`): edge exists · not already occupied (`buildings.roads[edgeId]`) ·
  **connects to the player's own network** (`touchesOwnNetwork` — incident to one of
  the player's own roads OR own settlement/city) · supply not exhausted.
- **Settlement** (`1377`): vertex exists · not occupied (settlement OR city there) ·
  **distance rule** (`violatesDistanceRule` — no building on an adjacent vertex) ·
  **connects to the player's own road** (`touchesOwnRoad`) — 🔴 **main-phase requires
  road connection; SETUP WAIVES IT.** So you CANNOT just reuse `legalBuildSettlements`
  = `legalSetupSettlements` (`board/setupLegality.ts:16`) — that omits the road-
  connectivity gate. Reuse the distance-rule portion, ADD the own-road-connectivity
  gate. · supply not exhausted.
- **City** (`1421`): `buildings.settlements[vertexId] === playerId` — i.e. the vertex
  is one of the player's OWN settlements (a city vertex is no longer a settlements
  key, so upgraded/empty/enemy all correctly read illegal) · supply not exhausted.

🔴 **Core exports only `findVertex`/`findEdge`/`buildTopology`** (`core/index.ts:35`).
`touchesOwnNetwork` / `touchesOwnRoad` / `violatesDistanceRule` / `countOwned` /
`canAfford` are **private to `validate.ts`** — you must RE-DERIVE them as pure client
helpers (same discipline as S2.8.2's `setupLegality.ts`). Do NOT export them from core
(keeps core surface minimal; the client mirror is advisory anyway). Keep the mirror
faithful to the cited `validate.ts` lines and unit-test it against hand-built states.

## Requirements

### 1. Build submode + type selector (`hud/`)
- Enable the «Строить» button (`hud/BottomDeck.tsx`, disabled in S2.8.3a) ONLY when
  `phase==='main' && selectIsMyTurn(state, myPlayerId)` (reuse `selectIsMyTurn`,
  `store.ts:278` — do NOT reimplement).
- Clicking «Строить» toggles a small **build-type selector** (settlement / road /
  city). Each type button:
  - shows its cost (icons/label, i18n),
  - is **disabled when unaffordable** (advisory — mirror `canAfford` against the local
    player's `resources`) OR when that type's supply is exhausted,
  - selecting it enters that pick mode; selecting again / pressing the button again /
    an explicit «Отмена» cancels back to no-build. **Buttons disable, never disappear
    or shift** (DESIGN.md §6) — the selector may appear/collapse as a unit, but within
    it nothing jumps.
- Keep it SIMPLE and misclick-resistant (DESIGN.md ethos): no nested menus, no free
  input; a click-to-cancel affordance so a mis-entered mode is trivially escapable.

### 2. Board pick wiring (`hud/useBuildPlacement.ts` — new, mirror `useSetupPlacement.ts`)
- Pure `deriveBuildPlacement(gameState, myPlayerId, buildMode)` → `{ pickMode,
  legalTargets, prompt }`:
  - `buildMode==='settlement'` → `pickMode:'vertex'`, `legalTargets` = vertex ids from
    `legalBuildSettlements`.
  - `buildMode==='road'` → `pickMode:'edge'`, `legalTargets` = edge ids from
    `legalBuildRoads`.
  - `buildMode==='city'` → `pickMode:'vertex'`, `legalTargets` = the player's own
    settlement vertex ids (`legalBuildCities`).
  - `buildMode==='none'` or not my main-phase turn → inactive (`pickMode:'none'`).
- Pure `resolveBuildPick(buildMode, pick, myPlayerId)` → the matching intent or `null`
  if the pick kind doesn't match the mode. **ADVISORY**: do NOT gate on
  `legalTargets` (same rationale as `resolveSetupPick`, `useSetupPlacement.ts:76` — a
  client/server legality drift must never lock out a legal move; the server decides).
- A thin `useBuildPlacement()` hook wires them to the live store and dispatches via
  `dispatchIntent`, exactly like `useSetupPlacement`.
- After a successful build, exit the pick mode (return to no-build submode) so the
  next build is a deliberate re-entry — avoids accidental double-placement. (The board
  scene currently REMOUNTS on every build — the pre-existing **F-remount** follow-up;
  do NOT fix it here, but be aware the camera resets after each placement.)

### 3. `board/buildLegality.ts` (new, pure — mirror `setupLegality.ts`)
- `legalBuildSettlements(state, topology, playerId)` → `VertexId[]` (occupancy +
  distance + own-road-connectivity + supply).
- `legalBuildRoads(state, topology, playerId)` → `EdgeId[]` (occupancy + own-network
  connectivity + supply).
- `legalBuildCities(state, playerId)` → `VertexId[]` (the player's own settlements;
  respects city supply).
- Plus a pure affordability helper `canAffordCost(resources, cost)` mirroring core
  `canAfford` (for the type-selector gating). Unit-test all four against hand-built
  `GameState`s (legal, each illegality reason, boundary at supply/affordability).

### 4. Screen routing (`hud/GameScreen.tsx`)
- `GameScreen` currently feeds `pickMode`/`legalTargets`/`onPick` from
  `useSetupPlacement`. Now select the source by phase: `setup` → setup placement;
  `main` → build placement (when a build submode is active, else inert). Do NOT run
  both; a single active pick source at a time. Keep the existing `dockVisible` and
  S2.8.1/2 threading intact.
