# S2.7.2 — Board auto-fit zoom (client) — follow-up to S2.7.1 F1

**Tier:** 2 (client rendering) · **Epic:** E2.7 UI polish · **Status:** OPEN
(owner-accepted follow-up, 2026-07-14).

## Why (S2.7.1 lead-review finding F1)

S2.7.1 offsets the board right when the trade dock is visible, but at **exactly
1280px** (the min desktop width) the board's leftmost tiles still clip the dock by
~24px (port markers ~55px). Geometry: chart at 1280 = 680px
(`GameScreen.css:11` grid `280px 1fr 320px`, no gap); dock reserve ≈408px leaves
272px, but the radius-2 board field is ~360px wide at the fixed `scale=1`
(`BoardScene.ts` sets `world.position` only — there is NO auto-fit). So at scale=1
the board cannot fit beside the dock at 1280 at ANY offset; a full-reserve shift
just pushes it off-screen right. Clears at ≥~1340px. Owner accepted the marginal
1280px overlap for now (pan/zoom recovers it; real testers are ≥1366px) and asked
for the proper fix as this separate story.

## Goal

The board's DEFAULT (un-panned) view auto-fits its field to the currently
available chart box — i.e. scale so the whole 19-tile field + port markers fit
inside `chartWidth − (dockVisible ? dockReserve : 0)` × `chartHeight`, centred in
that available box. Then 1280px (and narrower, down to the ≥1280 desktop floor) is
clean whether or not the trade dock is shown, and the board still centres nicely
on wide screens.

## Notes / constraints

- Must react to BOTH: chart resize (window resize — there's a `resizeTo: mountEl`
  already) AND the dock showing/hiding (reuse the S2.7.1 `setDockVisible` seam /
  `dockVisible` prop). No Pixi scene remount (same constraint as S2.7.1).
- Auto-fit sets the INITIAL/baseline scale + position; user pan/zoom still applies
  on top and must not be clobbered by a later resize unless the user hasn't
  interacted (decide: reset-to-fit on resize, or only fit once on mount +
  dock-toggle — pick the simpler that doesn't fight the user; document it).
- This SUPERSEDES the fixed `TRADE_DOCK_OFFSET_PX = 204` constant from S2.7.1:
  once the board is fit to the available box, the offset becomes "centre in the
  box beside the dock", derived from measured chart width, not a magic 204.
- Forward-looking: the radius-3 `expanded` board (S2.1.7b, 37 tiles) is physically
  larger — auto-fit is what makes it fit at all, so build the fit math off the
  actual field extent (from topology/descriptors), not a hardcoded radius-2 size.
- Desktop ≥1280px scope; mobile/≤1024 bottom-sheet reflow is still its own story.

## Acceptance criteria

1. At 1280px chart width with the dock shown (`main`), NO tile/token/port overlaps
   the dock at the default view. Prove with a computed-extent unit test (field
   extent vs available box → fits) — the test the F1a fix direction called for,
   now satisfiable because the board scales.
2. On window resize and on dock toggle, the fit recomputes without a scene remount
   and without breaking pan/zoom.
3. Wide screens (≥1920) still look good — board not absurdly small; cap max scale
   if needed.
