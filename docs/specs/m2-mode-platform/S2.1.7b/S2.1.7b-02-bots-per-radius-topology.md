# Bots: per-match topology, profile-derived bank, harness radius fix

## Goal

Bots stop assuming a 19-tile board. The two module-level `TOPO = buildTopology()` constants
(`heuristic/v0.ts:31`, `eval/features.ts:31`) and the hardcoded `BANK_PER_RESOURCE = 19`
(`v0.ts:249`) become per-match values resolved from `loadRuleProfile(state.profileId)`, and the
`simulateMatch` harness stops feeding a radius-2 topology to a radius-3 board. After this story a
6-player `expanded` match plays headless to a winner — the first end-to-end proof that the big board
is actually playable, and the earliest signal in this pack (see Tracer).

## Non-goals
- Do NOT re-tune heuristic weights for the bigger board. ADR-0013 explicitly defers 5–6p bot
  *quality* to M3; this story only makes bots play the correct board, not play it well.
- Do NOT touch `heuristic/v1.ts` logic or the robinHood behaviour — if v1 inherits `TOPO` through
  v0, route it, do not redesign it.
- Do NOT add a bot-count cap, seat validation, or lobby knowledge here. Seats are core (story 01)
  and server (story 04).
- Do NOT convert `buildTopology()` calls inside Classic-only tests that are asserting radius-2
  behaviour on purpose.
- Do NOT touch `packages/core`, `sim/sweep.ts`, or the balance-sim report format — a 37-tile board
  in the sweep is a separate balance question, not this story's.

## Tracer

This is the pack's tracer slice: the thinnest path that touches **core profile → per-radius topology
→ board generation → bot heuristics → a complete simulated 6-player match on the 37-tile board**,
with no server, client, protocol, or socket involved. If the expanded board is unplayable — a
placement heuristic that assumes 19 tiles, a token distribution that starves the bots, a
non-terminating match — this story finds it in wave 1, before five other stories are built on the
assumption that it works. Report the pinned seed and the winner in `## Implementation notes`; story

## Findings

- **`TOPO` from `eval/features.ts:31` has a wider blast radius than the story's `## Files`
  list covers.** Besides `heuristic/v0.ts:32` (its own separate module-level `TOPO`), the
  exported `features.ts` `TOPO` is imported by THREE files not in `## Files`:
  `eval/evaluate.ts:25` (used in `roadOpensSpot`, line 156 — `TOPO.edges.find(...)`),
  `heuristic/v1.ts:63` (used in 7 places: candidate-generation loops at lines 196, 214, 238,
  244, 326, 354, 516), and `heuristic/v1.robinHood.test.ts` (lines 22/35/46/55/63/68).
  `createHeuristicBot()` — the function every non-v0 caller (including a fresh
  `simulateMatch({profileId:'expanded', players:6, ...})` tracer run) uses by default —
  dispatches to `decideV1`, so AC #4 (6p expanded match reaches a winner) necessarily
  exercises v1's candidate-generation loops, which are pinned to a hardcoded radius-2
  `TOPO` import today.
- Several of the functions carrying this dependency (`distanceOk`, `touchesOwnRoad`,
  `touchesOwnNetwork`, `isOpenSettlementSite` in `features.ts`) take `Buildings`, not
  `GameState` — they have no `state.profileId` to resolve a per-match topology from. Making
  them per-call topology-aware means adding a `topology` parameter, which is a signature
  change every v1.ts call site must follow — not a same-file fix.
- The story's Non-goals anticipate SOME v1 touch ("if v1 inherits TOPO through v0, route it,
  do not redesign it"), but the premise is off: v1 imports `TOPO` directly from
  `features.ts`, not through `v0.ts`, and `eval/evaluate.ts` (equally affected, not
  mentioned anywhere in the story) isn't covered by that clause at all.
