# Core: seat metadata on profiles, ship `expanded`, bind the G4 ports clause

## Goal

`RuleProfile` gains `minSeats`/`maxSeats`, so seat count has ONE source of truth that server, client
and bots all read (plan D1). `expanded` joins `SHIPPING_PROFILE_IDS` so the lobby can offer it. The
three import-time guards that were left unbound or unwritten in S2.1.7a are closed: the G4 ports
clause becomes a real check instead of `N !== N`, a new G5 validates seat ranges, and a new G6 locks
the one radius-2 assumption we are knowingly not lifting (neutral-settlement placement).

## Files
- packages/core/src/ruleProfile.ts
- packages/core/src/ruleProfile.test.ts
- packages/core/src/boardgen.test.ts
- packages/core/src/index.ts

## Non-goals
- Do NOT touch server / client / bots / protocol. Widening `SHIPPING_PROFILE_IDS` may turn a client
  lobby test that counts preset options red — story 05 owns that; leave it red.
- Do NOT lift `neutral.ts`'s radius-2 assumption. G6 exists precisely so we do not have to; neutral
  placement on a big board is a future setup-forced-placement story.
- Do NOT change any rule flag, `vpToWin`, supply, or board contents. Seat metadata only.
- Do NOT touch `board.ts` — `buildTopology` / `topologyForRadius` are correct as shipped.
- Do NOT introduce a start-time gate that refuses to start a match below `minSeats` — `minSeats` is
  advisory lobby/matchmaking metadata in this pack (it would break existing 1–3 seat room tests).

## Acceptance criteria
- [ ] Every profile in `PROFILE_REGISTRY` exposes `minSeats`/`maxSeats`: classic/balanced/blitz
      `2..4`, twoPlayer `2..2`, expanded `5..6`. Both are exported on the public core surface.
- [ ] `SHIPPING_PROFILE_IDS` = `['classic','balanced','blitz','twoPlayer','expanded']`; the
      "until S2.1.7b" comment is gone.
- [ ] **G4 ports clause is bound**: the expected port-slot capacity is computed INDEPENDENTLY of
      `ports.length` — from the radius closed form `boundaryEdges(r) = 6·(2r+1)` (30 at r=2, 42 at
      r=3, matching `board.test.ts`) — and the guard rejects `ports.length > boundaryEdges(radius)`
      (the double-assign case) as well as `ports.length < 5` (one 2:1 per resource is the ADR-0013
      fairness invariant). A test proves the clause fires on a `ports`-only corruption — the exact
      case S2.1.7a demonstrated could NOT fire (`ports.slice(0,10)` failed to throw).
- [ ] The closed form is cross-checked against reality once, not trusted: a test asserts
      `buildTopology(r, n).boundaryEdges.length === 6·(2r+1)` for r = 2 and 3.
- [ ] **G5**: `2 ≤ minSeats ≤ maxSeats ≤ 6` (6 = `ADAPTIVE_MAX_PLAYERS`, `adaptiveDuration.ts:32`),
      throwing at import for a violating profile.
- [ ] **G6**: a profile with `neutralSettlements > 0` must have `board.radius === 2`, throwing at
      import. Documents-by-guard that neutral placement is radius-2-only today.
- [ ] Each of G4/G5/G6 has a negative test that fails ALONE when its clause is deleted (the G1–G3
      style S2.1.7a's tests already follow — verify by isolating, do not assume).
- [ ] `boardgen.test.ts` comment nit closed: the `attemptsUsed 26` vs `TOKEN_RETRY_BOUND 64`
      comments at `:14/:154/:173/:250` are reconciled into one accurate statement. **Comments only —
      no assertion, no bound, no fixture value changes.**
- [ ] Classic byte-frozen: every pre-existing core test passes unchanged; no golden fixture edited;
      `board.generated` payload untouched (`minSeats`/`maxSeats` are profile fields, never event
      fields — same shape as `radius` in S2.1.7a).
- [ ] `packages/core` stays zero-runtime-dep.
