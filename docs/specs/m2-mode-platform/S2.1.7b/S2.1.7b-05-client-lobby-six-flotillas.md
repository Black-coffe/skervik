# Client lobby: preset-aware bot cap and two new flotilla identities

## Goal

The lobby stops assuming a 4-seat room. `MAX_LOBBY_BOTS` becomes preset-derived
(`maxSeats − 1`, so 3 for Classic and 5 for Grand Chart), the `expanded` preset that story 01 shipped
renders and behaves correctly in the radiogroup, and seats 5–6 get real identities instead of
silently reusing seat 0/1's colors (`flotillaColors.ts:19-24`, `seatIndex % 4`).

## Implementation notes

- `MAX_LOBBY_BOTS` replaced by `maxBotsForProfile(profileId) = loadRuleProfile(profileId).maxSeats - 1`; `setProfileId` now re-clamps `botCount` against the new preset's cap in the same `set()` call, so a 4-5 bot pick under `expanded` never survives a switch back to a lower-cap preset. `LobbyScreen`'s bot-count radiogroup is now `useMemo`-derived from `profileId` instead of a module constant.
- `flotillaForSeat` already cycled on `FLOTILLAS.length` (not a hardcoded `4`), so adding `moray`/`manta` to the `FLOTILLAS` array required no logic change there — only the two new entries plus the `FlotillaId` union.
- Deutan/protan reasoning: moray (hue 145, L 0.62) sits directly across the wheel from narwhal's neighboring hue 190 (L 0.78) — the two are separated by lightness, not hue alone, mirroring the existing petrel/narwhal precedent. Manta (hue 330) is in an unused hue region shared with nothing else on the palette.
- Emblems are placeholder geometric glyphs matching the existing style (circle/triangle/rect/diamond): moray is a stroked sinuous "S" path (distinct as the only non-filled glyph); manta is a filled 6-point concave kite (wide wingtips + tail notch), visually distinct from narwhal's convex diamond.
- Lore-primer glossary: added items 5-6 (Мурена/Manta blurbs) and repurposed the old "Гагара/Тюлень in reserve" line — those two names were never chosen; Moray/Manta filled the 5-6 seat slots per the owner-approved D6 proposal. Blurb wording (role/color prose) is my own addition, matching the existing 4 entries' style — not owner-locked like the name/color/emblem table.
- Found `packages/core/dist/` was stale (built 2026-07-14, before wave-1 landed `minSeats`/`maxSeats`/`expanded`) — vitest's default config has no source alias for `@skervik/core` (unlike `vite.config.ts`, which does), so `pnpm --filter @skervik/client test` was silently resolving `maxBotsForProfile` to `undefined.maxSeats` (NaN) and rendering only 4 presets until I ran `pnpm --filter @skervik/core build`. Flagged in `CONCERNS` for the Queen/lead-review — other wave-2/3 workers hitting stale-core symptoms should rebuild core, and the integration gate should build core before testing client.
