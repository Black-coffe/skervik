# S2.6.3 — Postgres-backed match metadata

Today the room's `MatchMetadataStore` only records the commit-reveal `seed` (at `game.ended`) —
in-memory or an FS sidecar. This story makes matches **durable and queryable**: a `matches` row at
match-start (`status='live'`), completed at `game.ended` (`seed` reveal + winner + `status='finished'`),
plus a `match_players` row per seat (final VP + result). This is the match-history half of the M2
accounts gate and the durable substrate S2.6.5 (solo save/resume) reads.

**Determinism is the hard constraint here.** These writes are PURE SIDE-EFFECTS on the room's
`#queue`, exactly like the existing `recordSeedReveal` — they never touch `gameState`, never become a
`GameEvent`, never enter `events.ndjson`, never feed `reduce`/`validate`. The event log stays the
byte-replayable source of truth; a metadata-store failure must be caught + logged and NEVER crash the
room, block the match, or diverge the log.

**OUT OF SCOPE:** ratings/`player_ratings` (M3); reading match history into a UI / "my games" list
(that's a later read-surface story); solo resume-from-DB (S2.6.5); OAuth (S2.6.2b). This story only
WRITES the metadata + provides the repo reads its tests need.

## Design decisions (locked — implement as stated)

- **`matches.id` (uuid PK) ≠ the room's `matchId` (Colyseus `roomId`).** The `roomId` is short and can
  recycle across restarts, so it is NOT the durable PK. Add a **`room_id text not null unique`** column
  to `matches` via **additive migration `0002`** (Invariant 3 — generated, committed, never edit 0000/0001).
  `MatchRepository.findByRoomId(roomId)` resolves the durable row; the store writes `event_log_uri` as
  `{matchesDir}/{roomId}/events.ndjson` (same key the FS event log uses).
- **Record at BOTH start and end** (ADR-0012 Fork 3): `recordMatchStart` inserts (`status='live'`,
  `room_id`, `profile`, `seed_hash`, `player_count`, `started_at`, `event_log_uri`); `recordMatchResult`
  updates that row (`seed`, `winner_id`, `status='finished'`, `finished_at`) + inserts `match_players`.
  Captures live/abandoned matches, not only finished ones.
- **`matches.winner_id` (FK users.id) is NULLABLE** — set only when the winning seat maps to a
  token-authenticated `userId`; a bot or tokenless-guest winner → `null`. The winning SEAT is still
  `match_players.result='win'` regardless.
- **`match_players.user_id` is NULLABLE** — a bot seat (`isBot`) or a guest that presented no token → `null`.
- **Best-effort, defensively isolated.** Every metadata call is wrapped so a throw is caught + logged
  and execution continues. The event log + broadcast already completed before these run; metadata is
  secondary.

## Scope — build exactly this

### A. Migration 0002 (`room_id`)
- Add `roomId: text('room_id').notNull().unique()` to `db/schema/matches.ts`. `pnpm --filter
  @skervik/server db:generate` → `migrations/0002_*.sql` (additive; COMMIT; do NOT edit 0000/0001).

### B. Extend `MatchMetadataStore` (`packages/server/src/matchMetadata.ts`)
- Add two methods to the interface (`void | Promise<void>`):
  ```
  recordMatchStart(matchId, { roomId, profile, seedHash, playerCount, startedAt, eventLogUri })
  recordMatchResult(matchId, { seed, winnerUserId?, finishedAt, playerResults: Array<{seat, userId?, finalVp, result}> })
  ```
  (`matchId` = the room's `roomId`, keeping the interface's existing key semantics; pass it as `roomId`
  in the payload too so the Pg impl writes the column.) Implement on ALL FOUR stores:
  `NoopMatchMetadataStore` (discard), `InMemoryMatchMetadataStore` (buffer both, for test assertions —
  expose getters), `FsMatchMetadataStore` (write a `match.json` sidecar next to `seed-reveal.json`,
  reusing `assertSafeMatchId`), and the new `PgMatchMetadataStore`.

### C. `PgMatchMetadataStore` (`packages/server/src/matchMetadata.ts` or a new `pgMatchMetadataStore.ts`)
- Constructed with a `MatchRepository` + `MatchPlayerRepository`. `recordMatchStart` → `matchRepo.create({
  roomId, profile, seedHash, playerCount, status:'live', startedAt, eventLogUri })`. `recordSeedReveal`
  + `recordMatchResult` → `findByRoomId(roomId)` → `matchRepo.update(row.id, {...})` + a
  `matchPlayerRepo.create(...)` per seat. **`recordSeedReveal` (the existing method) also updates the
  row's `seed`** so the commit-reveal seed lands in `matches.seed` (its durable home per ADR-0009 Fork 3).
  If `findByRoomId` returns null (start never recorded — shouldn't happen), log + no-op, never throw
  outward.

### D. `MatchRepository.findByRoomId` + the empty-patch guard (folds S2.6.1 nit #1)
- Add `findByRoomId(roomId: string): Promise<MatchRow | null>` (`eq(matches.roomId, roomId)`).
- Guard `update(id, patch)`: if the built `.set(...)` object is empty, return the current row (or a
  clear no-op) instead of letting Drizzle throw `"No values to set"` (S2.6.1 review nit #1).

### E. Room wiring (`GameRoom.ts`) — the lifecycle hooks (determinism-critical)
- **At match-start** (in `#startMatch`, AFTER `await eventSink.append` + state commit — mirror the
  seed-reveal placement): call `recordMatchStart` guarded by a new one-shot latch `#matchStartRecorded`,
  wrapped in try/catch (log on failure, continue). Assemble the payload from `this.gameState.matchId`
  (=roomId), `#seedHash`... actually `this.gameState.seedHash`, `this.#profileId` →
  `loadRuleProfile(this.#profileId)` for the full `profile`, `this.state.seats.length`, a wall-clock
  `startedAt` from the room scheduler (NOT core), and `eventLogUri`.
- **At `game.ended`** (alongside the existing `recordSeedReveal` at ~GameRoom.ts:1287, inside the same
  `gameEnded` block): call `recordMatchResult` guarded by `#matchResultRecorded`, try/catch. Build
  `playerResults` by iterating seats: `seat` index, `userId` = `resolveUserIdForSeat(seatIndex)` (bot or
  no-token → undefined), `finalVp` = the seat's final victory points, `result` = `'win'` for the winner
  seat else `'loss'` (a disconnected non-bot seat with grace expired → `'abandoned'`). `winnerUserId` =
  the winner seat's resolved userId (or undefined).
- **`resolveUserIdForSeat(seatIndex)`**: `const seat = this.state.seats[seatIndex]; if (!seat || seat.isBot)
  return undefined; return this.clients.find(c => c.sessionId === seat.playerId)?.userData?.userId;`
- **Winner + final VP — VERIFY THE CORE API, do NOT guess.** Read `@skervik/core` for the `game.ended`
  event shape (winner field) and the exported victory-point helper (`computeVictoryPoints` per
  S1.3.4/S2.2.2 — public + hidden). Use the AUTHORITATIVE computation, not a client-side mirror. State
  the exact core symbols you used in your report.

### F. Boot wiring (`boot.ts`) — three-tier, gated on `DATABASE_URL`
- Compose `metadataStore` for the room define (currently only `verifySessionToken` is passed, ~boot.ts:165):
  `DATABASE_URL` set → `PgMatchMetadataStore(new MatchRepository(db), new MatchPlayerRepository(db))`
  (reuse the SAME `db`/`createPgDb(databaseUrl)` instance already built for `DbGuestStore` — do NOT open
  a second pool); else `MATCHES_DIR` set → `FsMatchMetadataStore`; else `InMemoryMatchMetadataStore`.
  Mirror the existing three-tier `GuestStore` pattern (boot.ts ~:127-131). The `registerMatchVerifyRoute`
  metadataStore (~:143) should use the SAME store instance so the verify endpoint reads the durable seed.
- Fold S2.6.1 nit #2: `await pool.end()` in the `migrate` CLI's `main()` after `runMigrations` so the
  process exits promptly (`db/migrate.ts`).

### G. Tests
- **PgMatchMetadataStore (PGlite, hermetic):** run migrations (incl. 0002); `recordMatchStart` inserts a
  `live` row with `room_id`; `recordSeedReveal` + `recordMatchResult` update it to `finished` with `seed`,
  and insert one `match_players` row per seat (bot seat → `user_id` null; winner seat → `result='win'`);

- **Room integration (injected spy/in-memory store, NO real DB):** a room-level or e2e test that a match

## Acceptance criteria
- **AC1 (durable lifecycle, PGlite):** as Test G-1 above — start→result writes the right rows, seed lands
  in `matches.seed`, per-seat `match_players` correct, nullable user_id/winner_id honored.
- **AC2 (room drives the store — FORCING):** an injected recording store observes exactly one
  `recordMatchStart` (at start) and one `recordMatchResult` (at `game.ended`) with correct payloads over
  a real/simulated match. Would fail if a hook were missing or double-fired (latch works).
- **AC3 (determinism untouched):** the authoritative event batches / final `gameState` are byte-identical
  whether the metadata store is `Noop` or a recording store — proven by comparison. Metadata writes never
  enter the event log (grep/assert no metadata in `events.ndjson`).
- **AC4 (best-effort isolation):** a metadata store whose methods THROW does NOT crash the room, block the
  match, or drop/duplicate any `GameEvent` — the match still completes and the log is intact (test with a
  throwing store).
- **AC5 (no regression):** with no `DATABASE_URL`, the server boots on `InMemory`/`Fs` stores; all 170
  existing server tests pass unchanged; core git-byte-unchanged + zero-dep guard; PlayerId semantics
  unchanged; protocol untouched (this story touches NO protocol).
