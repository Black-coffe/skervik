# S2.8.4b — Over-7 discard picker (human sheds half on a 7)

**Epic:** E2.8 · **Tier:** 2–3 · **Depends on:** S2.8.3a (roll → a human can now
roll/face a 7), S2.8.4a (robber move — stays inert while discards are owed) ·
**Status:** DISPATCH-READY. Completes the robber flow started in S2.8.4a.

## Goal

When a **7** is rolled (by the human OR a bot) and the local player holds **more than
7 cards**, they must discard **`floor(handSize / 2)`** of their choosing before the
robber can move. Today there is no UI for this — the human is stuck in the `robber`
phase (`Капер`) until the ~35s turn-timer force-discards for them (and that idle stall
can drop the WS → the client falls back to the offline dev fixture, losing the match).
This story adds a **discard picker** so the human sheds cards promptly, unblocking both
their own 7 (then S2.8.4a's move UI activates) and everyone else's 7 (the robber move —
theirs or a bot's — is blocked `MUST_DISCARD_FIRST` until every ower has discarded).

🔴 **Not turn-gated.** A discard is owed based on `state.playersToDiscard` membership,
NOT whose turn it is — several players (me + bots) may owe on the same 7, in any order
(bots auto-discard via the server driver). So the picker must appear whenever
`myPlayerId ∈ state.playersToDiscard`, even on an OPPONENT's turn. This is the one HUD
surface that is active off-turn.

## Core contract (verified — client never calls `validate`; advisory hints only)

- Intent: `{ type: 'intent.discard', playerId, resources: Record<ResourceType, number> }`
  (`core/types.ts:1019`). Send via `store.dispatchIntent`.
- Owed ⇔ `myPlayerId ∈ (state.playersToDiscard ?? [])`. That array is set on the
  `dice.rolled` event of a 7 and shrinks as each ower discards (`remainingToDiscard`);
  once empty it's dropped from state (S1.3.1).
- Required count (`validate.ts:1654`): `floor(handSize(myResources) / 2)` — `handSize` =
  the plain sum of the resource counts; the divisor is `profile.robber.halfDivisor` (2 in
  every shipping preset — Classic is the only one reaching a live 7 today, so `/ 2` is
  fine; resolve via `loadRuleProfile(state.profileId ?? 'classic').robber.halfDivisor` if
  you want to be exact).
- Server rejects (mirror for the confirm-button gate, all advisory): the selected multiset
  must sum to EXACTLY `required` (`WRONG_DISCARD_COUNT` else) and can't exceed what the
  player holds per resource (`CANNOT_AFFORD` else); a discard from a non-owing player is
  `NOT_OWED_DISCARD`; outside `robber` phase is `NOT_IN_ROBBER_PHASE`.

## Requirements

### 1. `hud/discardActions.ts` (new, pure — mirror `hud/turnActions.ts` discipline)
- `owesDiscard(state, myPlayerId): boolean` — `(state.playersToDiscard ?? []).includes(myPlayerId)`.
- `requiredDiscardCount(state, myPlayerId): number` — `floor(handSize(myResources) / 2)`
  (0 if not found / not owing). `handSize` = sum of the player's `resources`.
- `isValidDiscardSelection(selection, required, myResources): boolean` — selection sums to
  `required` AND every `selection[res] <= myResources[res]` AND no negatives. (Used to gate
  the «Сбросить» button — advisory; the server re-validates.)
- Unit-test: owes/doesn't-owe, required = floor(n/2) for several hand sizes (8→4, 9→4,
  13→6), selection valid only at the exact count and within holdings.

### 2. `hud/DiscardPanel.tsx` (+ `.css`) — the picker
- Renders ONLY when `owesDiscard(state, myPlayerId)` (independent of `pickMode`/turn).
- Shows: a storm prompt ("Шторм! Сбросьте {n} карт" — reuse the lore term for a 7 =
  **Шторм** if a key exists; grep the catalogue) with `n = requiredDiscardCount`; a row per
  resource the player HOLDS (≥1) with a −/+ stepper bounded `0..held`; a live
  "выбрано {sum} / {n}" counter; a **«Сбросить»** confirm button **enabled only when
  `isValidDiscardSelection`** (exact count + within holdings). On confirm →
  `dispatchIntent({ type:'intent.discard', playerId: myPlayerId, resources: selection })`.
- Reuse the **Trade UI's stepper pattern** (`OfferBuilder` has bounded −/+ per resource
  with the resource glyph + accessible name) — don't reinvent the widget; keep it
  misclick-resistant. Resources are shown with their §2.3 glyph + name (never hue-only,
  DESIGN.md §10). Buttons disable, never disappear/shift (§6). No free-text.
- After dispatch the panel disappears on its own once the folded `resources.discarded`
  removes me from `playersToDiscard` (server-authoritative) — do NOT optimistically hide
  it before the echo (a rejected discard must leave the picker up). It's fine to disable
  «Сбросить» briefly after a click to avoid a double-dispatch (a stale double-send is
  harmless — server rejects — but disabling is cleaner).
- Selection state is UI-only and transient — **component-local `useState`** is the natural
  home (unlike S2.8.4a's `robberPendingTile`, this never has to survive a hook-routing
  switch; it's one self-contained component). If you must reset it, key it off the required
  count / owing status so it clears when the owe resolves. State your choice.

### 3. Placement (`hud/GameScreen.tsx`)
- Render `<DiscardPanel/>` when owed. Position it prominently (it's a forced action) but
  per DESIGN.md prefer a **docked panel / prompt bar over a hard modal** — it may sit over
  the board area like the trade dock; the board must stay visible (the player reasons about
  the board while shedding). Coexists with the phase-routed pick source: while owed, the
  S2.8.4a robber-move UI is already inert (it gates on empty `playersToDiscard`), so there's
  no conflict — the discard picker is simply the active surface until I discard.

## Constraints
- Server authoritative; the confirm-gate is an advisory client mirror — a wrong-count or
  over-hold selection can't be confirmed client-side, but if one somehow dispatches the
  server rejects → existing `NoticeBar`. Never block the dispatch pipeline on the mirror
  beyond the button-enable.
- Client never has the seed (irrelevant here — discard has no randomness).
- Client-only. Do NOT touch `packages/core`, `packages/protocol`, `packages/server`, or
  `memory/`. Do NOT touch S2.8.4a's robber-move code, `BoardScene.ts`, or F-remount.
- Touch ONLY: new `hud/discardActions.ts` (+ test), new `hud/DiscardPanel.tsx` (+ `.css`),
  `hud/GameScreen.tsx`, and `i18n/keys.ts` + `locales/{en,ru,uk}.ts`. Reuse existing
  resource-glyph / stepper components rather than adding new ones.
