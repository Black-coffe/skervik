# S2.8.2 — Setup-phase placement (human completes the snake draft)

**Epic:** E2.8 interactive human play · **Tier:** 3 · **Depends on:** S2.8.1 (pick
layer, merged) · **Status:** DISPATCH-READY.

## Goal

Let the local human place their setup settlements + roads by clicking the board,
so a real match **completes setup and reaches the `main` phase** (today it sticks:
the human seat can't place). Server stays authoritative; the client composes
`placeSettlement`/`placeRoad` intents from clicks and shows legal-target hints.

## The core signals (verified in `packages/core`)

- Turn: `state.currentPlayerId` (`types.ts:176`). Local turn ⇔
  `state.phase === 'setup' && state.currentPlayerId === myPlayerId`.
- **Setup sub-step: `state.pendingRoadVertexId` (`types.ts:233`).**
  - `undefined` → a SETTLEMENT is expected next.
  - a `VertexId` → a ROAD attached to THAT vertex is expected next
    (`validate.ts:1267` rejects a settlement while it's set; `:1302` reads it for
    the road).
- Intents (confirm exact field names in `types.ts` — the worker MUST read them):
  `intent.placeSettlement { type, playerId, vertexId }`,
  `intent.placeRoad { type, playerId, edgeId }`. Client composes
  `playerId: myPlayerId` (server re-binds to seat; anti-spoof holds, same as Trade
  UI). `store.dispatchIntent(intent)` (`hud/store.ts:186`) already sends any intent.
- Legality rules to MIRROR as pure client HINTS (advisory only — server is the
  authority): settlement = empty vertex + NO adjacent-vertex building (distance
  rule, `validate.ts:1279-1289`, setup has no road-connection requirement); setup
  road = an edge incident to `pendingRoadVertexId` that has no road yet
  (`validate.ts:1301+`). Cross-check your helper against those exact lines.

## Requirements

### 1. Pure legality helpers (`board/setupLegality.ts` + test)
- `legalSetupSettlements(state, topology): VertexId[]` — empty + distance-rule-ok.
- `legalSetupRoads(state, topology, pendingVertexId): EdgeId[]` — empty edges
  incident to `pendingVertexId`.
Pure, no Pixi, unit-tested against a small fixture (a placed settlement blocks its
neighbors; a taken edge is excluded; incident-only for roads). Reuse topology
adjacency + `GameState.buildings`; do NOT call core `validate` (no seed on client).

### 2. Placement orchestrator (a hook, e.g. `hud/useSetupPlacement.ts`)
Derive from the store (`gameState`, `myPlayerId`):
- `active = phase==='setup' && currentPlayerId===myPlayerId`.
- `active && pendingRoadVertexId===undefined` → `pickMode:'vertex'`,
  `legalTargets = {kind:'vertex', ids: legalSetupSettlements(...)}`.
- `active && pendingRoadVertexId!==undefined` → `pickMode:'edge'`,
  `legalTargets = {kind:'edge', ids: legalSetupRoads(..., pendingRoadVertexId)}`.
- else → `pickMode:'none'`, no targets.
- `onPick`: vertex → dispatch `placeSettlement`; edge → dispatch `placeRoad`
  (both with `playerId: myPlayerId`). Dispatch the resolved pick as-is; an
  off-hint / illegal click is left to the SERVER to reject (existing `NoticeBar`
  reject UX) — do NOT hard-gate on the client legality set (avoids a drift lockout
  where a client-side rule mismatch blocks a legal move). Highlights are guidance.

### 3. Board renders the legal-target set (extend S2.8.1's board layer)
- New `GameTable` prop `legalTargets?: { kind: 'vertex'|'edge'; ids: readonly string[] }`
  threaded to the scene (same non-remount ref pattern). BoardScene draws a
  persistent `legalLayer` (distinct from S2.8.1's transient hover highlight):
  markers on each legal vertex/edge. Style: shape + the accent/primary token, NOT
  hue-only (a11y §10) — e.g. a filled dot/ring on vertices, a highlighted segment
  on edges; subtle, does not fight the hover ring. Clears when empty.
- Wire the orchestrator in `GameScreen.tsx`: pass `pickMode` + `onPick` +
  `legalTargets` to `<GameTable>`. This is the FIRST real `pickMode` — so the
  S2.8.1 dev harness (`PickDemoControls`, active only when `pickMode===undefined`)
  correctly disappears during setup on my turn. Keep it working when NOT my turn
  (pickMode 'none' → harness still shows in dev; acceptable).

### 4. A turn prompt (i18n)
A small status line (reuse `NoticeBar`/HUD prompt or a new element) telling the
player what to do: «Разместите поселение» / «Разместите дорогу» / «Ход соперника».
Every string a `t()` key ×ru/uk/en (build-gated). No hardcoded text.
