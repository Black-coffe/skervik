# S2.1.6 — 2-player mode (neutral/phantom blocking on the standard board)

## Goal

Deliver a **balanced 2-player mode** — the last E2.1 story. Recon confirmed the engine already has
NO ≥3-player assumptions: snake-draft, trade (targets degrade to the single opponent), robber, and
setup all work for N=2 on the standard 19-tile board. The problem 2p introduces is **balance**: two
players on a full board don't compete for space, producing a dull solo-build — exactly the "dead"
dynamic the product designs out. S2.1.6 fixes that with a **neutral/phantom mechanic** (owner-selected
2026-07-07): a handful of **neutral blocking settlements** placed at genesis on deterministic, contested
vertices, forcing the two real players to spread and compete — reusing the existing **distance rule**
(a neutral settlement blocks its neighbours automatically) rather than reworking the board.

**Chosen approach (surfaced fork, owner-decided): phantom on the STANDARD board** — NOT a trimmed
board. So there is **no boardgen topology change, no client render change, and NO verify change** (the
board doesn't diverge → the verify board-leg stays deferred to a future trimmed-board story). This
keeps S2.1.6 a bounded, low-risk single story on the existing board + client.

## What to build

### 1. The `twoPlayer` profile (core)
- Add **`'twoPlayer'`** to `RuleProfileId` + a **`TWO_PLAYER_PROFILE`** (spreads `CLASSIC_PROFILE` —
  standard board, standard costs/VP) with the 2p-specific knobs (below); register it in
  `SHIPPING_PROFILES` (keeping the exhaustiveness guard) and add `'twoPlayer'` to the protocol
  `profileId` enum (`messages.ts`). Classic/Balanced/Blitz values UNCHANGED.
- A `neutralSettlements` count knob (e.g. a small `TwoPlayerProfile` sub-object or a top-level constant
  — surface the choice): how many neutral blockers to place (e.g. 2–3; v1, documented tunable).
- **Note the orthogonality trade-off (Law 4):** `twoPlayer` is modeled as its own profile id (like
  Balanced/Blitz), so "2-player Balanced" isn't expressible yet. Making player-count orthogonal to
  rule-mode (a `phantomPlayers` flag any profile sets when 2 seats) is a deferred refinement — the
  distinct-id path is the simplest coherent thing now (Law 2).

### 2. The neutral/phantom mechanic (core — the balance meat)
- **Placement:** at match genesis (alongside `board.generated`, before player setup), place
  `neutralSettlements` neutral settlements at **deterministic, legal, high-contention vertices** chosen
  by a **policy over the board — NOT a seed draw** (e.g. the highest-production / most-central legal
  vertices, canonical tie-break). Deterministic-from-board ⇒ **no new PRNG slot, no verify change**
  (the S2.1.4 discard-policy precedent). Record the placement as **event(s)** (append-compatible new
  genesis event, or reuse `settlement.placed` with a neutral owner — surface the choice) so replay
  reconstructs the identical board state; they must be legal under the distance rule at placement time.
- **Model:** neutral pieces are buildings owned by a **reserved neutral owner id** (a constant that can
  never be a real `PlayerId`). They exist in the buildings/ownership structure so the **existing
  distance rule blocks real players on and adjacent to them with ZERO new adjacency code**.
- **Exclusions (the neutral is NOT a player):** confirm/ensure the neutral owner is excluded from —
  turn order (`playerOrder` holds only real playerIds, so neutral takes no turns — likely already
  true), **production payout** (a neutral-owned building must NOT receive resources — the main explicit
  change: the payout loop must skip neutral-owned buildings), **robber victims** (neutral has no hand →
  already filtered if victim selection iterates `state.players`), **trade targets** (neutral not in
  `state.players` → already excluded), and **VP / longest-road / largest-army** (per-real-player
  tallies → neutral excluded). Verify each exclusion holds; add the one(s) that don't.
- The neutral pieces are **static** — they do NOT take turns, produce, grow, get robbed, or count VP.
  (Neutral "growth"/pseudo-turns are explicitly NOT built.)

### 3. 2-seat support (server — minimal)
- Recon: `GameRoom` already starts when seats fill (`maxSeats` option, no MIN) and the core has no ≥3
  assumption — so a room created with `maxSeats:2` + `profileId:'twoPlayer'` plays a full 2p match.
  S2.1.6 needs NO new seat machinery; GameRoom stays hardcoded `'classic'`/4 default (lobby selection =
  S2.5.4). Prove 2p via room options in a server/e2e test, not by changing the default.

### 4. Tests
- A **2-player full-match test** (2 scripted/real players finish under `twoPlayer` to victory,
  deterministic, replay byte-identical, `verifyMatchRandomness` ok — verify must pass UNCHANGED since
  the board is Classic and placement is non-seed).
- **Neutral-blocking**: a real player cannot build a settlement on OR adjacent to a neutral settlement
  (distance rule).
- **Neutral exclusions**: production does NOT credit neutral buildings; robber cannot steal from /
  target the neutral; trade offers don't list the neutral; neutral buildings add 0 VP and don't extend
  any real player's longest road.
- **Determinism**: neutral placement is identical across two runs (policy, not seed); the genesis log
  replays byte-identically.
- Classic/Balanced/Blitz suites stay green UNCHANGED (twoPlayer is a new id; golden is Classic).

## Key decisions (surface any deviation)

1. **Phantom on the standard board, not a trimmed board (owner-decided 2026-07-07).** Why: delivers a
   balanced 2p at the lowest cost/risk — no boardgen topology rework, no setup-fit risk (the full 19-tile
   board comfortably holds 4 real + K neutral placements), no client render change, no verify change.
   The trimmed-board alternative (which WOULD discharge the verify board-leg) is a heavier, deferred story.
2. **Neutral placement is a DETERMINISTIC board policy, not a seed draw.** Why: it needs no fairness
   audit (it's a fixed function of the public board), so it adds NO PRNG slot and NO `verify` change —
   the S2.1.4 discard-policy precedent. Recorded as events so replay reconstructs it exactly.
3. **Neutral modeled as buildings under a reserved owner id — reuse the distance rule.** Why: an
   existing settlement already blocks its neighbours via the distance rule, so blocking costs ZERO new
   adjacency code; the neutral is excluded from turns/production/robber/trade/VP by a few per-owner
   filters (most already hold because the neutral isn't in `state.players`).
4. **`twoPlayer` is its own profile id (not orthogonal to mode).** Why: matches the Balanced/Blitz
   pattern, simplest coherent thing (Law 2); 2p×other-modes is a deferred refinement.
5. **Classic byte-frozen; determinism intact.** twoPlayer is a NEW id — Classic/Balanced/Blitz play and
   the golden are unchanged; the neutral genesis events are append-compatible and only appear under
   twoPlayer. `reduce`/`validate` signatures LOCKED (profile via `state.profileId`).
6. **No ADR needed** — profiles-as-config is locked; this is its application + a bounded mechanic. Flag
   an ADR only if the neutral-owner state model proves contentious in review.
