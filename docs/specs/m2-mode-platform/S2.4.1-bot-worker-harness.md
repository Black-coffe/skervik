# S2.4.1 — Bot worker harness (`@skervik/bots` brain + in-process runner)

## Goal

First story of E2.4 (Bots). Today `@skervik/bots` is a pure stub (`BOTS_VERSION = '0.0.1'`); the only
real decision logic is the S1.7.2 E2E `decideAction` (expansion-first, test-local in
`packages/server/src/e2e/scriptedDriver.ts:366-484`). This story **productizes that seed into a real bot
brain in `@skervik/bots`** and builds the **in-process harness** that proves the brain can play a full,
deterministic Classic match to `game.ended` (VP ≥ 10) — the foundation E2.4/E2.3 build on.

**What a bot IS (architecture, locked by the invariants):** a bot consumes the PUBLIC `GameState` (folded
from a snapshot + `event.batch` via core `reduce`) and proposes a `PlayerIntent`. It holds **NO authority**
— it never sees the seed, never calls the authoritative `validate` as an authority, never mutates state.
The server (S2.4.3) validates + applies the bot's intents through the SAME `#queue`/`#applyAuthoritativeIntent`
pipeline a human client goes through. The bot is just "a client's brain without a socket."

**Scope of THIS story = the harness + the brain, package-internal.** No server changes beyond a
behavior-preserving re-shim of the E2E driver (so S1.7.2's determinism gate keeps passing). NO bot-seat, NO
single-player, NO bot-fill, NO ×3 difficulty — those are S2.4.2/S2.4.3/E2.3.

## What to build (all in `packages/bots`, + a server re-shim)

### 1. Move the decision brain into `@skervik/bots` (canonical, behavior-preserving)
Move `decideAction(state: GameState, playerId: PlayerId): PlayerIntent | null` and its pure helper searches
(`firstBuildableSettlement`, `roadTowardSettlement`, `bankTradeToward`, `planDiscard`, `planRobberMove`, and
whatever else it privately uses) from `packages/server/src/e2e/scriptedDriver.ts:366-484` into a new
`packages/bots/src/heuristic/v0.ts` (the canonical v0 bot brain). **Behavior MUST be byte-identical** — same
deterministic tie-breaks (topology order, resource order, players-order for robber), same expansion-first
strategy. This is a MOVE, not a rewrite. Import the core helpers it needs from `@skervik/core`'s public API
(`buildTopology`/`findVertex`/`findEdge`/`findTile`, `loadRuleProfile`, `computePublicVictoryPoints`,
`isStealable` — confirm each is exported; if the brain used a core-INTERNAL helper not on the public API,
STOP + report rather than reaching into core internals).

### 2. The `Bot` seam (decision ≠ transport; reuse-ready for S2.4.2/M4)
Define a minimal seam in `packages/bots/src/bot.ts`:
```
export interface Bot {
  readonly id: string;                 // difficulty/label, e.g. 'v0'
  decide(state: GameState, playerId: PlayerId): PlayerIntent | null;
}
export function createHeuristicBot(/* no knobs yet */): Bot;  // wraps v0 decideAction
```
Keep `decide` a pure function of `(state, playerId)`. **Do NOT bury a scoring/evaluation abstraction here
yet** (Law 2) — v0 is rule-based, not scored. The owner's "shared board/action evaluation module" (bot ↔ M4
advisor share one brain) is introduced by **S2.4.2** WHEN difficulty knobs + scoring actually exist; S2.4.1
only guarantees the seam so S2.4.2 swaps the brain without touching callers. Note this in a code comment +
the story so S2.4.2 inherits the intent.

### 3. The in-process harness (provably-terminating full-match runner)
`packages/bots/src/harness.ts` — a `simulateMatch`-style runner that plays a FULL deterministic match by
acting as BOTH the bots (via `Bot.decide`, no seed) AND a mock-authority (core `validate(state, intent,
playerId, seed)` → events → `reduce` fold). This is the productized version of the S1.7.2
`scriptedDriver.test.ts` `simulateMatch`:
```
export interface SimResult { finalState: GameState; events: GameEvent[]; winnerId: PlayerId | null; turns: number; }
export function simulateMatch(opts: {
  seed: Seed; playerIds: PlayerId[]; bots: Record<PlayerId, Bot>;
  profileId?: RuleProfileId; maxTurns?: number;   // HARD cap — throws loudly if exceeded (never hangs)
}): SimResult;
```
- Bootstraps a Classic room genesis (mirror how `scriptedDriver.test.ts`/S1.7.2 builds the initial
  `GameState` + `match.started`/`board.generated` — reuse that exact bootstrap; do NOT invent a new one).
- Loops: fold current state → `bot.decide` for the current seat (or the discard/robber sub-phase actor) →
  `validate` with the test seed → append events → `reduce`. Advance until `phase:'finished'` or the
  `maxTurns` cap. **The cap MUST throw a descriptive error (loudly) if hit** — a bot that can't reach 10 VP
  must fail the test, never spin. [[e2e-scripted-driver-expansion]] is the law here: the driver is
  expansion-first so it provably terminates; if the moved brain deadlocks, that's a bug to surface, not hide.
- The harness is the seam S2.4.3 (single-player) reuses in-process; keep it free of any `packages/server`
  import (bots must not depend on server — dependency direction is server → bots).

### 4. Re-shim the server E2E driver (keep S1.7.2's gate green, no duplication)
In `packages/server/src/e2e/scriptedDriver.ts`: replace the moved `decideAction` body with a re-export/import
from `@skervik/bots` (`export { decideAction } from '@skervik/bots'` or a thin wrapper) so the existing S1.7.2
E2E test (which imports `decideAction`) keeps working with byte-identical behavior. Add `@skervik/bots` to
`packages/server/package.json` deps (workspace). Do NOT change the E2E test's assertions — it is the
determinism/termination gate that proves the move preserved behavior. If the server E2E's `simulateMatch`/
constants also want to move, keep that OUT of scope (leave them in the server test) unless the move can't be
behavior-preserving otherwise — then STOP + report.

### 5. Tests (`packages/bots/src/*.test.ts`)
- **Deterministic full match:** `simulateMatch` with a fixed seed + 3–4 v0 bots reaches `phase:'finished'`
  with a `winnerId` at `computePublicVictoryPoints`/full VP ≥ 10; same seed + same bots → deep-equal
  `finalState` + identical `events` (reproducibility).
- **Replay-equality:** the harness's persisted `events` folded through `reduce` from genesis deep-equals
  `finalState` (the event-sourcing gate — mirrors S1.7.2 (3)).
- **Termination cap:** a deliberately tiny `maxTurns` throws the descriptive cap error (proves it fails loudly,
  never hangs).
- **Brain-move parity (guard the shim):** the ported `@skervik/bots` `decideAction` returns the SAME intent
  as the pre-move server behavior for a handful of representative states (or simply: the S1.7.2 server E2E
  test still passes UNCHANGED — that IS the parity proof; call it out in the report).
- **No-authority discipline:** a smoke assertion that `Bot.decide` takes only `(state, playerId)` — no seed
  parameter — so a bot structurally cannot predict future rolls.

## Scope — build THIS, defer the rest

workspace dep.

**DEFER — do NOT build:**

- **ANY server wiring** — no bot-seat type, no GameRoom change, no `#queue` bot injection, no single-player
  room, no bot-fill. That is S2.4.3 (single-player + bot-fill) + E2.3 (reconnect/bot-fill). The scout mapped
  the `#queue`/`forcedAction` seam (GameRoom.ts:315/583/798) for S2.4.3 — do NOT touch it here.
- **A separate bot PROCESS / network client** — the plan's "separate process" is an M5-scale concern; M2 runs
  the bot in-process (single node, in-memory rooms — "start cheap, don't over-engineer scale"). See Key

- **Any `packages/core` change** — the bot consumes core's existing public API. If the brain needs a core
  export that isn't public, STOP + report (do NOT reach into core internals or add a core export without a
  scoped decision).
- **Non-determinism / `Math.random` in v0** — allowed by the package's ESLint scope, but v0 stays
  deterministic for reproducible tests; controlled randomness (if any) is S2.4.2's difficulty concern.

## Key decisions (surface any deviation)

1. **In-process, delivery-agnostic brain (NOT a separate process yet).** The plan describes bots as "a
   separate process emitting intents like a client," but also specifies bot-fill "drives the absent seat via
   the E2.4 bot through the SAME `#queue`" and "single-player = a room filled with bots" — i.e. the SERVER
   invokes the bot in-process. For M2 (single node, in-memory rooms, cheap infra) the bot is a pure decision
   MODULE the server calls in-process; a standalone bot process is an M5-scale option. The harness therefore
   takes no socket. **Tradeoff:** in-process = simplest, satisfies every M2 requirement, no new deployment;
   the separate-process/horizontal-bot-scaling story is deferred to M5. If the worker sees a reason M2 needs
   the external process now, STOP + report.
2. **MOVE the brain, don't duplicate.** `@skervik/bots` becomes the single source of truth for `decideAction`;
   the server E2E imports it (behavior byte-identical → S1.7.2 gate green). A copied brain would drift.
   Dependency direction: server → bots (never bots → server).
3. **Bot holds NO authority + never sees the seed.** `decide(state, playerId)` — no seed param. The harness's
   mock-authority `validate` call uses the TEST seed (the harness plays the server's role in a test); the bot
   itself is seed-blind. This is the authoritative-server invariant applied to bots.
4. **Decision ≠ transport ≠ scoring.** The `Bot` seam isolates decision from the harness (transport) so
   S2.4.3 can drive it in-process and S2.4.2 can swap in a scored brain. The shared EVALUATION module (owner
   reuse directive) is S2.4.2's to introduce with difficulty — S2.4.1 does not pre-abstract scoring (Law 2).
5. **Provably terminating (no hung CI).** The harness's `maxTurns` cap throws loudly. The v0 brain is
   expansion-first precisely so a full match terminates ([[e2e-scripted-driver-expansion]]); if the moved
   brain can't reach 10 VP, the test must FAIL, not spin.
6. **Core untouched, determinism intact.** No `packages/core` diff. `@skervik/bots` is outside the core
   zero-runtime-deps + ambient-RNG guard, but depends only on `@skervik/core` (workspace) and stays
   deterministic in v0.
