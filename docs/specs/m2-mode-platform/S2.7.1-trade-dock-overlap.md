# S2.7.1 — Trade dock overlap + phase-gating (client UI polish)

**Tier:** 2 (client-only, multi-file, DESIGN.md-bound) · **Epic:** E2.7 UI polish
(new) · **Owner-triggered:** live browser QA 2026-07-14 (see memory
`ui-overlap-manual-qa`).

## Problem (owner, first live browser run)

«Навигация и меню не проработаны. Перекрывают игровое пространство и другие
показатели.» On a live match the trade offer builder covers the board, and it is
shown during the `Постановка` (setup) phase when trading is impossible.

## Root cause (verified, with line refs)

1. **No phase gate.** `packages/client/src/hud/GameScreen.tsx:30-34` renders
   `<TradeZone />` (and the incoming-offer card path) UNCONDITIONALLY inside
   `.game-screen__chart`. It shows in every phase, including `setup`/`roll`/
   `robber`/`finished`, when no trade is legal (`packages/core` `validate.ts`:
   p2p + bank/port trade intents are legal only in phase `'main'`).
2. **Board centered under the dock.** `packages/client/src/board/BoardScene.ts:443`
   `world.position.set(app.screen.width / 2, app.screen.height / 2)` centres the
   board across the FULL chart width, so it sits under the left-docked trade
   panel. The design authority (mockup `docs/design/mockups/game-table.html:201,
   219,570`) intentionally keeps the trade panels as an absolute left dock
   (`position:absolute; left:16px; width:372px; z-index:var(--z-trade)`) and
   comments (line 570) **"Board sits right-of-center"** — i.e. the board must be
   offset right when the dock is visible. That offset is currently missing.

NOTE — the bottom `dev · trade` bar (`TradeDemoControls`) overlapping
`Мои ресурсы` is **dev-only** (`GameScreen.tsx:41` gates it behind
`import.meta.env.DEV`); it does not exist in a `vite build` prod bundle, so it is
NOT a product bug. See "Optional" below.

## Design authority (binding)

`DESIGN.md` §6 (game-screen zoning — the Chart is the hero; instruments frame it,
never cover it) and §7 (Trade UI: fixed docked panel, "offers to me arrive as a
docked card … NEVER a screen-blocking modal"). Reference mockup
`docs/design/mockups/game-table.html`. Follow the mockup's model (absolute left
trade dock + board offset right); do NOT switch to a different layout model
without owner sign-off.

`GamePhase` (core) = `'setup' | 'roll' | 'main' | 'robber' | 'finished'`
(+ `'lobby'` from the server projection). Trade dock visible **iff phase ===
'main'**.

## Acceptance criteria

1. **Phase-gate the trade dock.** Introduce a pure, unit-tested helper (e.g.
   `canShowTradeDock(phase): boolean` returning `phase === 'main'`) and use it so
   the trade offer builder AND any incoming-offer card render ONLY in `'main'`.
   In `setup`/`roll`/`robber`/`finished`/`lobby` the trade dock is absent from
   the DOM (not merely `visibility:hidden`).
2. **Board never sits under the dock.** When the trade dock IS shown (`main`),
   the board's horizontal centre is offset right by the dock's footprint
   (dock width + gutter — mockup: 372px panel at left:16px, so reserve ≈ 372+16
   plus a small gutter) so no tile/token/port is covered by the dock at the
   default (un-panned) view, at ≥1280px width. When the dock is hidden, the board
   centres across the full chart width (unchanged behaviour).
3. **No scene teardown on phase change.** The board offset must react to the dock
   appearing/disappearing WITHOUT rebuilding the Pixi scene (a full remount loses
   pan/zoom and flickers). `GameTable`'s effect currently keys on
   `[state.board, state.buildings, state.playerOrder, state.players]` — do NOT add
   `phase` to that dep list in a way that remounts; instead thread the inset
   reactively (prop → a scene method that repositions `world`, respecting the
   user's current pan/zoom as the new baseline, or recomputing the centred
   baseline). Pan and zoom must keep working after the offset changes.
4. **Nothing else overlaps** at ≥1280px: rail, chart, log, deck stay in their
   grid areas; the trade dock sits within the chart's left inset, not over the
   rail/log/deck.
5. **Merge gates (DESIGN.md §10):** no new hardcoded user-facing strings (reuse
   existing `t()` keys; if any new string is unavoidable, add ru/uk/en — build
   fails otherwise); no hue-only information introduced; two-surface model kept
   (no canvas drama on instruments).

## Implementation notes

- `packages/client/src/hud/store.ts` — added `canShowTradeDock(phase)` (pure,
  `phase === 'main'`), next to `shouldShowGame`.
- `packages/client/src/hud/store.test.ts` — unit tests for
  `canShowTradeDock` (forcing: true only for `'main'`, false for the rest).
- `packages/client/src/hud/GameScreen.tsx` — computes `dockVisible =
  canShowTradeDock(gameState.phase)`; passes it to `<GameTable>`; renders
  `<TradeZone/>` conditionally (`{dockVisible ? <TradeZone/> : null}`) so it's
  gated at ONE place (the parent) and absent from the DOM outside `main`.
- `packages/client/src/board/GameTable.tsx` — added `dockVisible: boolean`
  prop. Scene-creation effect's dep list is UNCHANGED (no remount on phase
  change). Added a `sceneRef` (holds the live `BoardSceneHandle`) and a
  `dockVisibleRef` (mirrors the latest prop every render, read inside the
  async `.then()` so a scene that finishes loading after a dock toggle still
  starts correctly offset). A second, separate `useEffect` keyed on
  `[dockVisible]` calls `sceneRef.current?.setDockVisible(dockVisible)` to
  reposition the EXISTING scene reactively.
- `packages/client/src/board/BoardScene.ts` — `BoardSceneHandle` gained
  `setDockVisible(visible: boolean): void`. Added `TRADE_DOCK_RESERVE_PX =
  372 + 16 + 20` (mirrors `TradeZone.css`'s `left:16px; width:372px` + a 20px
  gutter — duplicated because Pixi can't read CSS) and
  `TRADE_DOCK_OFFSET_PX = TRADE_DOCK_RESERVE_PX / 2`. Offsetting by HALF the
  reserve, not the full reserve, is the deliberate reading of "reserve space
  for the dock, then centre the board in what's left of the chart" — centre
  of `[reserve, chartWidth]` is `chartWidth/2 + reserve/2`, not
  `chartWidth/2 + reserve`; a full-reserve shift would push the board
  noticeably off-centre-right (and off-screen on a narrower ~1280px chart
  column). `setDockVisible` shifts `world.x` by the DELTA between the new and
  previously-applied offset (not an absolute recompute), so any pan the user
  already applied survives the toggle untouched; zoom (`world.scale`) is
  never touched by this path.
- No changes to `TradeZone.tsx` (gated at the parent, per the story's
  "pick ONE place; parent is cleaner") and no changes to `TradeDemoControls.tsx`
  (skipped the optional dev-only reposition — story marks it non-blocking and
  "skip if it adds risk"; kept the diff minimal).
- Deviation: none from the acceptance criteria. One judgment call flagged
  above (half-reserve vs full-reserve offset math) — surfaced for the Queen's
  live-browser eyeball since the story's prose ("offset right by the dock's
  footprint") reads ambiguously between the two.

  build` all green (224/224 tests passing, including the 2 new
  `canShowTradeDock` cases). No git commands run, nothing staged/committed.
