# S2.3.1 — Reconnect tokens + grace ≥120s (hold a dropped seat, reclaim on reconnect)

## Goal

First story of E2.3 (Resilience). Today `onLeave` is an M1 stub (`GameRoom.ts:606-614`) — it flips
`seat.connected = false` and does nothing else; a dropped player's seat is neither held with a grace window
nor reclaimable, and a fresh reconnect would mint a brand-new seat. This violates the **"no karmic bans"**
product law (a network drop must never cost you the game). This story wires **Colyseus 0.17's native
`allowReconnection(client, graceSeconds)`** so a dropped seat is **HELD for a grace window (≥120s)** and, when
the same client reconnects within that window, the seat is **reclaimed** (`connected` flips back) with the
**same session identity** — the authoritative `gameState` untouched throughout.

**What reconnection IS (locked by the invariants):** a pure TRANSPORT-layer seat-hold. Colyseus's
`allowReconnection` keeps the client's `sessionId` reserved for `graceSeconds`; because the seat's identity is
already `playerId = client.sessionId` (`GameRoom.ts:~583`), a native reconnect resumes the SAME seat with NO
identity remap. Reconnection mutates ONLY the Colyseus `connected` projection + the client lifecycle — it
NEVER touches the authoritative `gameState`, NEVER appends an event, NEVER changes a rule. Determinism/replay
stays byte-identical (the M1 stub already proved "authoritative GameState untouched"; this story preserves
that). **The match never freezes for the OTHER players:** while a seat is held, the EXISTING turn timer keeps
firing deterministic forced defaults for an absent current player (S2.1.4) — grace holds the *identity*, not
the *clock*.

**Scope of THIS story = the SERVER reconnect mechanism + server tests.** NO client React wiring / reconnect
UX (S2.3.2 owns the client half, with resync); NO full missed-state resync message (S2.3.2); NO bot-fill on
expiry / deliberate safe-leave (S2.3.3); NO core / engine / protocol-message / rule change.

## What to build (all in `packages/server`, + tests)

### 1. A grace-window room option
Extend `GameRoomOptions` (`GameRoom.ts:93-165`) with `reconnectGraceSeconds?: number` — the seat-hold window,
**default 120** (product law ≥120s). Keep it a ROOM option (a resilience/infra knob), NOT a `RuleProfile`
field — grace is not a game rule (profiles stay rule-only). A future lobby (E2.5) can pass it; for now it
defaults. (Optionally clamp to a `>= 120` floor, or just document the default — worker's call, note it.)

### 2. Grace hold on a non-consented leave (`onLeave`)
Rewrite the M1 stub `onLeave(client, consented)` (`GameRoom.ts:606-614`) to hold the seat on a network drop:
```
async onLeave(client, consented) {
  const seat = this.state.seats.find(s => s.playerId === client.sessionId);
  if (seat) seat.connected = false;              // projection: mark absent (existing behavior)
  if (consented) return;                          // deliberate leave → S2.3.3 owns safe-leave/rejoin
  try {
    await this.allowReconnection(client, this.#reconnectGraceSeconds);  // HOLD the seat for the window
    if (seat) seat.connected = true;              // reconnected within grace → reclaim (same session)
    // (missed-state resync to the reclaimed client = S2.3.2)
  } catch {
    // grace expired, no reconnect → seat REMAINS (connected:false), NO forfeit (no karmic ban).
    // bot-fill of the held seat on expiry = S2.3.3.
  }
}
```
- **Non-consented (network drop) → grace hold** is the core deliverable (the "no karmic ban for disconnects"
  law). **Consented (deliberate `.leave()`, `consented===true`) → mark disconnected, NO grace hold** — the
  deliberate safe-leave/rejoin UX is S2.3.3. Note this boundary explicitly.
- Confirm the Colyseus 0.17.10 `allowReconnection(client, seconds)` signature + reject-on-expiry semantics
  (the promise RESOLVES on reconnect, REJECTS on timeout; on reject Colyseus drops the client from
  `this.clients` but OUR `state.seats` entry persists — we never remove it → no forfeit). If 0.17 uses the
  `"manual"` token form instead of a seconds arg, adapt + report.
- **`autoDispose` interaction:** verify the room does NOT auto-dispose while a reconnection is pending (so a
  room where the LAST/only human dropped survives the grace window). `allowReconnection` should keep it alive;
  confirm + add a test (a single-human room whose human drops must not dispose before grace expiry). In a
  single-player room (1 human + bots) the bots keep playing via `#driveBotTurn` while the human is held — the
  human resumes on reconnect. Note this property.

### 3. Turn-timer coordination — do NOT pause (close the S2.1.4 deferred item)
**Leave the turn-timer path UNCHANGED.** While a seat is held in grace, if the absent player is the CURRENT
actor, the existing hard-timeout (`#onHardTimeout` @ 885 → `resolveForcedAction` → `#applyAuthoritativeIntent`)
keeps firing deterministic forced defaults so the match advances — the OTHER players are never frozen waiting
on a dropped socket (the ≤60-min-ceiling intent). Grace holds the seat's IDENTITY for reclaim, not the clock.
This **closes the deferred S2.1.4 "reconnect/grace coordination" item** with the decision "continue, don't
pause." Do NOT add a pause/resume to the timer (Key decision 2). Confirm via a test that a forced action still
fires for an absent current player during grace, and that on reconnect the player resumes mid-match with a
consistent state.

### 4. Reconnect identity — rely on the native session, add NO new schema field
Do NOT add a reconnect-token field to `SeatSchema` (Law 2 — no dead config; Colyseus manages the
`reconnectionToken` internally, and the seat is already keyed by `sessionId`). Reclaim = find the seat by
`client.sessionId` in the resolved `allowReconnection` branch and flip `connected`. The client-side
token persistence + `client.reconnect(token)` call is S2.3.2's (client half). **Zero schema change in this
story** — reuse the existing `connected` field.

### 5. Tests (`packages/server/src/room/*.test.ts` — extend `GameRoom.test.ts` or a new `reconnect.test.ts`)
Use the `@colyseus/testing` harness (the scout mapped the pattern: `client.leave()` → `onLeave`; reconnect =
a `connectTo`/reconnect within grace). Cover:
- **Grace hold + reclaim:** a client drops (non-consented) → `seat.connected===false` + the seat is NOT
  removed; the client reconnects within grace → `seat.connected===true`, SAME `playerId`/seat, and the
  authoritative `gameState` is byte-identical across the whole cycle (reconnect mutated no game state).
- **Grace expiry, no forfeit:** a client drops and does NOT reconnect within a SHORT test grace → the seat
  REMAINS in `state.seats` (`connected:false`), no forfeit, no crash. (Use a tiny `reconnectGraceSeconds` +
  the test scheduler / fake timers so the test is fast and deterministic — mirror the S2.1.4 turn-timer test
  seam; do NOT sleep 120s.)
- **Turn advances during grace:** the CURRENT player drops → the turn timer fires a forced action (turn
  advances) while the seat is held → the player reconnects and resumes on a consistent state.
- **No auto-dispose during grace:** a single-human room whose human drops does NOT dispose before grace
  expiry (the room survives the hold window).
- **Consented leave:** a deliberate `.leave(consented=true)` marks `connected:false` WITHOUT holding grace
  (the S2.3.3 boundary) — assert the existing `gameState`-untouched property still holds.
- **Determinism guard:** reconnect appends NO event to the sink/log (only forced actions from the timer do);
  the event stream during a drop+reconnect equals the event stream of the same match with no drop.

## Key decisions (surface any deviation)

1. **Native Colyseus `allowReconnection` — NOT a hand-rolled token.** Colyseus 0.17.10 ships the exact
   primitive (grace-scoped session reservation + `reconnectionToken`), and the seat is ALREADY keyed by
   `sessionId` → a native reconnect resumes the same seat with zero identity remap. Rolling our own token +
   custom `onJoin` re-attach would re-implement the framework and risk identity bugs in the very field the
   whole `gameState` keys off (`playerId`). ADR-0011 already locked Colyseus 0.17 — use its primitive (Law 2).
   **Tradeoff:** we inherit Colyseus's reconnection semantics (reject-on-expiry, client must present the token
   in S2.3.2); we accept that in exchange for not owning identity-recovery correctness.
2. **Grace does NOT pause the turn timer — the match continues via forced defaults.** If the absent player is
   the current actor, the existing S2.1.4 forced-action keeps the game moving; grace holds the seat IDENTITY
   for reclaim, not the clock. **Rejected: pausing the timer during grace** — that would freeze EVERY other
   player for up to 120s on one dropped socket, violating the ≤60-min ceiling and the "dead time" design
   intent. "No karmic ban" is satisfied by holding the seat (you keep your game + VP), not by pausing everyone.
   This closes the deferred S2.1.4 grace-coordination item.
3. **Reconnection is TRANSPORT-only → determinism byte-untouched.** No event is appended on drop or reclaim;
   the only log entries during an absence are the EXISTING deterministic forced actions (no timestamp/marker).
   `gameState` is never mutated by reconnect. Replay of a match with a drop+reconnect equals replay of the same
   match without it. This is the M1 stub's guarantee, preserved.
4. **Server mechanism now; client reconnect + resync in S2.3.2.** The load-bearing part (hold + reclaim by
   session) is fully testable server-side via `@colyseus/testing`. The React client's token-persist +
   `reconnect()` + resync UX is a coherent unit with S2.3.2's missed-state resync — deferring it keeps S2.3.1
   a tight server T2 and avoids a half-baked client change.
5. **Grace = a room option (default 120), not a profile field.** Resilience is infra, not a game rule; profiles
   stay rule-only. The lobby (E2.5) can override later.
6. **On expiry: hold, don't forfeit.** Grace running out does NOT remove the seat or end the game — the seat
   stays `connected:false` (bot-fill on expiry is S2.3.3). "No karmic ban" means the drop never costs the game,
   even if the player never returns within grace.
