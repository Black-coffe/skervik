# S2.8.4a — Robber move + steal victim (human resolves a 7)

**Epic:** E2.8 · **Tier:** 3 · **Depends on:** S2.8.1 (board pick layer), S2.8.3a
(roll → a human can now roll a 7) · **Status:** DISPATCH-READY. Split from S2.8.4;
**S2.8.4b** (discard-over-7 picker) follows separately.

## Goal

When a human rolls a **7** (or the mover otherwise enters the `robber` phase with no
discards outstanding), let them **move the robber** by clicking a tile and, if that
tile has an opponent to rob, **pick the victim** — dispatching `intent.moveRobber`.
This closes the exact dead-end live-QA hit repeatedly: a human who rolls a 7 lands in
the `robber` phase (`Капер`) with **nothing to click**, and only the ~35s turn-timer
force-resolve bails them out (and that idle stall can drop the WS → the client falls
back to the offline dev fixture, losing the match). After this story a human resolves
their own robber promptly.

🔴 **Scope boundary:** this story handles the robber MOVE (+ steal) for the current
player when **no discard is owed**. The over-7 **discard picker** is **S2.8.4b** — do
NOT build it here. `intent.moveRobber` is rejected `MUST_DISCARD_FIRST` while
`state.playersToDiscard` is non-empty, so this UI must stay inert until discards clear
(in a 1-human/3-bot game the bots auto-discard via the server driver; a HUMAN who owes
a discard is unblocked only by S2.8.4b). Knight-triggered robber moves are S2.8.5.

## Core contract (verified — client never calls `validate`; advisory hints only)

- Intent: `{ type: 'intent.moveRobber', playerId, tileId, victimId? }`
  (`core/types.ts:1030`; `victimId` optional). Send via `store.dispatchIntent`.
- Current robber location: **`state.board.robberTileId`** (`TileId`). A move to that
  same tile is rejected `ROBBER_SAME_TILE` — so every OTHER tile is a legal target.
- Victim eligibility (mirror `validate.ts` `resolveRobberMove` `865`–`909`): the owners
  of a settlement OR city on any of the target tile's vertices, **excluding the mover**,
  who hold **≥1 card**. `state.board.tileKinds` + the topology give the tile's vertices;
  `state.buildings.settlements` / `.cities` give owners; `state.players[id].resources`
  gives hands. If **0** eligible card-holders, `moveRobber{tileId}` (no `victimId`) is a
  legal no-op steal — do NOT require a victim. If ≥1, the server REQUIRES a valid
  `victimId` (`NO_SUCH_VICTIM` otherwise).
- Friendly-robber protection: core exports **`isStealable(state, playerId, robberProfile)`**
  — reuse it (do NOT reimplement). It's a no-op for every shipping preset (`friendlyRobber:
  false`), so for Classic the eligible set is simply "building-owner-on-tile, not me, has
  cards". Resolve the profile via `loadRuleProfile(state.profileId ?? 'classic')` if you
  need `robber` for `isStealable`; Classic is the only profile reaching a live `robber`
  phase today.
- The stolen resource itself is a server-secret seed draw — the client NEVER chooses or
  predicts it; it only names the victim. (No seed on the client.)

## Requirements

### 1. `board/robberLegality.ts` (new, pure — mirror `buildLegality.ts` discipline)
- `legalRobberTiles(state, topology)` → `TileId[]`: every tile id except
  `state.board.robberTileId`. (Used for the prompt/derive; see the highlight note below.)
- `stealVictims(state, topology, tileId, myPlayerId)` → `PlayerId[]`: eligible victims per
  the rule above (owner-on-tile ≠ me, ≥1 card, `isStealable`). Order stable (e.g. seat
  order) so the picker is deterministic. Unit-test: 0 victims (empty tile / only my
  buildings / card-less owners), 1 victim, multiple victims, a city owner counts, the
  mover is never a victim.

### 2. `hud/useRobberPlacement.ts` (new, pure derive/resolve + hook — mirror `useBuildPlacement.ts`)
- Pure `deriveRobberPlacement(state, myPlayerId, pendingTileId)`:
  - Active ⇔ `state.phase === 'robber'` AND `state.currentPlayerId === myPlayerId` AND
    **no discard outstanding** (`state.playersToDiscard` is undefined/empty). Else inactive
    (`pickMode:'none'`, no prompt).
  - When active and `pendingTileId` is unset → `pickMode:'tile'`, prompt `moveRobber`
    ("Переместите Капера на другой остров"). (Highlight: see note.)
  - When active and `pendingTileId` IS set (a tile with ≥1 victim was picked, awaiting
    victim choice) → `pickMode:'none'` (board picking paused), prompt `chooseVictim`, plus
    the victim list (`stealVictims(state, …, pendingTileId, myPlayerId)`) for the picker UI.
- Pure `resolveRobberTilePick(state, topology, tileId, myPlayerId)` → one of:
  `{ dispatch: MoveRobberIntent }` (0 victims — move + no steal immediately) OR
  `{ pendingTile: tileId }` (≥1 victim — enter victim-choice). **ADVISORY**: don't gate on
  `legalRobberTiles`; a same-tile click still dispatches and the server rejects
  (`ROBBER_SAME_TILE` → `NoticeBar`), consistent with `resolveSetupPick`/`resolveBuildPick`.
- Pure `resolveVictimPick(pendingTileId, victimId, myPlayerId)` →
  `{ type:'intent.moveRobber', playerId: myPlayerId, tileId: pendingTileId, victimId }`.
- The `useRobberPlacement()` hook wires these to the store + `dispatchIntent`, holds the
  UI-only `pendingTile` (see state note), clears `pendingTile` after any dispatch, and
  exposes `{ pickMode, prompt, victims, onPick, onChooseVictim, onCancelVictim }`.

### 3. Victim picker UI (bottom deck or an inline prompt bar)
- When `prompt === 'chooseVictim'`, render a small picker: one button per eligible victim
  (flotilla display name — reuse the players-rail naming — optionally its hand size), plus
  a «Отмена» that clears `pendingTile` back to tile-pick. Buttons disable, never
  disappear/shift (DESIGN.md §6). Misclick-resistant (no free input). Every string a
  typed `t()` key ×ru/uk/en.
- When `prompt === 'moveRobber'`, show the move prompt (reuse the existing setup/build
  prompt surface — `GameScreen.tsx` maps prompt → `t()` key).

### 4. Screen routing (`hud/GameScreen.tsx`)
- Extend the existing phase-routing (setup→setup, main→build) with **robber→robber**:
  feed `pickMode`/`onPick` from `useRobberPlacement` when `phase==='robber'`. One active
  pick source at a time. Keep S2.8.1/2/3b threading + `dockVisible` intact.

### 5. Board highlight (note — keep it simple)
`setLegalTargets` supports only `vertex`/`edge`, NOT `tile`, and highlighting ~18 legal
tiles would be noise. So do **NOT** add a persistent legal-tile layer: rely on the
existing S2.8.1 **hover ring** (BoardScene `drawHighlight` already has a `'tile'` case) +
the server reject for a same-tile click. Do NOT modify `BoardScene.ts` beyond what's
already exported (`setPickMode`/`onPick`). (A "mark the forbidden current-robber tile"
polish is out of scope.)

## UI-only state
The `pendingTile` (a tile awaiting victim choice) is UI-only — never in `gameState`,
never sent except inside the resolved `moveRobber`. Put it in the store (a
`robberPendingTile` field + setter, cleared on dispatch, on «Отмена», and — heeding the
S2.8.3b review nit — on match-join `applySnapshot`, NOT on `setGameState`) OR in the hook
via component state. State which you chose and why; keep it from leaking across matches.
