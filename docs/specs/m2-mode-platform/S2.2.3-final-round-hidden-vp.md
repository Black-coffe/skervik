# S2.2.3 — Final round (Splendor-style) + hidden VP

## Goal

Third catch-up mechanic (roadmap principle 3 — *catch-up over runaway-leader*). **Owner decisions
2026-07-08:**

1. **`finalRound` — Splendor-style "round to end of circle."** Today the game ends INSTANTLY the
   moment a player reaches `vpToWin` on their own turn (`validate.ts:558`). That is unfair: whoever's
   turn falls first wins a tie, and trailing players never get a symmetric last chance. With
   `finalRound` on, **reaching the threshold does NOT end the game** — it **triggers a final round**:
   every OTHER player gets **exactly one more turn**, then the game ends and the player with the
   **highest full VP** wins (deterministic tie-break). This directly removes the "won because my turn
   came first" asymmetry.
2. **`hiddenVp` — dev-card victory points stay hidden from the endgame threshold until the final
   round triggers.** Today the win check uses the FULL tally (`computeVictoryPoints = public + hidden`,
   `validate.ts:394-403`), so a leader can secretly stockpile VP cards and win with no warning. With
   `hiddenVp` on, the **win/trigger threshold uses PUBLIC VP only** (`computePublicVictoryPoints` —
   dev-card VP excluded); hidden VP is **revealed at the final standings** (`game.ended` always tallies
   full VP). So concealed cards can't spring a surprise win, but they still count when the winner is
   decided.

Both are **profile-gated `CatchUpProfile` booleans**, off on every shipping preset for now (liveness
via test profiles, the S2.1.5/S2.2.1/S2.2.2 discipline).

**These are DETERMINISTIC-from-state mechanics** — the trigger, the round-completion detection, the
threshold measure, and the winner are all pure functions of `state` + the profile. **NO seed slot, NO
new PRNG, `verify.ts` UNCHANGED** (scout confirmed verify.ts reads no VP/game-end — Area 5). The
seed-derived draws (dice, dev-card, board, steal) are untouched.

**Why T3 (three things make it more than two booleans):**
1. **It rewrites the single most load-bearing determinism branch** — the WIN CHECK (`validate.ts:558`)
   and adds a NEW terminal condition on the turn-end path. Any drift here breaks every replay. The OFF
   path MUST stay byte-identical to today's code.
2. **New event + persistent-but-absent state.** `game.finalRoundStarted` (a new `GameEvent` → trips
   the protocol drift-pin, S2.2.2 precedent) + a `GameState.finalRound` field that must be ABSENT
   under `finalRound:false` so Classic/golden stay byte-frozen.
3. **Combinatorial flag semantics.** `finalRound` and `hiddenVp` are independent booleans whose four
   combinations must each be well-defined (see the truth table below) — and the forced-action /
   turn-timer cross-check re-opens because the turn-end path now decides game-end.

## Mechanic (precise)

### Threshold measure (what counts toward reaching `vpToWin`)

```
thresholdVp(state, id) = catchUp.hiddenVp
  ? computePublicVictoryPoints(state, id)     // dev-card VP EXCLUDED (hidden until final round)
  : computeVictoryPoints(state, id)           // full tally (today's behavior)
```

`computePublicVictoryPoints` (validate.ts:415-430, already EXPORTED) = settlements + cities×2 +
longest-road + largest-army. `computeVictoryPoints` (validate.ts:394-403) = public + held dev-card VP.
**Reuse them — do NOT recompute.** Using the public helper for the threshold is the SAME
no-hidden-leak discipline S2.2.1/S2.2.2 use for their gates.

### `finalRound` OFF (today's behavior, byte-frozen)

Win check at `validate.ts:558`: `if (thresholdVp(cursor, actingPlayerId) >= victory.vpToWin)` → emit
`game.ended` immediately, `winnerId = actingPlayerId`, `finalStandings` = **full** VP for every player
(reveal at end — unchanged from today). With `hiddenVp` also off, `thresholdVp === computeVictoryPoints`,
so this is byte-identical to the current line 558.

### `finalRound` ON

- **Trigger:** when `actingPlayerId`'s `thresholdVp >= victory.vpToWin` AND the final round is **not yet
  triggered** (`state.finalRound` undefined) → emit a new **`game.finalRoundStarted`** event carrying
  `{ triggeredBy: actingPlayerId, triggeredOnTurn: state.turn }`. **Do NOT emit `game.ended`.** Play
  continues.
- **Already triggered:** if `state.finalRound` is already set, the win check emits NOTHING (no re-trigger,
  no early end) — the game only ends when the round completes.
- **Round completion → end:** on the **turn-end path** (the `intent.endTurn` → `turn.ended` emission in
  `validate`), when `state.finalRound` is set AND the player who would become current NEXT equals
  `state.finalRound.triggeredBy` (i.e., every OTHER player has now taken exactly one turn since the
  trigger) → emit **`game.ended`** with `winnerId` = the player with the **highest full VP**
  (`computeVictoryPoints`, hidden revealed) and `finalStandings` = full VP for all. The trigger player
  does NOT get a second turn.
  - **Detection is deterministic:** turns rotate strictly by `playerOrder`; the next current player is
    computed the same way `turn.ended` already computes it. "Next === triggeredBy" ⟺ `state.turn` has
    advanced `playerOrder.length - 1` times since the trigger. Use whichever expression is cleaner given
    the existing turn-rotation code, but anchor it to the SAME rotation the reducer uses (no parallel
    turn math that could diverge).
- **Winner tie-break (deterministic, provisional balance knob):** highest full VP; ties broken by
  **fewest total buildings placed** (settlements + cities — "more efficient wins"); still tied →
  **earliest seat in `playerOrder`** (final deterministic fallback). Mark it tunable (like S2.2.2's
  provisional numbers) — the flag is off on presets, so it changes no shipping behavior.

### Flag truth table (all four combinations must be well-defined)

| finalRound | hiddenVp | Threshold measure | Endgame | Winner |
|---|---|---|---|---|
| off | off | full VP | instant `game.ended` on crossing | actingPlayer (today) |
| off | on  | **public** VP | instant `game.ended` on crossing public threshold | actingPlayer; standings reveal full |
| on  | off | full VP | crossing → final round → ends when round completes | highest **full** VP + tie-break |
| on  | on  | **public** VP | crossing public threshold → final round → completes | highest **full** VP (hidden revealed) + tie-break |

> Numbers/tie-break are **provisional balance knobs** (flags off on all presets → they change no shipping
> behavior). Tune later in the M2 balance-sim/playtest workstream. Set them, don't agonize.

## Key decisions (surface any deviation)

1. **Deterministic → verify untouched.** Trigger, round-completion, threshold, and winner are pure
   functions of `state` + profile. No new PRNG slot, no verify branch (scout Area 5 confirmed verify.ts
   reads no VP/game-end). Same discipline as S2.2.1/S2.2.2.
2. **PUBLIC VP for the hidden-VP threshold, never a hidden leak.** Reuse `computePublicVictoryPoints`.
   The final standings (`game.ended`) are the ONLY place full VP is revealed. This is the memory-noted
   "refines what public VP means" — the endgame threshold now joins the robber/robin-hood gates in
   reading public VP under `hiddenVp`.
3. **Additive GameState field, absent when off.** `finalRound` optional + only written by the trigger
   event → golden byte-frozen under `finalRound:false`. This is the headline determinism risk; lead-review
   verifies the OFF win/end path is byte-identical.
4. **Turn-timer forced-action cross-check RE-OPENS ([[turn-timer-forced-action-hang-risk]]).** finalRound
   changes what the turn-end path does (it can now end the game) — so the story that changes this MUST
   confirm the forced default action stays LEGAL throughout the final round (a timed-out final-round turn
   forces `endTurn`/roll/discard/robber as usual and the round still completes to `game.ended`), and add
   the per-kind timed-out-during-final-round test. It does NOT change per-action robber/discard legality,
   so no new re-arm watchdog is mandated beyond confirming no-hang — but if the worker finds the forced
   action could ever be rejected once `finalRound` is set, STOP + report (that's the hang the memory warns
   about). Keep the S2.1.4/S2.2.1 forced→validate tests green.
5. **`game.ended` reused, not replaced.** The final round ends via the SAME `game.ended` event + reducer
   (phase→finished). Only the EMISSION SITE and the winner computation differ. No second terminal event.
6. **No ADR needed.** Profiles-as-config + catch-up-profile-gating are locked (S2.1.1/S2.2.2); this is
   their application. If the worker judges the turn-end terminal condition warrants an ADR (it shouldn't —
   it's a localized rule), STOP + report before writing one.
7. **Winner tie-break is a provisional balance knob** — fewest buildings → playerOrder. Off on presets;
   tune in playtest. If implementing "fewest buildings" balloons scope, fall back to playerOrder-only and
   flag it.
