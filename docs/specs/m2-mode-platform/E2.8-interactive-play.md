# E2.8 — Interactive human play (client input) — EPIC PLAN

**Status:** PROPOSED (2026-07-14, awaiting owner approval before build) · **Tier:** 3
(client-heavy, cross-story) · **Area:** M2 client.

## Why this epic exists

The client renders `GameState` and has a working Trade UI, but **a human cannot
drive a match by hand**: there is no way to click the board to place/build, roll,
move the robber, or play a dev card. M1's "3–4 players play a Classic match"
E2E was driven by a **scripted test driver**, never the UI — so real interactive
play was never built. This is the gap that makes a live browser match "stick" in
setup (owner saw it 2026-07-14). This epic closes it.

## What already exists (recon 2026-07-14) — the good news

- **Intent dispatch is already generic + wired.** `store.dispatchIntent(intent:
  PlayerIntent)` (`hud/store.ts:186`) forwards ANY `PlayerIntent` to the server
  through the S1.6.5 net layer when connected; the Trade UI proves the whole
  path (compose → dispatch → server `validate`→`reduce`→broadcast → client fold).
  **No protocol/net/server work is needed** — this epic is client input + client
  legality hints only. Server stays the sole authority (it re-validates).
- **Intents exist in core** with the fields the UI must supply: placement/build
  take `vertexId`/`edgeId`; robber takes `tileId`/`victimId`; roll/endTurn/dev
  cards defined (`core/src/types.ts`). Client composes `playerId: myPlayerId`
  (server re-binds to seat — anti-spoof holds, same as Trade UI).
- **`myPlayerId` + turn** are in the store (S1.6.5); inputs enable only on the
  local player's turn.

## What must be BUILT (the lift)

1. **Board hit-testing** — there is NO Pixi interaction on game pieces today
   (only pan/zoom via canvas listeners). Need inverse geometry (pointer →
   nearest `vertexId` / `edgeId` / `tileId`) + a Pixi interaction layer + hover
   affordances. This is the foundational new piece.
2. **Per-phase input wiring** — compose the right intent from a click, gated by
   phase + whose turn it is.
3. **Client-side legal-move hinting** — the client CANNOT call core `validate`
   (needs the server-secret seed), but placement/build legality (distance rule,
   network adjacency, ownership, affordability) IS computable from `GameState`
   with PURE helpers, for highlighting only (server stays authoritative). Reuse/
   extract pure helpers from core where they exist (keep core zero-dep).

## Story breakdown (proposed order — value-first)

- **S2.8.1 — Board hit-testing + interaction layer (foundation).** Pure inverse-
  geometry (`pixelToNearestVertex`/`…Edge`/`…Tile`, snap radius, unit-tested) +
  a Pixi interaction layer emitting `{kind, id}` on click + hover highlight. No
  game logic. Tier 2–3. *Biggest new piece; everything else builds on it.*
- **S2.8.2 — Setup-phase placement (unsticks matches).** In `setup` on my turn:
  highlight legal settlement vertices (distance rule, pure client helper) → click
  → `placeSettlement{vertexId}`; then highlight legal incident road edges → click
  → `placeRoad{edgeId}`; snake-draft order; disabled off-turn. **After this a
  human can complete setup → a real match reaches `main`.** Tier 3.
- **S2.8.3 — Main-phase core loop.** Roll control → `rollDice`; «Завершить ход» →
  `endTurn`; build modes (settlement/road/city) via board clicks with legal-target
  highlight + affordability gating (client hint). Tier 3.
- **S2.8.4 — Robber + 7-discard.** Discard-over-7 picker → `discardResources`;
  move-robber tile-click → `moveRobber{tileId}`; steal-target select →
  `stealResource{victimId}`. Tier 3.
- **S2.8.5 — Dev cards (Предприятия).** Buy (`buyDevCard`) + play each type
  (knight/road-building/YoP/monopoly) with target pickers. Tier 2–3.

**Milestone check:** after S2.8.1+S2.8.2+S2.8.3 a human can play a basic Classic
turn loop end-to-end in the browser; S2.8.4/S2.8.5 complete the ruleset. S2.8.2 is
the single highest-value story (it makes ANY human match playable).

## Cross-cutting constraints (bind every story)

- **DESIGN.md is binding** (§6/§7, a11y §10): legal-target highlights must not be
  hue-only; every new string is `t()` ×ru/uk/en (build-gated); the Chart stays the
  hero. Coordinate with **S2.7.2 auto-fit-zoom** (board-fit) so interaction maps
  correctly under any zoom/pan (hit-testing must invert the live world transform).
- **Client never gains the seed / never calls `validate`.** Legality hints are
  advisory; a click always dispatches an intent and the server is authoritative
  (an illegal click → server reject → existing reject UX).
- **Manual browser QA is mandatory** per every UI surface ([[ui-overlap-manual-qa]]):
  each story eyeballed live (now genuinely drivable once S2.8.2 lands).
- Reuse the Trade UI's `dispatchIntent` seam; don't fork a second dispatch path.
