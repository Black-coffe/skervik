## Methodology & caveats

- **Presented-FPS is unreliable in automation:** Chrome throttles rAF for
  occluded windows (observed: 1 fps rAF while `visibilityState === 'visible'`;
  Pixi Ticker's 100 ms `deltaMS` clamp then reads as a constant "10 FPS" in the
  overlay). The 100/98 desktop numbers are from a genuinely foregrounded run.
- Mobile proxy therefore uses **synthetic frame cost** — CPU-side
  `renderer.render()` timing under DevTools CPU throttling. The GPU cannot be
  throttled this way; the scene is batched `Graphics`, trivially light for any
  modern mobile GPU, so CPU was the meaningful axis.
- **Residual risk (accepted):** one real-device spot-check (mid-range Android)
  during the first alpha. The revisit triggers in ADR-0002 stay as written.
- The scene handle is exposed as `globalThis.__SKERVIK_PROTO__` (scene.ts) so
  the benchmark can drive synthetic renders — occlusion-immune by design.
