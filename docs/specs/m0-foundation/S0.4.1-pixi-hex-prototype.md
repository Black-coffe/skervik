## Scene spec

- **Board**: axial hex grid, radius 2 → exactly 19 tiles (hexagon of hexagons).
  Pointy-top or flat-top — your choice, pick what reads best isometrically.
- **2.5D look**: flatten vertically (y-scale ≈ 0.55–0.65) and give each tile an
  extruded darker "side" face below its bottom edges — tabletop depth, no real 3D.
- **Tile types** (placeholder palette, lore names in comments only): 4× pines
  (timber), 3× clayShoals (clay), 4× meadows (fleece), 4× barleyFields (barley),
  3× oreRidges (iron), 1× mistBank (center, no token). **Fixed deterministic
  layout array** — no randomness, so perf runs are reproducible.
- **Never color-only** (project invariant): each tile type carries a second cue
  besides fill color — a simple procedural pattern (stripes/dots/crosshatch via
  Graphics) or a glyph letter. Cheap is fine; this is a perf scene, not art.
- **Number tokens** on the 18 producing tiles: small disc + number text
  (classic 2..12 distribution minus 7, any fixed assignment).
- **Interaction**: drag-pan + wheel zoom on the board container.
- **Animation**: one subtle continuous animation (e.g. mist-bank alpha pulse) so
  the ticker renders real frames instead of idling.
- **Perf harness overlay** (plain DOM, dev harness — NOT product UI, so ADR-0008
  trilingual rule does not apply; keep text minimal/EN): rolling avg FPS + 1% low
  (5 s window), JS heap MB (`performance.memory` when available), renderer
  backend (webgpu/webgl), tile count, and a **stress toggle** that tiles the
  board ×7 (133 hexes) to probe headroom.

## Implementation notes
<!-- appended by the worker -->

Built the prototype under `packages/client/src/proto/`:

- `hexBoard.ts` — pure data: `axialRing(radius)` enumerates a hexagon-of-hexagons
  in a fixed deterministic order; `BASE_BOARD` (19 tiles, fixed type/number
  arrays, mistBank at center index 9) and `STRESS_BOARD` (133 tiles = 7 copies
  of `BASE_BOARD` tiled across a radius-1 hex-of-boards, offset in axial space
  by the board span so copies never overlap). No randomness anywhere.
- `tileRenderer.ts` — flat-top hex geometry (`axialToPixel`, y-flatten baked
  into pixel conversion via `Y_SCALE = 0.6`), `createTileVisual(tile)` builds a
  `Container` per tile: darker extruded side faces along the lower contour
  (edges whose midpoint sits below center — 3 of the 6 edges), a shrink factor
  (`GAP_SCALE = 0.92`) so neighbours leave a gap revealing the extrusion (avoids
  needing z-order/painter's-algorithm bookkeeping), a masked procedural pattern
  per tile type (stripes/diagonals/cross-hatch/dots — the "never color-only"
  second cue), and a number-token disc + `Text` (red ink for 6/8).
- `scene.ts` — `createHexScene(mountEl)` builds the `Application` (v8 async
  `init()`, `preference: 'webgpu'` with automatic WebGL fallback), a `world`
  container for pan/zoom, a `tilesLayer` rebuilt by `setStress()`, one ticker
  callback pulsing the mist-bank fog overlay alpha, and plain pointer/wheel
  listeners for drag-pan + zoom-to-pointer (no Pixi `eventMode`/interaction
  plugin needed — simpler and avoids per-tile hit-testing).
- `PerfOverlay.ts` — plain DOM panel: 5 s rolling sample window keyed off the
  Pixi ticker's `deltaMS`, avg FPS + 1% low computed from sorted samples,
  `performance.memory` heap MB (Chromium-only, "n/a" fallback), renderer
  backend derived from `app.renderer.type` (`RendererType` 1/2/4 →
  webgl/webgpu/canvas), tile count, and the stress-toggle button.
- `main.tsx` — replaced the placeholder `<h1>` with a `HexPrototype` React
  component; `useEffect` awaits `createHexScene`, guards against the
  StrictMode double-invoke race with a `cancelled` flag, mounts the overlay,
  and tears both down on unmount.
- `vite.config.ts` — PWA manifest `name`/`short_name` "Skerry" → "Skervik"
  (only that one field pair touched).
- `package.json` — added `pixi.js@^8.19.0` to `dependencies` via
  `pnpm --filter @skervik/client add pixi.js` (lockfile updated).

Decisions / tradeoffs:
- Chose the gap-and-shrink approach over strict back-to-front z-ordering for
  the extrusion — simpler code, no per-frame or per-layout sort needed, and
  reads clearly as "tabletop depth" per the story's own framing.
- Pan/zoom implemented with raw DOM pointer/wheel events on `app.canvas`
  rather than Pixi's `eventMode`/`FederatedPointerEvent` system — fewer
  moving parts for a perf harness, and avoids per-tile hit-area setup.
- `STRESS_BOARD` reuses `BASE_BOARD`'s fixed type/number arrays verbatim per
  copy (no attempt to vary them) — kept deterministic and simple; the story
  only asks for tile-count stress, not content variety.
