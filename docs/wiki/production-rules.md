# Продукция: правило банка «всё или ничего» ПО РЕСУРСУ

Когда бросок кубика означает выплату, сервер заранее вычисляет полную формулу один раз в `validate()` и кладёт результат в события как неизменяемый факт (types.ts, types.ts `ResourcesProducedEvent`). `reduce()` никогда не пересчитывает продукцию.

## Сердце: all-or-nothing ПО РЕСУРСУ, не ПО БРОСКУ

**Если банк не может выплатить полный размер одного ресурса всем, кто её имеет право, то ЭТОТ ресурс никому не выплачивается этот бросок.** Другие ресурсы того же броска выплачиваются нормально.

Пример: бросок выпал 6 (timber), положено 2 timber (два поселения). Банк: 1 timber, 4 clay, 5 ore. Результат:
- Timber: всего должно 2, доступно 1 → **никому не выплачивается**, банк остаётся 1 timber.
- Clay и ore: выплачиваются обычно (если на них есть поселения).

Реализация (validate.ts, строка 163): `if (totalOwed > available) continue;` — цикл по ресурсам, перейти к следующему.

## Константы Classic (S1.2.1)

**`bankPerResource = 19`** (validate.ts, строка 59): каждого из 5 ресурсов в банке ровно 19 единиц физической паритета (как в настольной Catan). Когда первый раз производится ресурс, на `GameState.bank` добавляется ключ; если ключа нет, подразумевается полный пул 19.

## Как считается продукция

1. **На каждом tile, совпадающем с выпавшим числом, кроме тайлов с Капером**: собрать одного ресурса от каждого соседнего поселения (1 = поселение, TODO S1.2.2 2 = гавань).
2. **Агрегировать по ресурсам и игрокам**: `owed[resource][playerId] = сумма по всем producing tiles`.
3. **Цикл по ресурсам**: если всего должно больше, чем доступно, пропустить весь ресурс; иначе выплатить каждому, обновить банк.
4. **События записывают факты**: `ResourcesProducedEvent.grants` (кто что получил), `ResourcesProducedEvent.bank` (полное состояние банка после).

## Граничные случаи

- **Никакого доступного ресурса**: `grants = {}` (пусто), но событие всё равно испускается.
- **Бросок 7**: нет `resources.produced` события вообще (разбойник — S1.3.1), только `dice.rolled`.
- **Капер на тайле**: тайл блокируется полностью, даже если число совпадает.
- **Нет доски или поселений**: `grants = {}`, `bank` копируется как есть.

## Дизайн: факты, не рецепты

Каждый `DiceRolledEvent` и `ResourcesProducedEvent` — это frozen facts, которые может пересчитать аудитор (в `GET /matches/{id}/verify`) из seed + event log. Благодаря commit-reveal ([[fair-rng-commit-reveal]]), реплей и аудит не требуют мутации банка — всё пересчитывается из исходных фактов (deterministic-core invariant).
